# Iso & Orbit - Camera and Character Controller Template

**English** · [Español](README.es.md) · [日本語](README.ja.md) · [Português (Brasil)](README.pt_BR.md) · [Русский](README.ru.md) · [Türkçe](README.tr.md) · [简体中文](README.zh_CN.md)

Version 1.1.0 · Godot 4.7 (tested on 4.7.2) · GDScript · MIT

A click-to-move character controller and an orbit camera for isometric and top-down RPGs. Click the ground and
the hero runs there, pathing around obstacles; hold the button and the hero follows the cursor. The camera
orbits, zooms and keeps out of walls.

![Click to move, hold to steer, orbit and zoom the camera, discover a place](docs/images/demo.gif)

No third-party assets: characters are built from primitives by a script, surface patterns are generated by
shaders and baked into seamless textures, sounds are synthesized.

## Getting started

1. Install Godot 4.7.2, the standard or the .NET build. Jolt Physics is built into the engine, nothing to
   install. The renderer is Forward+.
2. Clone the repository, import `project.godot` in the Project Manager and open it. The first import takes
   a moment, since `.godot/` is not in the repository.
3. Press F5 to run the demo (`res://gdscript/main.tscn`).

The controls are listed in the top-left corner. To hide them, open Settings (F10) → Interface and turn off
**Controls hint and speed**. The interface language is chosen on the same tab.

## Controls

| Input | Action |
|---|---|
| Left click on the ground | Run to that point |
| Hold the left button | Run after the cursor |
| Left + right button | Run where the camera looks; A / D veer diagonally |
| Right button + mouse | Orbit the camera |
| Right button + WASD | Move relative to the camera |
| Mouse wheel | Zoom: lower and closer, or higher and farther |
| Shift | Sprint while held (or toggle, in the settings) |
| Space | Jump |
| F10 | Open the settings (pauses the game); Esc or F10 closes them |

All modes and their settings: [Controls](docs/en/controls.md).

## Features

**Movement**

- Click to run to a point along the navigation mesh; a marker shows where.
- Hold the left button to run after the cursor: by default straight at it, sliding along obstacles; optionally
  along a navigation path to the point under it.
- A click and a hold are told apart after 0.2 s, so holding the button never sends the hero on a detour to the
  point where you pressed.
- Both buttons together: run where the camera looks. Right button and WASD: move relative to the camera, facing
  forward or turning to face the way you go.
- Constant acceleration and braking, a stop exactly at the target without overshoot, a limited turn rate and an
  instant turn from a standstill.
- Sprint with stamina. Jump with coyote time and input buffering; the jump height is the same at any physics
  tick rate.
- A ledge guard: at the edge of a drop the hero stops or slides along it, as along a wall.
- Stairs up to 0.3 m are climbed and descended without leaving the ground; slopes up to 45° are walked up.

**Camera**

- Orbit with the right button, zoom with the wheel. Distance and pitch change together: the closer the camera,
  the lower its angle, so you see what lies ahead.
- Optionally turns behind the running hero and eases its pitch to a set angle.
- While the camera turns, the cursor stays over the same spot on the ground, so a held button keeps the hero on
  course instead of sending them in circles.
- A camera arm: the camera stops at a wall, a mountain or a roof behind it and, optionally, moves in when an
  obstacle hides the hero. Close up, the hero turns translucent.
- Behind obstacles the hero shows as one silhouette with an outline, with held equipment drawn on top.

**Also included**

- A settings window (F10) with tabs for controls, character, camera, display, interface and sound, saved to
  `user://settings.cfg`. The interface is in English, Spanish, Japanese, Brazilian Portuguese, Russian, Turkish and
  Simplified Chinese, switchable on the fly.
- The character reports what it is doing, for animations, effects and the interface: the state (standing, running,
  sprinting, jumping, falling) with a signal for each change, steps with the foot, take-offs and landings, the speed
  as a blend value, the movement in the model's axes, turning and the gait cycle. Sounds are connected to the
  signals, and a panel (Settings → Interface) shows it all live with the latest events.
- A demo level: an 80 × 80 m fenced glade with ruins, a camp, a farmstead, a hedge maze, a platform with a ramp and
  stairs, and a mountain with a spiral trail. Four places to discover with five NPCs posted at them, and ten hero looks
  to choose from.
- Headless tests of movement, input, jump, sprint and sounds, the character's state, stairs and slopes, the camera and
  its arm, hero looks, the settings window and translations, and a script that finds the editor's node warnings in all
  scenes without opening the editor.

**Not included:** gamepad support (mouse and keyboard only) and animations: the models are static primitives.

## How it fits together

```
mouse, WASD ──► PointClickMoveInput ──move_to(point)────► NavigationMover ──► GroundMotion
                                    ──steer(direction)──► (path or            (acceleration, braking,
                                                           direction)          turning: plain math)
                                                               │ velocity
                                                               ▼
Shift, Space ──► CharacterActionInput ──────────────────► GroundCharacter
                                                          (CharacterBody3D: gravity, jump, sprint,
                                                           move_and_slide, turning the model)

mouse ──► OrbitCameraRig ──► CameraArm ──► Camera3D
```

- **Only `GroundCharacter` moves the body.** Movement components return a velocity and never call
  `move_and_slide()`, so gravity, jumps and any future knockback are combined in one place.
- **`GroundMotion` is math without nodes**, easy to test in isolation.
- **The character knows nothing about the mouse.** The input nodes live in `main.tscn`, not in `player.tscn`.
  For an NPC, instance `player.tscn` without the player-only `Silhouette` and `Appearance` nodes and call
  `NavigationMover.move_to()` from your AI.
- **Components know nothing about the settings.** They read their own exported properties. Only the demo's
  `settings_applier.gd` and the settings window talk to the `Settings` autoload, so a component moves to another
  project without them.

Details: [Architecture](docs/en/architecture.md).

## Using it in your project

The components are in `addons/iso_orbit/`, one folder per part; copy the ones you need into the same folder of
your project:

| Addon | What it gives |
|---|---|
| `orbit_camera` | The orbit camera and its arm; works with any `Node3D` target |
| `click_to_move` | Click and hold to move along the navigation mesh, steering, the click marker |
| `ground_character` | The ready-made body: gravity, jump, sprint with stamina, ledge guard, step signals, sounds, the hand swing, switchable models (needs `click_to_move`) |
| `occluded_silhouette` | The character's silhouette behind obstacles |
| `points_of_interest` | Places to discover and the message about them |
| `ui_screens` | A stack of windows that pauses the game, and an FPS counter |

Movement comes as a chain: input commands a `NavigationMover`, and the mover only computes a velocity, so the body it
belongs to applies it every physics tick. `GroundCharacter` is the ready-made body; a minimal one looks like this:

```gdscript
extends CharacterBody3D

@onready var mover: NavigationMover = $NavigationMover


func _physics_process(delta: float) -> void:
	var planar := mover.compute_velocity(delta)
	velocity.x = planar.x
	velocity.z = planar.z
	if not is_on_floor():
		velocity += get_gravity() * delta
	move_and_slide()
```

Call `mover.move_to(point)` or `mover.steer(direction)` from anywhere: your own input, AI or network code.
[Using it in your project](docs/en/integration.md) says what each addon needs, and
[Project setup](docs/en/project-setup.md) lists the physics layers, input actions and groups the components
expect from `project.godot`.

## Tests

```bash
godot --headless --fixed-fps 60 --path . --script res://tests/run_checks.gd
```

Here `godot` is your Godot 4.7.2 executable; on Windows use the `_console.exe` build to see the output and get
the exit code. To run only some suites, add parts of their names after `--`, for example `-- camera input`. The
exit code is 1 if any check fails. Details: [Tests](docs/en/testing.md).
