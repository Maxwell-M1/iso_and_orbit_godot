# Орбитальная камера

[← Оглавление документации (репозиторий шаблона)](../../../docs/ru/index.md)

> Это перевод [английского оригинала](README.md). При расхождениях верен оригинал.

[English](README.md) · [Español](README.es.md) · [日本語](README.ja.md) · [Português (Brasil)](README.pt_BR.md) · **Русский** · [Türkçe](README.tr.md) · [简体中文](README.zh_CN.md)

Орбитальная камера для изометрических игр и игр с видом сверху. Она следует за любым `Node3D`, вращается мышью
и меняет зум колесом. На бегу камера может независимо поворачиваться за целью, выравнивать наклон и возвращаться
к заданному зуму. Держатель не даёт ей войти в стены и по желанию приближает её, если препятствие скрывает цель.

Часть Iso & Orbit для Godot 4.7. Лицензия MIT (см. `LICENSE`). При самостоятельном использовании этой папке
не нужны другие аддоны.

| Скрипт | Класс | Назначение |
|---|---|---|
| `orbit_camera_rig.gd` | `OrbitCameraRig` (`Node3D`) | Следование за целью, ввод, зум и необязательное выравнивание на бегу |
| `camera_arm.gd` | `CameraArm` (`Node3D`) | Размещение камеры, реакция на препятствия и необязательная прозрачность вблизи |

## Добавление в сцену

1. Скопируйте эту папку в `res://addons/iso_orbit/orbit_camera/`.
2. В **Project Settings → Input Map** добавьте `camera_rotate` (правая кнопка мыши), `camera_zoom_in` (колесо вверх)
   и `camera_zoom_out` (колесо вниз). Экспортируемые имена действий рига можно изменить. Отсутствие действия
   вызывает ошибку при запуске, а ввод по нему не сработает.
3. Добавьте узлы ниже рядом с движущейся целью. Назначьте `CameraRig.target` на персонажа или другой `Node3D`.
   Оставьте масштаб поддерева камеры и его родителей неизменным.

   ```text
   Scene
   ├── Character (движущаяся цель)
   └── CameraRig (Node3D + orbit_camera_rig.gd; target = ../Character)
       └── CameraArm (Node3D + camera_arm.gd)
           └── Camera3D (Current = on)
   ```

   Риг и держатель сами находят первых прямых детей `CameraArm` и `Camera3D` соответственно; можно также
   назначить экспортируемые ссылки `arm` и `camera`. Локальный трансформ `Camera3D` оставьте исходным:
   держатель задаёт его сам. Сделайте камеру Current, когда она должна показывать активный вид. Для кадрирования
   шаблона задайте угол обзора 45° и дальнюю плоскость 300 единиц мира.
4. Твёрдые коллизии мира поместите на физический слой 1. Маска держателя `collision_mask` по умолчанию — слои 1
   и 3 (`0b101`); на слое 3 могут быть препятствия только для камеры, например крыши. Не помещайте персонажей
   в эту маску, чтобы они не толкали камеру. Добавьте `camera_ignore` телу или его предку, чтобы исключить его.
   По желанию назначьте `CameraArm.fade_target` на корень модели, который станет полупрозрачным вблизи.
5. Если цель движется на физических тиках, включите **Project Settings → Physics → Common → Physics Interpolation**.
   Каждый отображаемый кадр риг следует за интерполированной позицией цели и отключает собственную интерполяцию.
   Держатель и камера по умолчанию наследуют этот режим.

По умолчанию скрипт даёт ручное вращение: все три выравнивания на бегу выключены, хотя у их времени и целей есть
значения. Для необязательного следования, настроенного в герое шаблона, используйте `follow_time = 1.1` с,
`follow_pitch_angle = -22°`, `follow_pitch_time = 1.1` с, `follow_zoom_level = 0.55`,
`follow_zoom_time = 1.5` с, `follow_wait_after_rotate = true` и `height_follow_time = 0.15` с. Включите
`follow_movement` для поворота за бегом; `follow_pitch` и/или `follow_zoom` включайте лишь при необходимости.
В начале у героя шаблона все три выключены. Углы в Инспекторе задавайте градусами, в GDScript — радианами
через `deg_to_rad()`.

При включённом `follow_wait_after_rotate` следование остаётся на паузе после намеренного вращения мышью,
пока цель не замедлится или не начнёт новый бег. Если ввод запускает новый бег до остановки цели, вызовите
`end_follow_wait()`. Шаблон соединяет с ним `PointClickMoveInput.run_requested`, а `hold_pending_changed` —
с `set_follow_paused()` в `gdscript/player/playable_hero.tscn`. Если цель движется непрерывно и не может
сообщить о новом беге, выключите ожидание. Держите `sharp_turn_speed` не выше половины скорости поворота
персонажа, чтобы камера не следовала за промежуточными направлениями разворота: в шаблоне 360°/с соответствует
повороту героя 720°/с.

Без держателя работает и прямой дочерний `Camera3D` рига. Она остаётся на расстоянии зума и может проходить
сквозь стены; для реакции на препятствия и прозрачности нужен `CameraArm`.

Кривая зума, все свойства, перекрытие и проверенные взаимодействия описаны в
[Камере](../../../docs/ru/systems/camera.md). Перенос готового героя — в
[Использовании в своём проекте](../../../docs/ru/integration.md#перенос-героя-из-демо-в-свой-проект) и
[Настройке проекта](../../../docs/ru/project-setup.md).
