# 在编辑器中编辑场景

[← 文档目录](index.md)

> 本文是[英文原文](../en/editor_authoring.md)的翻译。两者不一致时，以英文版为准。

演示中的场景就是为在编辑器中编辑而设计的。节点之间的引用在检查器中设置；组件会检查自身配置，缺少什么或设置有误时在“场景”面板中显示警告；游戏开始时才设置的内容（相机的视角、角色的模型和头顶的名字、传送门标牌上的地名、道具的尺寸）也会在编辑器中显示。这些预览从不保存：保存的场景只包含你设置的内容，因此其 diff 中只有你的改动。

## 引用与警告

与其他节点协作的组件以属性的形式引用它们：`PlayableHero.character`、`GroundCharacter.mover`、`OccludedSilhouette.target` 等。在检查器中把节点拖到相应字段即可设置。只要组件需要的引用为空，或者节点处于无法工作的状态（`NavigationMover` 不在它所移动的身体下、`LevelPortal` 没有目标场景、输入映射中缺少某个输入动作），“场景”面板就会在该节点旁显示警告标志；把鼠标指针悬停在上面即可看到原因。警告会跟随你的编辑：修改属性、添加或删除子节点、编辑路线的曲线、边缘防护的 `max_drop` 或角色的下落设置时，警告会随之出现或消失，无须重新打开场景。

组件之所以能在编辑器中检查自身，是因为它们的脚本是工具脚本。在编辑器中它们只做检查和预览：不处理输入，不运行物理和计时器，计算出的任何内容都不会写入场景。在游戏中，它们照常工作。

## 初始关卡

`gdscript/main.tscn` 包含关卡容器 `Levels`，初始关卡 `World` 是它的子节点，并由 `Levels.initial_level` 指定。未指定时，容器从它的第一个 `Node3D` 子节点开始；如果有多个 3D 子节点且都未指定，容器会显示警告。见[关卡](systems/levels.md)。

## 编辑器中的相机

`Hero/CameraRig` 显示游戏开始时的视角：支架位于目标处、高出目标 `focus_height`，按 `start_yaw` 转向，倾角和距离由 `start_zoom` 决定，相机臂则把相机显示在该距离上。修改这些属性即可调整开局的取景；3D 视图会立即随之变化。

游戏每一帧都会设置支架的变换、相机的变换以及支架下相机臂的 `length`，因此它们在编辑器中也只是预览：手动移动的支架或相机会回到游戏放置它的位置，支架下相机臂的 `length` 为只读。保存时保留场景加载时的值，因此预览从不出现在 diff 中，放置英雄的场景也不会多出一份其相机位置的副本。没有目标的支架则不同：游戏不会移动它，因此它的位置由你决定，并按你的设置保存；只有它的转向是预览。

## 来自设置窗口的设置

`SettingsApplier` 会把玩家已保存的设置（F10）应用到场景中设置的值之上。场景中的值也就是默认值：玩家没改过的设置保持场景中的值，**全部重置**也会恢复到这些值。在检查器中调整场景节点时，可以关闭 `SettingsApplier.use_saved_settings`，让节点完全按设置的值运行；此时设置窗口不会改动它们，只改变引擎设置（全屏、帧率、V-Sync、物理插值、界面缩放、语言、音量）。见[设置](settings.md)。

## 实体道具

实体道具是以 `StaticProp` 为根节点的场景，根节点是挂载 `shared/world/props/static_prop.gd` 的 `StaticBody3D`。其可见部件和碰撞形状都是根节点的子节点，并已编组，因此在 3D 视图中点击会选中整个道具。

- 通过根节点**移动**它。
- 用 `dimensions` **调整尺寸**，以米为单位，沿道具自身的轴计量：可见部件和碰撞会一起改变。某个轴上为 0 时，各部件在该轴上保持原有尺寸，因此新道具（取值为 `(0, 0, 0)`）保持制作时的尺寸，而要把柱子加高，只需设置它的高度。不要缩放根节点，否则它会显示警告；也不要缩放其子节点；把网格放大或缩小时，它的碰撞形状也要随之修改。
- 用 `surface_material` **重新着色**：它会替换所有可见部件的材质；留空则保留它们各自的材质。

各关卡共用的道具是 `shared/world/props/` 中的场景：`stone_pillar.tscn`、`solid_box.tscn`（墙、箱子、平台及其坡道）、`grove_tree.tscn`、`rock.tscn`，以及森林、营地和农庄中的实体道具（灌木没有碰撞，也不是 `StaticProp`）。每个实例各自设置 `dimensions` 和 `surface_material`；要修改所有实例，请编辑道具的场景。只用一次的部分直接放在所属关卡中，带有自己的 `StaticProp` 根节点：草地的地面、平台的台阶、迷宫的树篱、各地点的人物、十种英雄外观、孤岛的地面和边缘墙。树篱保持其网格的尺寸：它们的树叶需要细分为约 25 厘米单元格的网格，因此其他尺寸的树篱要换用相应尺寸的网格，而不是用 `dimensions`。

像平常一样编辑部件：移动子节点、更换网格或形状、添加部件。道具会把改动当作自己的新形状：在 `dimensions` 为 0 的轴上，它采用部件的新尺寸；在其他轴上，它保持原有的拉伸。新道具不会自动编组：选中其根节点，然后点击 3D 视图工具栏中的 Group（编组）按钮。保存时，部件按你制作的样子保存；尺寸调整是预览，在场景打开时和游戏开始时重新应用。调整过尺寸的形状是该实例自己的副本，因此调整一个实例的尺寸绝不会改变另一个实例。圆形或旋转过的形状若被不均匀地拉伸，会变成以同样方式拉伸的凸形状。

会动的部件要放在普通的 `Node3D` 之下：自行播放动画的节点不能是道具调整尺寸的那个节点。在山上，道具调整尺寸并放置的是 `CrystalAnchor`，而它的子节点 `Crystal` 负责旋转和上下浮动。

改变道具的碰撞（移动、调整尺寸或编辑它）后，请重新烘焙导航网格，见[世界与导航](systems/world-and-navigation.md#重新烘焙导航网格)。

## 巡逻

草地上的骑士会沿一条路线行走。打开 `shared/world/world.tscn`，选中 `Routes/KnightPatrol`（一个 `Path3D`）：在 3D 视图中用曲线工具编辑其曲线，骑士就会沿那里绘制的线行走，在弯处平滑转向。要让拐角变圆，在工具栏上开启 **Select Control Points**，按住 Shift 从该点拖动，拉出它的手柄。让线与树篱保持约一个骑士身宽的距离：沿线行走时，骑士不会寻找绕开树篱的路。骑士（`NavigationRegion3D/Characters/Knight`，`gdscript/npc/knight_patrol.tscn` 的实例）在 **Route** 中引用它。骑士从房子旁边的位置走到路线的第一个点，走完最后一个点后沿最短路径返回：这两段路不属于所绘制的线。路线属于关卡，因此同一个角色可以在另一个关卡中走另一条路线。孤岛上的游侠（`island_patrol.tscn`）在岛上沿 `Routes/IslandPatrol` 行走。路线没有点，或者路线位于角色内部时，角色的根节点 `Knight` 上会显示警告。

在编辑器中，巡逻角色会显示其模型和头顶的名字；两者都不会保存到场景中。在其根节点上可设置 **Model Scene**、**Speaker Name**（显示在头顶和字幕中的名字）和 **Blocked Line**（有人挡路足够久时说的台词）。行走方式在 `Character/PatrolController` 上设置（需开启 **Editable Children**）：**Cycle Wait**，每轮结束后在出发点的等待时间（10 秒）；**Waypoint Wait**，在曲线每个点上的停留时间；**Blocked Delay**，有人挡路多久后才说台词（骑士为 2.5 秒）；**Blocking Distance** 和 **Blocking Angle**，骑士前方有人就会让他停下的区域：向前 1 米，向两侧各张开 25°，像手电筒的光束。在他的侧面和后面，没有人能让他停下。见[移动](systems/locomotion.md#patrolcontroller沿路线行走)。

## 检查编辑器端的功能

`tests/run_checks.gd` 检查的是游戏，它无法运行编辑器。编辑器端的功能，即随编辑更新的警告、预览以及场景保存时包含的内容，有自己的检查：打开 `tests/editor_tool_checks.tscn`，然后在检查器中点击 **Run Checks**。结果显示在检查器的 **Status** 和 **Results** 中，也写入 `.godot/editor_tool_checks/results.json`；输出中会打印状态行。这些检查只把场景保存到该文件夹中，每次运行都会清空它：不会写入项目中的任何场景，也不会写入玩家的任何设置。见[测试](testing.md#编辑器中的检查)。
