# 世界与导航

[← 文档目录](../index.md)

> 本文是[英文原文](../../en/systems/world-and-navigation.md)的翻译。两者不一致时，以英文版为准。

演示的初始关卡是草地 `shared/world/world.tscn`：一片 80 × 80 米、围着木栅栏的林间空地。其中的一切都由基本几何体和着色器构建；精细的表面图案来自烘焙纹理。远古石环旁的传送台通往第二关“孤岛”；两关详见[关卡](levels.md#演示中的关卡)。

## 物理层与导航

障碍物是第 1 层（`world`）上的 `StaticBody3D`，角色位于第 2 层（`characters`），仅阻挡相机的物体位于第 3 层（`camera`），关卡边缘的隐形墙位于第 4 层（`bounds`）；见[项目配置](../project-setup.md#物理层)。导航网格由第 1 层的碰撞体烘焙（孤岛还包括第 4 层边缘墙），代理半径为 0.5 米；角色胶囊体半径为 0.35 米，因此路径与拐角保持余量。

| `NavigationMesh` 参数 | 值 | 原因 |
|---|---|---|
| `agent_radius` | 0.5 米 | 路径远离拐角 |
| `agent_height` | 1.75 米 | 演示现有网格的烘焙值；新建有天花板的关卡至少要用完整碰撞体高度（英雄胶囊体为 1.8 米） |
| `agent_max_slope` | 40° | 山坡不会被纳入网格 |
| `cell_height` | 0.025 米 | 足够精细，可区分下述攀爬高度 |
| `cell_size` | 0.25 米 | 水平烘焙分辨率；必须与导航地图匹配 |
| `agent_max_climb` | 0.3 米（12 个单元格） | 角色能迈上的台阶（`GroundCharacter.max_step_height`） |
| `geometry_parsed_geometry_type` | Static Colliders | 网格依据碰撞形状，而非可见网格。下述碰撞掩码作用于碰撞体；没有可见网格的隐形墙也只有用此模式才能参与烘焙 |
| `geometry_collision_mask` | 第 1 层；孤岛为第 1 和第 4 层 | 只计入障碍物及隐形墙 |
| `filter_walkable_low_height_spans` | 演示中关闭 | 有天花板的新关卡应开启，以排除净空低于 `agent_height` 的区域 |

**让导航与碰撞身体匹配。**`agent_max_climb` 不应高于 `GroundCharacter.max_step_height`（此处为 0.3 米），导航坡度上限不应高于身体的地面坡度上限（此处分别为 40° 和 45°）。修改任一数值后都要重新烘焙。导航会被栅格化为单元，因此数值匹配也不能保证每一处边缘都正确：请测试最高的可攀台阶和最低的禁止越过的边缘。演示测试其 0.2 米台阶，并拒绝一个 0.4 米方块。竖向单元精细到 0.025 米，才可区分这些小高度差。

新关卡的代理高度至少应等于胶囊体完整高度，并启用 `filter_walkable_low_height_spans`；只设置高度不会开启净空过滤。烘焙时要纳入天花板碰撞体。悬浮模型高出身体，因此其视觉净空还需单独检查。半径控制路径与墙的间距；改变胶囊体半径后，也请检查狭窄走廊并重新烘焙。

地图和网格的 `cell_height`、`cell_size` 应分别相等。演示竖向使用 0.025 米，水平方向使用 0.25 米；对应项目设置为 `navigation/3d/default_cell_height` 和 `navigation/3d/default_cell_size`。Godot 的 [NavigationMesh 参考文档](https://docs.godotengine.org/en/stable/classes/class_navigationmesh.html)介绍了烘焙分辨率、取整和净空过滤。

烘焙出的表面可能略高于碰撞地面。`NavigationMover` 在 XZ 平面比较路径进度；物理系统决定身体实际高度。物理层选择烘焙几何体，区域的导航层和 `NavigationMover.navigation_layers` 则选择可用路径。

导航结果为空时，移动器退回直线移动；部分路径可能在不可达目标之前结束。调整移动参数来弥补坏路线之前，请先使用 **调试 → 显示导航（Debug → Visible Navigation）**和演示的**角色路径线**。见[移动](locomotion.md#navigationmover)。

## 重新烘焙导航网格

网格预先烘焙并直接保存在各关卡场景 `shared/world/world.tscn` 和 `shared/world/island/island.tscn` 中（`NavigationRegion3D` 的 `NavigationMesh` 资源）；游戏不会重新计算。编辑关卡后，请重新烘焙对应网格。两者参数相同，只有碰撞掩码不同：孤岛包含第 1 和第 4 层。

**何时需要：**移动、添加、删除或调整第 1 层（`world`）上任何带碰撞形状的物体：岩石、箱子、墙、树、道具、NPC、山；在孤岛上也包括第 4 层（`bounds`）的隐形墙。只改变外观（网格、材质）时不需要；第 3 层（`camera`）的身体、玩家角色（第 2 层）和区域（`Area3D`）也不需要。如果忘记重烘，路径会穿过已移动的物体（角色会撞上并沿其滑动），或绕开它原来所在的空位。

**在编辑器中：**

1. 打开关卡场景。
2. 在场景树中选中 `NavigationRegion3D`。
3. 点击 3D 视图上方工具栏中的 **Bake NavigationMesh（烘焙导航网格）**。几秒钟后，视图中的蓝色网格会更新：物体周围出现代理半径（0.5 米）宽的空洞，原先物体所在位置变为完整网格。
4. 保存场景（Ctrl+S）：网格嵌入场景。

烘焙参数位于资源本身：选中 `NavigationRegion3D`，在检查器中展开 `Navigation Mesh`。

重新烘焙后，请运行[测试](../testing.md)：测试路线依赖网格。在运行的游戏中，可用编辑器的“调试 → 显示导航”查看网格；设置（F10）→ 界面 → **角色路径线**显示角色路径。

## 关卡

- **中心**是出生点。周围有：一圈残破的石柱、开口朝向出生点的 U 形陷阱、一道带缺口的长墙、箱子、一片小树林、树篱迷宫，以及一个 1.6 米高的平台，平台西侧有坡道，东侧有台阶（七级 0.2 米高的台阶，踏面深 0.4 米）。测试会用到所有这些物体，因此它们保持在原位。
- **道路**是土路带：从南侧栅栏穿过墙上的缺口通到出生点，再通往山、遗迹、营地和坡道；农庄的道路在墙的南侧分岔。道路只是一种图案（`shared/world/terrain.gdshaderinc` 中的 `ROADS` 线段），不影响移动。地面和山脚下的缓坡草地都会绘制道路，因此道路与山路无缝衔接。道路从西侧到达山路起点：山路起点以东，山是高达 4 米的陡峭崖壁。
- **道具**来自 `shared/world/props/`：西北方和边缘一带的森林、灌木、巨石，东边的营地（帐篷、光线闪烁的篝火、木桶），西南边的农庄（房屋、水井）。
- **山**位于东北方，高 10 米，有一条螺旋山路通往山顶。
- **十种英雄外观**背靠南墙排成一排，位于缺口东侧（见[角色](characters.md#英雄外观)）。

要改变布局，请在关卡场景中编辑道具实例，然后重新烘焙导航。回归测试使用演示中的特定路线和障碍物位置；自己的布局最好另建关卡，或在改动测试地形时同步更新测试。

### 地点与 NPC

四个地点都是 `PointOfInterest` 区域。玩家首次进入时，屏幕顶部会显示“发现地点：……”几秒钟。每个地点都站着 NPC，头顶有名称标签（`Label3D`），面朝地点中心；骑士则面朝道路前方。

| 地点 | 位置 | 谁在那里 |
|---|---|---|
| 风啸峰 | 东北方的山顶 | 巫师，站在带水晶的祭坛旁 |
| 旅人营地 | 东边：帐篷、篝火、木桶 | 游侠和矮人，在篝火旁 |
| 井边农庄 | 西南边：房屋、水井 | 骑士，在路边守卫 |
| 远古石环 | 出生点西北方的一圈石柱 | 盗贼，站在祭坛旁 |

每个 NPC 都是第 1 层上带胶囊体的 `StaticBody3D`（`World/NavigationRegion3D/Characters`）：导航网格绕开他们，没有人能穿过他们。营地、农庄和遗迹位于 `World/Places` 下；山峰位于 `mountain.tscn` 中。

**新增地点：**在任意世界场景中添加一个 `PointOfInterest`（`collision_mask` 包含角色所在第 2 层的 `Area3D`），并设置碰撞形状和 `title`。提示消息会通过分组找到每个地点，包括以后加载的关卡中的地点；无须手动连接。将标题加入翻译（见 [UI](ui.md#翻译)）。孤岛上还有第五处地点“隐士营地”。

## 表面

几乎每种表面都是 `shared/world/` 中的着色器，配有 `shared/world/materials/` 中的材质；例外的是普通 `StandardMaterial3D` 材质，在本节末尾列出。依赖物体尺寸和形状的部分由着色器计算，开销很低：与箱体高度相适应的砌石层、木板、框架和立柱、木构架、桶板和桶箍、柱槽和柱鼓、沿 `ROADS` 的道路、按高度分布的岩层。因此任何尺寸的箱体都不会拉伸其图案。精细细节（草叶、碎石、树叶、树皮、石材纹理）来自烘焙纹理，见下文。

| 表面 | 着色器 | 外观 |
|---|---|---|
| 墙、平台、坡道、台阶 | `stone_masonry` | 错缝砌筑的石块带有灰缝，每块石头都有各自的色调、纹理和缺口，通过法线表现浮雕，靠近地面处有污垢和苔藓。顶面是一层沿短边横铺的石块 |
| 树篱迷宫 | `hedge_foliage` | 两层树叶，每层都有各自的旋转、大小、色调和倾斜；缝隙中透出灌木深处的阴影；侧面像修剪过的灌木一样凹凸不平 |
| 箱子、栅栏 | `wood_planks` | 带年轮、纤维、节疤和缝隙的木板。箱子每个面都有木板框、斜撑和钉子；栅栏由固定在每隔 2.5 米一根立柱上的长条风化木板组成 |
| 石柱、水井 | `stone_column` | 通过法线表现的环绕柱身的凹槽，从地面起每 0.8 米一节带接缝的柱鼓，光滑的柱基，条纹，少量裂纹，地衣，靠近地面的苔藓。水井使用环形砌块（`blocks_around`） |
| 巨石、立石 | `rock` | 带矿脉和裂纹的粗粒石材，顶部有地衣，靠近地面处有苔藓；图案采用三平面映射（`triplanar.gdshaderinc`），每块巨石各不相同 |
| 房屋墙壁 | `timber_plaster` | 木构架：立柱和横梁框架中带污渍和细裂纹的灰泥，石砌墙基 |
| 房屋和水井的屋顶 | `thatch` | 成排草束组成的茅草，每排下方有阴影，草秆顺坡而下，捆扎的屋脊，苔藓 |
| 帐篷、门帘、旗帜 | `canvas` | 编织帆布：带接缝的布片、褶皱、补丁；旗帜带有边框和纹章 |
| 木桶 | `barrel` | 带缝隙的桶板、生锈的铁箍、木板桶盖 |
| 原木、树干、旗杆 | `bark` | 沟壑纵横的树皮，靠近地面处和北侧有苔藓；篝火处有烧焦并阴燃的原木 |
| 树冠、灌木 | `foliage` | 三个轴向平面上的两层树叶，团块感，顶部较亮；松树上为针叶，秋橡树上为橙色和红色 |
| 地面 | `ground_grid` | 见下文。孤岛草地使用 `island_ground.tres`，即关闭道路（`roads`）的相同地面 |
| 山 | `mountain` | 按面颜色选择草地、山路和岩层 |
| 水井中的水、孤岛湖水 | `water` | 缓慢的涟漪。湖水（`lake_water.tres`）颜色更浅，涟漪更强（`ripple` 为 0.55，水井为 0.35） |

砌石图案沿网格的面分布，并且知道箱体尺寸：没有面细分的 `BoxMesh` 只在每个角上有顶点，因此 `abs(VERTEX)` 就给出半尺寸。它们以不插值的方式（`flat` varying）传给像素；若插值，各像素的末尾数字会略有不同，当砌层数量恰好落在半数上（如 1.4 米台阶用 0.4 米高的砌层），部分像素会向上取整、部分向下取整，产生闪烁。灰泥、木板和布料着色器也以同样方式传递箱体尺寸。侧面的砌层与高度相适应，侧面最上一层就是顶面石块的边缘，因此灰缝沿边缘延续。坡道（一块薄板）也是这样的一层，两端灰缝与顶面吻合。相比之下，迷宫箱体每隔 25 厘米有面细分（`subdivide_*`），因为其侧面按世界坐标的噪声位移：边上同一顶点的各副本一起移动，面不会裂开。碰撞形状仍是普通箱体；树叶会突出几厘米。

**地面**（`ground_grid.gdshader`，共用部分为 `terrain.gdshaderinc`）：多种尺度的草地（深色、普通和干枯草地的大块斑块，草丛，带倾斜法线和根部阴影的两层草叶，空地上零星的花朵）和道路（带草丛的参差边缘，被踩得较亮的中间部分，浅车辙，颗粒，干燥处的细裂纹，带阴影的碎石，边缘处更多）。精细细节来自烘焙纹理，每 3.84 米平铺一次；大块斑块来自覆盖整个地面的遮罩。在远处，细节通过纹理的 mip 级别淡化为平均颜色。山上的草地和山路使用相同的代码。一个 1 米网格（每 5 米一条粗线）默认关闭；可以通过 `shared/world/materials/ground.tres` 上的 `grid_strength` 开启，用来测量速度和距离。

低开销的着色器噪声（石块和木板的随机数、树叶的团块）位于 `noise.gdshaderinc`，树叶位于 `leaves.gdshaderinc`。少数材质仍是普通的 `StandardMaterial3D`：角色装备（法杖、弓、斧）使用的 `dark_wood.tres` 和 `wood.tres`，以及发光的 `crystal.tres` 和 `fire.tres`。

## 烘焙纹理

表面图案（带草叶和花朵的草地、带碎石的泥土、树叶、树皮、石材纹理、灰泥、木纤维、茅草、编织布）最初设计为噪声着色器，但游戏并不为每个像素实时计算它们：它们被一次性烘焙为 `shared/world/textures/` 中的无缝纹理，由世界着色器平铺使用。

烘焙用纹理采样代替每个像素重复进行的噪声计算。替换纹理时请保留下述导入设置；一些通道存储的是着色器数据，而不是普通颜色。

- **无缝。** 图案的噪声随图块重复，每个图块包含整数个特征，因此接缝不可见。例外是 `ground_mask`：它覆盖整个 96 米地面上的大块斑块和道路，不平铺。
- **颜色留在世界着色器中。** 树叶、柱石、树皮和木纤维烘焙时不带颜色（只有叶片色调、阴影、叶片或缝隙、污渍、法线倾斜），由世界着色器根据材质参数生成颜色：一张树叶纹理同时用于橡树、秋橡树和树篱。只有草地（作为斑块色调的乘数）、花朵和碎石烘焙了颜色。
- **浮雕**是存储在两个通道中的法线倾斜，在烘焙时根据高度差计算。
- **文件：** 无损 WebP（alpha 为零处的数据保持完整），导入时使用 GPU 压缩（BPTC）、生成 mipmap，并且不对透明像素做颜色修正，因为 alpha 通道存储着数据。替换纹理时请保留这些导入设置。

## 山与风啸峰

山位于世界边缘的一个角落（山坡延伸到栅栏之外），从任何地方都能看到。通往山顶的山路宽 3 米：从道路尽头（23, 0, −19）开始，以 12° 的坡度绕山将近一整圈（340°）。山路两侧的山坡都很陡（山路上方 76°，下方 60°）：既无法徒步爬上（身体只能站在 45° 及更平缓的坡面上），也无法沿路径上去（导航网格只接受 40° 以内的坡度），而边缘防护会防止角色从山路上掉下去。从地面点击山顶，角色会沿山路前往：51 米，用时 9.8 秒。

山顶有一座圣坛：一座祭坛，上方漂浮着一颗缓缓旋转的发光水晶，另有五块立石和一面旗帜。山顶就是“风啸峰”这个地点。

山是由脚本生成的高度图：一个带面颜色和平直着色的网格，上面覆盖材质 `materials/mountain.tres`（按面颜色分别呈现带草叶的草地、带碎石的山路泥土、带裂纹和地衣的岩层），以及由相同三角形生成的碰撞形状（`shared/world/mountain/*.res`）。为了能沿山路生成路径，做了以下处理：

- 山路在横向上高度一致，因此其内侧边缘比中轴更陡（陡的程度为中轴半径与边缘半径之比）。弯道并不急（半径 9.5 → 7 米），因此即使在接近山顶处，内侧边缘也比 16° 平缓：如果更陡，每 0.25 米单元格攀爬 0.075 米的导航网格就会把山路断开。
- 从道路进入的入口：在山脚，山路低于 1 米的那一段外侧坡度平缓。否则山路从起点开始就向外侧陡降，入口会收窄成一条比代理余量还窄的带子。
- 山路的最后 3 米与山顶齐平，因此山路与山顶沿一条带状区域相接，而不是只在一个点上相接。

相机默认从东南方向观察，因此在山路的远侧，山会遮住英雄，英雄随之显示为剪影（见[角色](characters.md#occludedsilhouette单一形状武器轮廓外圈描边)）。
