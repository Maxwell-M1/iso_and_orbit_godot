# 输入

[← 文档目录](../index.md)

> 本文是[英文原文](../../en/systems/input.md)的翻译。两者不一致时，以英文版为准。

两个节点将玩家输入转换为命令。它们自己都不移动任何东西。

- `PointClickMoveInput`：鼠标，以及按住右键时的 WASD → `NavigationMover.move_to()`、`steer()` 和 `stop()`。
- `CharacterActionInput`：冲刺和跳跃按键 → `GroundCharacter.sprint_requested` 和 `jump()`。

两者都位于可操控英雄场景（`playable_hero.tscn`）中，而不在角色场景中，因此同一个角色也可以改由 AI 驱动。玩家操作说明见[操作](../controls.md)。复制装配好的英雄见[在你的项目中使用](../integration.md#将演示中的英雄迁移到你的项目)；推荐的参数组合见[配置方案](../configurations.md)。

## PointClickMoveInput

| 输入 | 命令 |
|---|---|
| 点击地面 | `move_to(point)`：从相机发出、针对 `ground_mask` 的射线找到该点 |
| 按住左键 | 根据 `hold_mode`，`steer()` 朝向光标，或 `move_to()` 前往光标下的点 |
| 先按右键再按左键，或在 `hold_delay` 内同时按下 | `steer()` 朝相机所看方向；A 和 D 斜向前偏转（`keys_with_camera_steer`） |
| 已按住左键，再按右键 | 不下达新命令：按住状态继续朝瞄准点引导，右键只环绕相机（`look_around_while_held`） |
| 右键加 WASD | 相对相机 `steer()`，侧移或转向（`keys_with_camera`）；松开时 `stop()` |

每个物理帧由谁驱动角色，在 `_physics_process` 这一处决定：优先是按住的左键，其具体方式由 `hold_mode` 决定；否则是配合右键的按键。因此在按住右键和 W 时松开左键，角色不会停下：按键会立即接管。

反过来，在双键奔跑中松开右键，角色会保持相机原先所看的路线（`keep_camera_course`）。鼠标移动超过 8 像素之后，光标才接管；在松开后的前 `cursor_takeover_delay`（0.2 秒）内不接管，因为手可能还在转动相机。接管时光标从角色沿奔跑方向前方 4 米处开始引导。此前若松开左键，角色沿原路线停下，就像两键同时松开一样，不受两次松手间隔影响；人很难真正同时松开两个键。关闭 `keep_camera_course` 后，右键一松开，光标就以环绕前的位置立即接管，可能让角色急转。

### 奔跑中环顾四周

跟随光标持续奔跑时，再按右键只会环绕相机（`look_around_while_held` 默认开启）：玩家已在朝目标奔跑，此时只是想四处观察，不想把奔跑方向交给相机。没有这个设置时，角色会立刻转向相机所看方向；关闭相机跟随时，那通常不是原奔跑方向。按下右键的瞬间会确定此次行为：

- 已进入跟随光标引导的按住状态：环顾四周；
- 左键尚未超过 `hold_delay`（0.2 秒）而成为按住，即两键几乎同时按下，或先按右键：朝相机所看方向奔跑；
- 松开右键后，按住状态仍保持相机路线（`keep_camera_course`）：再次朝相机所看方向奔跑。鼠标移动后若已由光标引导，下一次按右键则改为环顾四周。

此行为依赖 `camera_steer_action` 同时转动相机，就像 `OrbitCameraRig.rotate_action`（两者均为 `camera_rotate`）：按住该键时，鼠标不会移动瞄准点。如果另用不同动作，或相机不会随它转动，请关闭 `look_around_while_held`。环顾四周时方向键不起作用：跟平常一样，左键持续引导奔跑。

环顾四周时，瞄准点不会随鼠标移动：它是相对角色脚下的地面点，也用于相机自行转动时保持路线（`keep_aim_on_camera_turn`）。鼠标只转动相机，在 `STEER` 模式下角色继续朝瞄准点跑。松开右键后，光标回到该点，鼠标移动又能引导。若大幅环绕使瞄准点超出屏幕，组件会沿同一方向将其拉近，以免到达窗口边缘时突然转向。

在 `FOLLOW_POINT` 模式下，环顾四周期间及之后直到鼠标移动，奔跑目标点相对角色脚下保持原位（与 `keep_camera_course` 相同：在 `cursor_takeover_delay` 过后移动超过 8 像素才接管），因此角色保持路线，不会到达目标。从另一个角度看，即使光标指向地面上相同的位置，射线也可能先碰到坡道或平台，光标下的点并非同一个。若按住奔跑已到达目标（光标在脚下），便没有可保持的目标点，环顾四周时也仍留在那里。松开右键后，除非新障碍物挡住，从新相机角度看，光标仍瞄准同一点。

若仍按着右键转相机时松开左键，隐藏的光标会在相机释放时出现在瞄准点，而非相机还原的位置（即按下右键时隐藏光标所在的位置）。

关闭 `keep_aim_on_camera_turn` 后，光标固定在屏幕上，环绕会带着奔跑路线一起转动（环绕 90°，路线也转 90°），与相机自动转动时一样。要不停下地从环顾四周切换成朝相机方向奔跑，可按住右键再次按左键：右键已按下时，左键会立即朝相机方向奔跑。关闭 `look_around_while_held` 后，无论按键顺序如何，右键都会引导奔跑。

### 点击还是按住

按下经过 `hold_delay`（0.2 秒）后变为按住。在此之前，角色继续做原来的事（站着，或继续朝原来的方向跑），既没有标记，也没有通往按下位置的路径。

- **提前松开：点击。** 角色沿路径跑向按下按键时的位置。该点在按下的瞬间确定，即使之后鼠标移动过也是如此。标记出现（`destination_picked`）。角色到达，或这次奔跑因改用按键或按住而被放弃时，标记淡出。
- **按得更久：按住。** 角色立即跟随光标奔跑（`hold_started`），而不会先转向按下的位置。否则它会先沿着通往那个点的路径出发，而绕开障碍物的路径可能通向与光标完全不同的地方。

代价是点击在松开时才生效，比按下即生效晚约 0.1 秒。在尚不确定按下是点击还是按住时，`hold_pending_changed(true)` 会暂停相机的跟随模式（在 `playable_hero.tscn` 中连接到 `OrbitCameraRig.set_follow_paused()`），因此短促的点击绝不会移动相机。

如果按下左键时右键已经按住，就不会产生点击：角色立即朝相机所看方向奔跑。

### 按住模式

`hold_mode`（设置 → 操作 → **按住左键**）：

- `STEER`（默认）：不使用路径，直奔光标。角色沿障碍物滑行，无论你指向坡道的哪里都能跑上去。光标距角色在 `steer_dead_zone`（0.5 米）以内时方向不变：离得这么近，方向对光标过于敏感。松开时角色平稳停下。
- `FOLLOW_POINT`：沿导航路径前往光标下的点。该点移动时路径会重建，因此在高度变化处（坡道、平台）附近，路径可能从一条路线跳到另一条。松开后角色继续跑到最后一个点，并由标记显示该点（`destination_picked`）；开启 `stop_on_release` 时，角色就地制动停下。此设置只影响按住操作：短按仍会跑到点击的点。空路径会直线奔跑，部分路径可能在请求的目标点前结束，详见[移动](locomotion.md#navigationmover)。

### 配合右键的按键

按键只在按住右键时有效：此时相机随鼠标转动，光标被捕获。不按右键时 WASD 不起作用。每个模式为 `OFF` 或两种变体之一，分别针对单独按住右键（`keys_with_camera`）和同时按住两键（`keys_with_camera_steer`）设置。

| | `SIDESTEP` | `TURN` |
|---|---|---|
| 右键 + W | 向前，朝相机所看方向 | 相同 |
| 右键 + A / D | 向侧面移动，面朝前方 | 向左 / 右转身并朝那里走 |
| 右键 + S | 后退，面朝前方，速度较慢 | 转身走向相机 |
| 两个键（W + A、S + D…） | 斜向移动，面朝前方 | 斜向移动，面朝前进方向 |
| 左键 + 右键 + A / D | 斜向前，面朝前方 | 斜向前，面朝前进方向 |

两者的脚本默认值都是 `SIDESTEP`；演示的设置和 `playable_hero.tscn` 都将两者设为 `TURN`。`keys_with_camera_steer = OFF` 会禁用双键按住时的 A/D，但两键仍会朝相机方向奔跑。若也要禁用这个命令，就得修改 `camera_steer_action`，这还会影响环顾四周及需要右键的方向键。

斜向移动与直线移动一样快。后退更慢：`NavigationMover` 按移动方向与朝向相反的程度缩放速度，见[移动](locomotion.md#navigationmover)。朝向作为 `steer(direction, facing)` 的第二个参数传入：侧移时它就是相机的前方方向。停下后角色保持原来的朝向；点击或按住会让它重新面朝奔跑方向。

松开按键或右键，角色平稳停下。只按住右键而不按任何键，不会打断跑向点击位置的过程，因此可以在奔跑中转动相机。按键会打断它，标记随之淡出。这些按键对应动作 `move_forward`、`move_back`、`move_left`、`move_right`，按物理位置绑定。

### 按住按键时的光标

**隐藏**（`hide_cursor_while_held`，默认开启）。奔跑时光标只会闪来闪去，尤其是在相机转动、光标随世界移动的时候。按下一旦变为按住，光标即隐藏（短按不会影响它），松开后在瞄准位置重新出现。组件使隐藏的光标留在游戏窗口内；在 macOS 上使用 `MOUSE_MODE_HIDDEN`，其他系统使用 `MOUSE_MODE_CONFINED_HIDDEN`，避免平台移动光标造成瞄准偏移。右键环绕相机时，由相机捕获光标；仍按住左键时松开右键，光标会再次隐藏。暂停或切换窗口会立即显示光标。`is_cursor_hidden()` 可查询组件是否隐藏了光标。

**保持瞄准**（`keep_aim_on_camera_turn`，默认开启）。按住左键时，奔跑方向来自光标这个屏幕上的点。如果相机转动时光标仍固定在屏幕上，光标下的地面位置便会改变，角色随之转向，相机又跟着角色转，结果可能绕圈。因此按住期间，组件让瞄准点随世界移动：相机平滑转到角色身后时，角色继续朝原先瞄准方向奔跑；移动鼠标仍可引导。奔跑中用右键环绕时，也用相同的瞄准点保持路线。

关闭时，光标像驾驶汽车一样操控方向：把光标放在角色右侧，角色就会向右偏转，直到光标位于正前方。在系统无法移动光标的地方（例如 Wayland），奔跑方向依然保持，但光标停在原处。

光标在相机本帧就位后，于 `_process` 中修正：该组件的 `process_priority` 为 1，相机的为 0。输入组件直接读取 `Camera3D`，对相机支架一无所知。

### 属性

| 属性 | 默认值 | 含义 |
|---|---|---|
| `mover` | — | 要下达命令的 `NavigationMover`；必需 |
| `camera` | — | 用于射线和方向的相机；为空时使用视口的当前相机 |
| `move_action` | `move_to_cursor` | 点击和按住 |
| `hold_mode` | `STEER` | 见上文 |
| `keep_aim_on_camera_turn` | 开 | 见上文 |
| `hide_cursor_while_held` | 开 | 见上文 |
| `camera_steer_action` | `camera_rotate` | 按住它时，左键可朝相机所看方向奔跑（先按右键或左键尚未变为按住时；见 `look_around_while_held`）。留空会关闭朝相机方向奔跑、环顾四周和依赖该动作的按键 |
| `look_around_while_held` | 开 | 跟随光标的按住状态中再按相机键，只转动相机，奔跑保持路线。关：不论按键顺序，双键都朝相机方向奔跑 |
| `keep_camera_course` | 开 | 双键按住时松开相机键，保持相机路线直到移动鼠标；随后光标从角色前方开始引导。关：光标立即从原位置接管 |
| `cursor_takeover_delay` | 0.2 秒 | 启用 `keep_camera_course` 时，松开相机键后这么快发生的鼠标移动尚不会接管路线 |
| `ground_mask` | 第 1 层 | 可以点击的物理层。不得包含角色层，也不得包含第 4 层隐形墙（`bounds`） |
| `hold_delay` | 0.2 秒 | 按下变为按住的时间 |
| `steer_dead_zone` | 0.5 米 | `STEER`：光标距角色这么近时不改变方向 |
| `stop_on_release` | 关 | `FOLLOW_POINT`：松开时制动停下，而不是继续跑到最后一个点 |
| `ray_length` | 1000 米 | 从相机发出的射线长度 |
| `keys_with_camera` | `SIDESTEP`（演示中 `TURN`） | 右键 + WASD 模式 |
| `keys_with_camera_steer` | `SIDESTEP`（演示中 `TURN`） | 左键 + 右键 + A/D 模式 |
| `move_forward_action` … `move_right_action` | `move_forward` … `move_right` | 按键 |

`ground_mask` 选择点击射线可命中的物理表面；`NavigationMover.navigation_layers` 则选择供路线使用的导航区域，两者是不同的掩码。角色和隐形墙都不应处于点击掩码中，否则射线可能先选中它们而非地面。

表格列出组件默认值，也注明了英雄场景中覆盖为 `TURN` 的值。在演示中，`SettingsApplier` 会在启动时将已保存的按住模式、光标隐藏、两种按键模式、环顾四周和保持瞄准设置应用到组件。复制 `playable_hero.tscn` 而不复制设置系统时，保留场景本身的值。

信号：`destination_picked(point)`、`hold_started`、`hold_pending_changed(pending)` 和 `run_requested`。后者表示玩家开始一段新的奔跑：点击新目标、按下变为按住，或配合右键按方向键开始行走。若点击的仍是当前目标，或方向键在按住操作结束后接着驱动，则不会发出。`playable_hero.tscn` 用它结束相机环绕后的等待（`CameraRig.end_follow_wait()`，见[相机](camera.md#跟随模式)）。

`cancel()` 会忘记正在进行的按下：尚未松开的短按不会跑向该点；由按住或配合右键按键驱动的奔跑会平稳停下（`FOLLOW_POINT` 模式也不会继续奔向最后的点）；隐藏的光标重新出现在瞄准处。一直按着的鼠标键须重新按下才算新的操作；配合右键的方向键每帧都读取，因此立即又可行走。已点击的目标属于移动器，奔跑会继续（`NavigationMover.halt()` 也能停下）。可操控的英雄在传送前或禁用操控时会调用此方法。

组件在启动时检查其输入动作是否存在，缺少时报告错误。之后不会再读取缺少的动作：对应按键不起作用，引擎也不再报错。即使缺少部分移动键，其余键仍可行走。`CharacterActionInput` 和相机支架也这样处理。

## CharacterActionInput

| 属性 | 默认值 | 含义 |
|---|---|---|
| `character` | — | 要下达命令的 `GroundCharacter` |
| `sprint_action` | `sprint` | Shift |
| `jump_action` | `jump` | 空格 |
| `sprint_mode` | `HOLD` | `HOLD`：按住按键时冲刺。`TOGGLE`：按一下开启冲刺，再按一下关闭；角色力竭时冲刺也会自动关闭，休息后不会自动恢复 |

该组件只负责传递输入；是否有足够的体力冲刺、当前能否跳跃，由角色决定。它在物理帧中先于角色运行（`process_physics_priority = -1`），因此按下和松开都能传到角色，不会多出一个物理帧的延迟。`is_sprint_toggled()` 返回 `TOGGLE` 模式下的状态。

### Shift 不会卡住

在 `HOLD` 模式下，每个物理帧都读取冲刺请求，因此正常松开 Shift 会立即结束冲刺。有时嵌入编辑器的“游戏”选项卡收不到松开事件，或事件被系统拦截。若 `sprint_action` 绑定的全部按键都是修饰键（Shift、Ctrl、Alt 或 Meta），`CharacterActionInput` 还会检查后续鼠标及键盘事件携带的修饰键状态，释放残留的冲刺按下状态。它读取当前绑定，因此运行时重新绑定也适用。若冲刺绑定的是非修饰键，则只能依靠常规动作状态。
