# Использование в своём проекте

[← Оглавление документации](index.md)

> Это перевод [английского оригинала](../en/integration.md). При расхождениях верен оригинал.

Если вам нужны движение и камера из демо в другом проекте, начните с готового героя. Отдельные компоненты подойдут,
если у вас уже есть контроллер персонажа или нужна только камера. Скрипты — обычные классы GDScript (`class_name`):
включать плагин редактора и добавлять автозагрузку `Settings` не требуется.

| Что вам нужно | С чего начать |
|---|---|
| Готовый герой с вводом и камерой | [Перенесите героя из демо](#перенос-героя-из-демо-в-свой-проект), затем [выберите конфигурацию](configurations.md) |
| Камера для существующего персонажа | [Только камера](#только-камера) |
| Движение проекта со своей моделью | [Готовое тело](#перемещение-по-щелчку-с-готовым-телом), затем [замена модели](systems/characters.md) |
| Движение по пути для своего контроллера или ИИ | [Своё тело](#своё-тело) и [управление контроллером перемещения](#управление-контроллером-перемещения) |

Пути далее заданы относительно корня проекта, где лежит `project.godot`. Путь с `res://` указывает на то же место
в Godot. Для первого рабочего переноса сохраните готовую структуру папок.

## Аддоны

| Аддон | Классы | Что нужно |
|---|---|---|
| `orbit_camera` | `OrbitCameraRig`, `CameraArm` | Действия ввода `camera_rotate`, `camera_zoom_in`, `camera_zoom_out`; физические слои для держателя камеры |
| `click_to_move` | `LocomotionSettings`, `GroundMotion`, `NavigationMover`, `PointClickMoveInput`, `ClickMarker`, `NavigationPathView` | Запечённый `NavigationRegion3D` в мире (без него персонаж бежит прямо к точке). Для ввода: любая `Camera3D` и действия `move_to_cursor`, `camera_rotate`, `move_forward`, `move_back`, `move_left`, `move_right` |
| `ground_character` | `GroundCharacter`, `FallSettings`, `LedgeGuard`, `Stamina`, `CharacterActionInput`, `CharacterSounds`, `HandSway`, `CharacterHover`, `DampedSpring`, `CharacterAppearance`, `StaminaBar` | `click_to_move`. Для клавиш: действия `sprint` и `jump`. Для звуков: свои или `shared/audio/character/`. Для покачивания руки и сменных моделей: модели, смотрящие в −Z, с узлом руки |
| `occluded_silhouette` | `OccludedSilhouette` с его шейдерами и материалами | Ничего: работает с любой моделью |
| `points_of_interest` | `PointOfInterest`, `DiscoveryToast` | Тело игрока в группе `player`, на физическом слое, который видят области |
| `ui_screens` | `UiRoot`, `UiScreen`, `FpsCounter`, `InputNames`, `ActionTexts` | Встроенное действие `ui_cancel`; действие `toggle_settings`, если `UiRoot` открывает окно по клавише. Названия клавиш берутся из вашей карты ввода |
| `levels` | `LevelHost`, `LevelPortal`, `SpawnPoint`, `LoadingScreen` | Только движок. Тело путешественника в группе `player` на физическом слое, который видят порталы |

В папке каждого аддона есть `README.md` с инструкцией по настройке и копия `LICENSE`. Берите аддон целиком: классы
внутри ссылаются друг на друга по типу, а неиспользуемый файл ничему не мешает. Держите папки в
`res://addons/iso_orbit/<addon>/`: сцены и материалы в них ссылаются на свои файлы по этим путям. Чтобы положить
аддон в другое место, переместите его в панели «Файловая система» (FileSystem) редактора — она обновит ссылки.

Виджеты HUD (`StaminaBar`, `DiscoveryToast`, `FpsCounter`) берут внешний вид из одноимённых вариаций типов в теме
демо, `shared/ui/ui_theme.tres`; без них используется тема по умолчанию.

Не вошли в аддоны, потому что построены вокруг демо: система настроек (`gdscript/settings/game_settings.gd` и окно
в `gdscript/ui/settings/`, см. [Настройки](#настройки)), `gdscript/ui/ui_root.tscn` (`UiRoot` с этим окном), игровой
герой (`gdscript/player/playable_hero.tscn`, собранный вокруг персонажа демо, см. [Игровой герой](#игровой-герой)),
приглашение к переходу (`gdscript/ui/travel_prompt.tscn`), оболочка игры `gdscript/main.gd` и связующий код
`gdscript/demo/hud.gd` и `settings_applier.gd`.

## Только камера

Камера работает с любой целью типа `Node3D`, и ей нужна только папка `addons/iso_orbit/orbit_camera/`.

1. Добавьте в сцену `Node3D` с `orbit_camera_rig.gd` рядом с целью, а не внутрь неё.
2. Добавьте ему дочерний `Node3D` с `camera_arm.gd`, а тому — дочернюю `Camera3D`.
3. Задайте `target` рига на движущееся тело, а `arm` — на узел держателя. Включите у камеры свойство **Current**.
   В `fade_target` держателя укажите корень модели, которая должна становиться полупрозрачной вблизи, либо оставьте
   поле пустым.
4. Добавьте действия ввода и, для держателя, физические слои со страницы [Настройка проекта](project-setup.md).

Сохраните масштаб рига, держателя, камеры и их предков `(1, 1, 1)`, а локальный трансформ камеры — исходным:
держатель задаёт его во время игры. Изменяйте вид свойствами кадрирования, а не масштабом узла.

Без держателя тоже можно — с `Camera3D` прямо в качестве дочернего узла рига камеры: тогда камера стоит на расстоянии,
заданном зумом, и проходит сквозь стены. Риг обновляется в `_process` по интерполированной позиции цели, поэтому,
если цель движется в физических тиках, включите в проекте интерполяцию физики. Подробнее: [Камера](systems/camera.md).

## Перемещение по щелчку с готовым телом

Скопируйте `addons/iso_orbit/click_to_move/` и `addons/iso_orbit/ground_character/`.

1. Запеките навигационную сетку для своего уровня (`NavigationRegion3D` →
   **Запечь NavigationMesh** (Bake NavigationMesh)). Её радиус агента и максимальная высота подъёма должны
   подходить вашему персонажу, см. [Мир и навигация](systems/world-and-navigation.md).
2. Создайте `CharacterBody3D` с `ground_character.gd`: форма столкновения, узел `Visual` с моделью (смотрит в −Z) и
   такие дочерние узлы: `NavigationMover` (`Node` с `navigation_mover.gd`), по желанию `LedgeGuard` и `Stamina`.
   Задайте у тела `mover`, `visual`, `ledge_guard` и `stamina`.
3. Дайте контроллеру перемещения ресурс `LocomotionSettings` или оставьте поле пустым, чтобы взять значения по
   умолчанию.
4. Добавьте в любое место сцены `Node` с `point_click_move_input.gd` и задайте его `mover` и `camera`.
5. По желанию добавьте `character_action_input.gd` с `character`, указывающим на тело, — для ускорения и прыжка.

`gdscript/player/player.tscn` — такая сборка со звуками, покачиванием руки, парением (`Visual/Hover` выключен,
падение замедлено), сменной моделью и силуэтом. Можно создать её экземпляр и убрать лишнее. Ошибки настройки
`GroundCharacter`, `LedgeGuard` и `CharacterHover` выводятся предупреждениями при запуске игры.

## Игровой герой

`gdscript/player/playable_hero.tscn` — готовый управляемый герой: `player.tscn` как `Character` (в группе `player`),
`PointClickMoveInput`, `CharacterActionInput`, риг камеры с держателем и камерой, маркер щелчка и линия пути со всеми
настройками и соединениями. Добавьте его в игровую сцену один раз, рядом с уровнями, а не внутрь уровня. Скрипт
`playable_hero.gd` использует только классы из аддонов:

- `place_at(marker)` и `teleport(position, facing)` сразу переносят героя: текущий нажим сбрасывается, персонаж
  оказывается на месте без рывка (`GroundCharacter.teleport()`), камера смотрит по направлению героя и мгновенно
  становится на место. Если `turn_camera` равен false, угол камеры сохраняется, как в начале демо.
- `controls_enabled = false` отключает ввод движения, ускорения и прыжка. Камерой по-прежнему можно управлять, а
  движение к уже выбранной щелчком точке продолжится. Дополнительно вызовите `character.mover.stop()` для плавного
  торможения или `halt()` для мгновенной остановки горизонтального движения. Пауза дерева сцены — отдельная операция.
- Части доступны как типизированные свойства: `character`, `input`, `actions`, `camera_rig`, `camera_arm`, `camera`,
  `click_marker`, `path_view`, а также `sounds`, `appearance`, `hover` и `silhouette` персонажа.

Для своей модели сделайте копию сцены и замените в ней `player.tscn` своим персонажем либо соберите узлы вручную.
Для камеры важны два соединения: `PointClickMoveInput.hold_pending_changed` → `OrbitCameraRig.set_follow_paused` и
`PointClickMoveInput.run_requested` → `OrbitCameraRig.end_follow_wait` (после ручного вращения камера ждёт нового
забега). Ещё четыре соединения показывают и скрывают маркер щелчка; см.
[Архитектура](architecture.md#соединения-в-сцене). Держите `sharp_turn_speed` камеры не выше половины скорости
поворота персонажа: это проверяет и сообщает предупреждением только `PlayableHero`.

## Перенос героя из демо в свой проект

Для повторения проверенной конфигурации демо используйте Godot 4.7.2, Jolt Physics и Forward+. Начните с небольшого
тестового уровня; собственные модели, уровни и настройки добавляйте после проверки скопированного героя.

1. **Скопируйте файлы, сохранив пути.** Перенесите в свой проект следующие папки и файлы:
   - `addons/iso_orbit/click_to_move/`, `ground_character/`, `orbit_camera/` и `occluded_silhouette/`;
   - `gdscript/player/`: герой, персонаж, скрипт героя и ресурсы настроек персонажа;
   - `shared/characters/`: десять моделей, их посохи и книги, материалы;
   - `shared/audio/character/`: шаги, прыжок, приземление и ускорение;
   - `shared/world/materials/wood.tres` и `dark_wood.tres`: из них сделаны деревянные части друида и боевого мага.
     Эти ресурсы лежат среди материалов мира, поэтому одного `shared/characters/` недостаточно.

   Скопируйте также соседние файлы `.uid` и `.import`: сцены находят скрипты и звуки по этим идентификаторам и
   путям. Папку `.godot/` оставьте: ваш редактор сам импортирует файлы. Чтобы хранить ресурсы в других местах,
   сначала скопируйте их, а затем переместите в панели FileSystem редактора — она обновит ссылки в сценах.
2. **Настройте проект** в Project Settings; подробнее — [Настройка проекта](project-setup.md):
   - действия ввода `move_to_cursor`, `camera_rotate`, `camera_zoom_in`, `camera_zoom_out`, `move_forward`,
     `move_back`, `move_left`, `move_right`, `sprint` и `jump`. Если действие отсутствует, использующий его компонент
     один раз сообщит об этом при запуске, а соответствующая клавиша или кнопка не сработает;
   - `navigation/3d/default_cell_height` = 0.025, чтобы соответствовать навигационной сетке следующего шага.
     Карта навигации и все назначенные ей сетки должны использовать одинаковые размеры ячеек;
   - включите интерполяцию физики (`physics/common/physics_interpolation`): камера следует за интерполированной
     позицией персонажа. Герой проверен с Jolt Physics (`physics/3d/physics_engine`);
   - физические слои: тело героя находится на слое 2 и сталкивается со слоями 1 и 4, луч щелчка ищет землю на
     слое 1, держатель камеры останавливается на слоях 1 и 3. Названия не важны, важны номера: поместите землю
     и стены на слой 1 либо измените эти маски в копии сцены.
3. **Постройте тестовый уровень** под `NavigationRegion3D`. Земля — `StaticBody3D` с `BoxShape3D` и видимым
   `BoxMesh`, оба размером 20 × 1 × 20 м и с центром в `(0, -0.5, 0)`, так что поверхность находится на Y = 0.
   Добавьте препятствие-куб 2 × 2 × 2 м с центром в `(0, 1, -4)`, соответствующей сеткой и коллизией на слое 1.
   Оно перекроет прямой путь от Spawn `(0, 0, 4)` к `(0, 0, -8)`. Добавьте свет и, по желанию, ступень
   3 × 0,2 × 3 м с центром в `(5, 0.1, 0)`. Одна лишь видимая сетка не создаёт коллизию.
4. **Создайте и запеките навигационную сетку.** Выберите регион, назначьте новый `NavigationMesh` и задайте:

   | Свойство | Значение тестового уровня | Зачем |
   |---|---|---|
   | Parsed Geometry Type | Static Colliders | Запекать геометрию, которая блокирует тело |
   | Geometry Collision Mask | слой 1 | Включить пол и препятствие, исключить героя |
   | Agent Radius | 0,5 м | Зазор вокруг капсулы радиусом 0,35 м |
   | Agent Height | 1,8 м | Не меньше полной высоты капсулы; проверьте самый низкий потолок |
   | `filter_walkable_low_height_spans` | `true` | Исключить участки с высотой прохода меньше Agent Height |
   | Agent Max Climb | 0,3 м | Совпадает с `Character.max_step_height` |
   | Agent Max Slope | 40° | Меньше предельного уклона пола тела — 45° |
   | Cell Height / Cell Size | 0,025 м / 0,25 м | Мелкие вертикальные шаги; согласуйте с настройками карты навигации |

   Держите пол и препятствие **под регионом**, затем нажмите **Bake NavigationMesh** и сохраните сцену. Сетки демо
   используют высоту агента 1,75 м и оставляют фильтр низких проходов выключенным. Для нового уровня с потолками
   используйте полную высоту коллайдера и включите фильтр. Навигация не заменяет физические столкновения. Если
   пригодного пути нет, контроллер может перейти к движению прямо к цели и тогда не обойдёт стену. Подробнее:
   [Мир и навигация](systems/world-and-navigation.md#физические-слои-и-навигация).
5. **Добавьте героя экземпляром рядом с регионом** под именем `Hero`. Добавьте `Marker3D` с именем `Spawn` в
   `(0, 0, 4)`. Сохраните масштаб корня героя `(1, 1, 1)` и активную камеру. Достаточно такой сцены:

   ```text
   Game (Node3D)
   ├── NavigationRegion3D
   │   ├── Ground (StaticBody3D с формой столкновения и видимой сеткой)
   │   └── Obstacle (StaticBody3D с формой столкновения и видимой сеткой)
   ├── Hero (экземпляр playable_hero.tscn)
   ├── Spawn (Marker3D)
   └── DirectionalLight3D
   ```

   Прикрепите к `Game` этот скрипт и запустите сцену:

   ```gdscript
   extends Node3D

   @onready var hero: PlayableHero = $Hero


   func _ready() -> void:
       hero.place_at($Spawn, false)
   ```

   `false` сохраняет исходный поворот камеры на 45°; без него камера встанет за направлением −Z маркера.
   После запуска переносите **персонажа через API героя**. Корень `Hero` — неподвижный контейнер и не следует за
   движущимся телом. Текущую позицию игрока берите из `hero.character.global_position`.
6. **Проверьте результат до настройки под себя.** Щёлкните по земле возле `(0, 0, -8)`, за препятствием: герой
   должен обойти его и остановиться. При необходимости отдалите камеру, чтобы увидеть цель. Удерживайте левую
   кнопку мыши: герой должен двигаться напрямую и остановиться после отпускания. Проверьте вращение правой кнопкой,
   зум колесом, правую кнопку с WASD, Shift и Space. С готовым ресурсом движения обычная скорость — 5,5 м/с,
   скорость при ускоренном беге — 8,25 м/с, высота прыжка — 1 м, а ступень в 0,2 м проходится без прыжка.
   Проверьте отладчик на отсутствие предупреждений о действиях ввода, ресурсах и настройке.

Скопированная сцена работает как демо по умолчанию и без системы настроек: оба режима клавиш — `TURN`, следование
камеры, выравнивание наклона и высоты, парение и звуки ускорения выключены. Начальная модель — некромант.
Точные пути к узлам, виды значений по умолчанию и два других варианта описаны в
[Конфигурациях](configurations.md).

### Если перенос не заработал

| Симптом | Что проверить первым |
|---|---|
| Не найден глобальный класс или ресурс | Скопированы ли все четыре папки аддонов и перечисленные ресурсы по исходным путям; закончил ли редактор импорт. Нужны оба материала дерева |
| Герой проваливается сквозь пол | У пола должна быть форма коллизии на слое 1; один MeshInstance3D только рисуется |
| Щелчки ничего не делают | Действие InputMap, активная камера, `PlayerInput.camera` и `ground_mask` луча; наложенный Control может поглощать ввод мыши |
| Герой идёт в стену, а не вокруг неё | Запеките коллайдеры под регионом, проверьте навигационные слои региона и контроллера, осмотрите полученную сетку |
| Путь пересекает слишком высокую ступень | Согласуйте подъём с `max_step_height`, уменьшите вертикальную ячейку и заново запеките; проверьте реальную геометрию |
| Изменения сцены исчезают при запуске | Скопированный `SettingsApplier` может перезаписать их сохранёнными настройками; отдельному герою он не нужен |
| Камера неожиданно поворачивается после правки движения | Сравните `turn_speed` персонажа и `sharp_turn_speed` камеры; см. [Конфигурации](configurations.md#настройка-без-нарушения-работы-варианта) |

Также учитывайте:

- Аддоны и `playable_hero.gd` объявляют глобальные классы (`GroundCharacter`, `NavigationMover`, `OrbitCameraRig`,
  `PlayableHero` и другие из [таблицы выше](#аддоны)). Если в вашем проекте уже есть класс с таким именем,
  переименуйте один из них.
- Изменяя `turn_speed` в `LocomotionSettings`, держите `CameraRig.sharp_turn_speed` не выше половины этой скорости.
  Иначе камера может принять разворот на месте за боковой бег и повернуться. Если порог не ниже скорости поворота,
  герой выдаст предупреждение при запуске.
- Автозагрузка `Settings` и окно настроек не требуются. HUD не входит в состав героя: шкала выносливости и
  уведомление о месте добавляются в `main.tscn` демо; о теме для них см. [Аддоны](#аддоны).
- Модели и звуки, как и код, распространяются по лицензии MIT этого проекта.

## Уровни

Скопируйте `addons/iso_orbit/levels/`. Главная сцена содержит `LevelHost` с начальным уровнем как единственным
дочерним узлом, героя рядом с ним и `loading_screen.tscn`. Главный скрипт соединяет сигналы хоста: при
`level_change_started` отключает управление, при `level_loaded(level, spawn)` ставит героя на `spawn`, при
`level_change_finished` возвращает управление, при `level_change_failed` тоже возвращает его (уровень остаётся,
а `level_change_finished` не приходит); `portal_entered` и `portal_exited` показывают и скрывают приглашение к
переходу. Так работает `gdscript/main.gd`. Каждому уровню нужен `SpawnPoint` с именем `default`; порталы — это
области `LevelPortal` с путём к целевой сцене.

При своей системе уровней возьмите только игрового героя и вызовите `place_at()`, когда уровень готов. Для своего
персонажа тот же эффект даёт `GroundCharacter.teleport()`. Подробности, значения по умолчанию и совместимые
настройки: [Уровни](systems/levels.md).

## Своё тело

Чтобы оставить свой контроллер персонажа, возьмите только `addons/iso_orbit/click_to_move/`. Контракт короткий:

- `NavigationMover` должен быть прямым потомком тела (любого `Node3D`). Он читает позицию тела и навигационную карту
  мира, в котором находится тело.
- Тело вызывает `mover.compute_velocity(delta)` раз в физический тик, до `move_and_slide()`, и применяет X и Z
  результата. Контроллер перемещения никогда не двигает тело.
- Вертикальная скорость остаётся за телом: гравитация, прыжки, отбрасывание.

```gdscript
extends CharacterBody3D

@onready var mover: NavigationMover = $NavigationMover


func _physics_process(delta: float) -> void:
	var planar := mover.compute_velocity(delta)
	velocity.x = planar.x
	velocity.z = planar.z
	if not is_on_floor():
		velocity += get_gravity() * delta
	move_and_slide()
```

Такому минимальному телу нужны собственная форма коллизии, пол и камера, чтобы его видеть; добавьте модель под
узлом `Visual`. Для поворота по ходу движения направляйте −Z этого узла вдоль `mover.get_facing()` в мировых
координатах. `GroundCharacter` уже обрабатывает поворот модели, в том числе при повёрнутом родителе, если вам не
нужна собственная реализация тела.

`LedgeGuard` необязателен и требует `addons/iso_orbit/ground_character/`: добавьте его дочерним узлом тела и
применяйте `velocity = ledge_guard.constrain(velocity, delta)` перед `move_and_slide()`. Для ускорения задайте
`mover.sprinting = true`: предел скорости вырастет в `LocomotionSettings.sprint_speed_multiplier` раз. Всё остальное,
что есть в `GroundCharacter` (прыжок, запас сил, ступени, состояние и его сигналы, плавный поворот модели), тогда
остаётся на вас.

## Управление контроллером перемещения

Персонажем может управлять что угодно: ввод игрока, ИИ, катсцена или сетевой код.

| Вызов | Эффект |
|---|---|
| `move_to(point)` | Следовать по навигационному пути к глобальной точке. Недоступная цель может завершиться на ближайшей доступной точке пути; пустой путь ведёт к прямому движению. Цель ближе `retarget_tolerance` (0,1 м) к текущей не перестраивает путь |
| `steer(direction, facing = Vector3.ZERO)` | Бежать в направлении без пути, пока не будет другой команды; с `facing` — смотреть в ту сторону во время движения (боком) |
| `stop()` | Плавно затормозить там, где персонаж находится |
| `halt()` | Остановиться мгновенно, например после телепорта |
| `face(direction)` | Сразу повернуть стоящего персонажа, например на точке появления |

Чтобы перенести всего персонажа, вызовите `GroundCharacter.teleport(position, facing)`: он останавливает контроллер,
поворачивает персонажа и его модель и перемещает тело без рывка для следующих за ним объектов.

Сигналы: `destination_changed(point)`, `path_changed`, `arrived`, `destination_cancelled` (от точки отказались ради
`steer()` или `stop()`). Запросы: `is_moving()`, `is_steering()`, `has_destination()`, `get_destination()`,
`get_speed()`, `get_heading()`, `get_facing()`, `get_remaining_path()`. Подробнее:
[Передвижение](systems/locomotion.md).

## NPC

Создайте экземпляр `player.tscn` (или своей сцены тела с контроллером перемещения) и удалите узлы `Silhouette` и
`Appearance`, нужные только игроку. Узлы ввода не добавляйте: вызывайте `NavigationMover.move_to()` из своего ИИ и
слушайте `arrived`. Чтобы взять одну из моделей персонажей демо, поместите её под `Visual/Hover` с именем `Model`.
Поворот NPC в редакторе задаёт его начальное направление; позже его меняют
`GroundCharacter.teleport(position, facing)` или `NavigationMover.face()`. NPC на уровне демо — статичные тела,
а не персонажи; см. [Мир и навигация](systems/world-and-navigation.md).

## Настройки

Компоненты никогда не читают настройки: каждый читает собственные экспортируемые свойства. Чтобы вынести их в своё
меню настроек, задавайте свойства из своего кода при изменении настройки. Пример — `gdscript/demo/settings_applier.gd`:
один `match` сопоставляет каждый ключ настроек свойству узла. Чтобы заодно взять систему настроек демо, скопируйте
`gdscript/settings/game_settings.gd`, зарегистрируйте его как автозагрузку `Settings`, замените его ключи и `DEFAULTS`
своими и возьмите элементы управления из `gdscript/ui/settings/`; см. [Интерфейс](systems/ui.md#настройки).
