# テスト

> これは[英語の原文](../en/testing.md)の翻訳です。内容が異なる場合は、英語版が正しいものとします。

テストは、実際の入力イベントと実際の物理を使ってメインシーンをヘッドレスで実行し、測定値を期待値と比較します。

```bash
godot --headless --fixed-fps 60 --path . --script res://tests/run_checks.gd
```

ここで`godot`はGodot 4.7.2の実行ファイルです。Windowsでは`_console.exe`版を使ってください。通常版はターミナルから切り離されるため、出力が表示されず、終了コードも得られません。クローンしたばかりの場合は、先にエディターで、または`godot --headless --path . --import`で、プロジェクトを一度インポートしてください。

一部のスイートだけを実行するには（たとえばカメラの作業中など）、`--`の後に名前の一部を付けます。

```bash
godot --headless --fixed-fps 60 --path . --script res://tests/run_checks.gd -- camera input
```

いずれかのチェックが失敗すると、終了コードは1になります。最後に、ランナーが各スイートで成功・失敗したチェックの数を表示します。

## テストの振る舞い

- テストはデフォルト設定で実行され、何も保存しません。プレイヤーの設定は実行中だけデフォルトに戻され、上書きされることはありません。
- 各チェックは変更したものを元に戻します。スイートは1つのメインシーン上で順番に実行されますが、単独で実行したスイートには新しいメインシーンが用意されます。チェックはどちらの場合でも成功しなければなりません。
- エンジンやスクリプトのエラーも、1つでもあれば実行全体が失敗になります。`OS.add_logger()`で追加した`Logger`がそれらを数え、ランナーがその数を「engine and script errors」として表示して失敗数に加えます。クラッシュしたチェックは途中で打ち切られますが、ほかのチェックは続行されるので、このカウンターがなければクラッシュに気付かないままになってしまいます。CPU負荷が高いと、Jolt自体が警告を出すことがあります。[既知の問題](known-issues.md#テスト)を参照してください。
- ハングした実行は、ゲーム時間で600秒後に失敗になります。
- 終了前に、ランナーはメインシーンを削除して0.1秒待ちます。`--fixed-fps`ではゲーム時間が実時間より速く進む一方、オーディオは実時間で再生されるので、終了直前に再生された足音はまだ鳴っています。すぐに終了すると、エンジンが`AudioStreamPlayback`オブジェクトと足音リソースのリークを報告することがあります。
- ヘッドレスのウィンドウはシステムカーソルを動かせないので、テストで確認できるのは走る方向だけです。カーソル自体はゲーム内で確認します。また、ヘッドレスのウィンドウはマウスモードも変えないので（`Input.mouse_mode`は常に`VISIBLE`）、カーソルが隠れているかどうかは、テストでは`PointClickMoveInput.is_cursor_hidden()`を読んで確認します。
- 判定の上限・下限は可能な限りコンポーネントの設定から計算されるので、`LocomotionSettings`を調整しただけでテストが壊れることはありません。

## チェックの書き方

新しいチェックは、適切なスイートに`_check_…`関数を追加し、そのスイートの`_checks()`に1行加えて作ります。新しいスイートは、`check_suite.gd`を継承する`tests/<topic>_checks.gd`ファイルを作り、`SUITES`に1行加えます。`check_suite.gd`には共通のヘルパーがあります。

| ヘルパー | 処理 |
|---|---|
| `_teleport(position)` | プレイヤーを停止状態で地点に置き、数ティック待つ |
| `_run_until_arrived(target, max_time)` | 走行を命じ、到着まで時間、速度、歩いた距離、引っかかったティック数を記録する |
| `_check_route(title, from, to, max_time)` | ルート：時間内に引っかからずに到着し、到達可能な地点ならその地点ちょうどに、正しい階の床の上で到着する |
| `_ticks(count)`、`_frames(count)`、`_wait_until(condition, max_ticks)` | 待機 |
| `_send_key()`、`_send_button()`、`_send_motion()` | 実際の入力イベント |
| `_expect(condition, what)` | チェックの成功または失敗を数えて表示する |
| `_median()`、`_min()`、`_max()`、`_first_time_at_most()` | 記録した値の統計 |

`Settings`自動読み込み（Autoload）にアクセスするクラス（設定ウィンドウのコントロール）を、テストスクリプト内で型として名指ししないでください。テストスクリプトは自動読み込みの名前が存在する前にコンパイルされるため、そうしたクラスはコンパイルに失敗し、その実行ではゲーム全体が壊れます。設定ノードは`_tree.root.get_node(^"Settings")`で取得し、ダックタイピングを使ってください。
