# テスト

[← ドキュメント目次](index.md)

> これは[英語の原文](../en/testing.md)の翻訳です。内容が異なる場合は、英語版を参照してください。

テストは実際の入力イベントと物理処理を使い、メインシーンをヘッドレスで動かして測定値を期待値と比較します。

```bash
godot --headless --fixed-fps 60 --path . --script res://tests/run_checks.gd
```

ここで`godot`は手元のGodot 4.7.2実行ファイルです。Windowsでは`_console.exe`版を使います。通常版はターミナルから切り離され、出力と終了コードが得られません。新しいクローンでは先にエディター、または`godot --headless --path . --import`で一度インポートします。

実行ファイルをPATHへ追加せず、フルパスで呼ぶこともできます。PowerShellで引用符付きパスを実行するには`&`が必要です。

```powershell
& 'C:\path\to\Godot_console.exe' --headless --fixed-fps 60 --path . --script res://tests/run_checks.gd
```

例のパスをインストール済みGodot 4.7.2のコンソール版へ置き換え、このプロジェクトのルートから実行します。

カメラの作業中など、一部のスイートだけなら`--`の後に名前の一部を指定します。

```bash
godot --headless --fixed-fps 60 --path . --script res://tests/run_checks.gd -- camera input
```

チェックが1つでも失敗すると終了コードは1です。最後にランナーがスイートごとの成功・失敗数を表示します。

## スイート

スイートは`tests/run_checks.gd`の順に1つのメインシーンを共有して実行します。変更に関係するものを選び、システムをまたぐ変更の組み込み前には全体を実行します。

| スイート | 主な検査 |
|---|---|
| `movement_checks.gd` | 加速、減速、目標変更、旋回、到達できる／できない地点、障害物の迂回経路、スロープ、崖 |
| `world_checks.gd` | デモ地形上のナビゲーション、発見エリア、場所にいるキャラクターとの衝突、ヒーロー用の展示モデル |
| `hero_look_checks.gd` | 10種類のヒーローモデルの切り替え、装備の位置、シルエット、手の動き |
| `character_actions_checks.gd` | ダッシュと疲労、押し続ける／切り替える入力、キー変更と修飾キーの解除、ジャンプバッファとコヨーテタイム、落下設定の上書き、キャラクターのシグナルと音 |
| `character_state_checks.gd` | 設定警告、状態とアニメーション用データ、階段・斜面、テレポート、浮遊、補間、時間停止、状態パネル |
| `input_checks.gd` | クリックと長押し、両ボタンの順序、2つの長押しモード、キーモード、カーソルの捕捉、取消し、欠けたアクション |
| `camera_checks.gd` | フレーム／ティックレートごとのオービット、ズーム、追従、急旋回、カメラへ向かう走行、手動オービット後の待機、追従を中断しないクリック、傾き・ズーム・高さの調整、テレポート |
| `camera_arm_checks.gd` | 障害物との余裕、衝突レイヤー、無視するグループ、任意の遮蔽時引き寄せ、近距離フェード |
| `settings_window_checks.gd` | 一時停止とフォーカス、各設定タブ、プロパティへの反映、依存する項目、UIスケール、リセットと閉じる操作 |
| `localization_checks.gd` | 翻訳の網羅、アクショントークンの保持、言語変更、12個のキー変更可能なアクションの名前、開いたツールチップ・ウィンドウ・ローディングヒント、翻訳の継承 |
| `level_checks.gd` | スポーン地点、移動案内、読み込み進捗と一時停止、シーン入れ替え、ヒーロー状態の維持、失敗後の復旧 |
| `patrol_checks.gd` | 自分のルートに描かれた線に沿い、そのすべてのポイントを通り、なめらかに曲がる騎士の巡回、持ち場での待機と次の周回。ヒーローの前での停止と2.5 s後のセリフ。前方1メートル以内とわずかに左右にいるキャラクターだけが巡回を止めること。島のレンジャーとその停止。回転したカーブ、閉じたカーブ、スクリプトからのルート。Bake Intervalが長い場合と短い場合に、ルートの点が描かれた線の上にあること、制御点での停止。欠けた参照 |
| `editor_authoring_checks.gd` | ムーバー間で共有され、実行中に交換される移動設定リソース。設定ファイルのパス、シーンの値より優先される保存済み設定、`use_saved_settings`がオフのときに保たれるシーンの値。開始レベル。設定警告。一体として扱われる小道具（移動、`dimensions`とその0、スケールしたルートノード、Surface Material、追加した部品、モデル、アニメーションする部品）。カメラへ向かう走行を除外するスイッチとその角度 |

記載された入力・カメラ構成には、まず`movement`、`character_actions`、`input`、`camera`、`settings_window`を実行します。フィルター`camera`はカメラ関連の両スイートを選びます。別のプロジェクトへヒーローをコピーする場合は[移植チェックリスト](integration.md#デモのヒーローを自分のプロジェクトへ移植する)にも従ってください。このリポジトリのテスト成功だけでは、必要なファイルとプロジェクト設定が移植されたとはいえません。

## テストの振る舞い

- テストはデフォルト設定で動き、プレイヤーの設定には触れません。設定は実行中だけデフォルトへ戻り、保存されません。設定ファイルを読む唯一のチェックは、独自のファイルを`.godot/`に書き込み、後で削除します。
- 巡回するキャラクターは、`patrol_checks.gd`以外のすべてのスイートで立ち止まっています。このスイートだけは自分でそれらを動かします。歩き回る騎士がほかのチェックの邪魔になるからです。
- 各チェックは変更したものを戻します。スイートは1つのメインシーンで順番に動き、単独実行では新しいシーンを使います。どちらでも成功しなければなりません。各チェック後、`Engine.time_scale`を1へ戻します。時間停止・減速中にクラッシュしても次のチェックへ影響させないためです。
- エンジンとスクリプトのエラーや警告も失敗になります。`OS.add_logger()`で追加した`Logger`が数を記録し、ランナーが「engine and script errors」として失敗数に加えます。クラッシュしたチェックは途中で終わってもほかのチェックは続くため、カウンターがなければ見逃します。意図的に起こすエラーだけは、事前にランナーの`expect_error()`で宣言し、`take_expected_errors()`で発生を確かめれば数えません。レベルにできないシーンの検査が例です。高いCPU負荷でJolt自身が警告することもあります。[既知の問題](known-issues.md#テスト)を参照してください。
- ハングした実行はゲーム時間1200 sで失敗します。バックグラウンド読み込み中、ウィンドウのない描画は画面表示より速く進み、ゲーム時間も早く進むため、レベル検査は実時間で切り替えを待ちます。
- 終了前にランナーはメインシーンを解放し、0.1 s待ちます。`--fixed-fps`ではゲーム時間が実時間より速く進む一方、音は実時間で再生されるため、終了直前の足音がまだ鳴っている場合があります。すぐ終了すると`AudioStreamPlayback`などのリークをエンジンが報告することがあります。
- ヘッドレスウィンドウはシステムカーソルを動かせないため、テストは走行方向だけを見て、カーソル自体はゲーム内で確認します。マウスモードも変わらず（`Input.mouse_mode`は常に`VISIBLE`）、隠れたカーソルは`PointClickMoveInput.is_cursor_hidden()`で調べます。
- 判定の範囲は可能な限りコンポーネント設定から計算するため、`LocomotionSettings`の調整だけではテストは壊れません。

## エディターでのチェック

`tests/run_checks.gd`はゲームを動かします。コンポーネントのエディター側の部分はエディター内でしか動かないため、専用のチェックがあります。エディターで`tests/editor_tool_checks.tscn`を開き、インスペクターで**Run Checks**を押してください。これらはゲームでは確かめられないことを扱います。シーンの編集中に警告が更新されること（依存するノード、リソース、巡回するキャラクターのボディに追加した、または取り除いたムーバー）、カメラ、小道具、巡回するキャラクター、ポータルの看板がエディターでプレビューを表示しつつ、保存したシーンには設定した内容が残ること、継承した小道具が基のシーンに追従し続けること、入力マップにエディター自身のアクションしかないエディター内でも、プロジェクトの入力アクションが認識されること、ゲームのスイッチ（浮遊、巡回）がエディターでは何も変えないこと、コピーした巡回するキャラクターがモデルを1つだけ表示すること、`@tool`なしで`CameraArm`を継承するスクリプトを持つカメラアームでも開始時の視点が表示されることです。インスペクターの**Status**と**Results**に結果が表示され、これらはシーンと一緒には保存されません。結果は`.godot/editor_tool_checks/results.json`にも書かれ、出力にはステータス行が出ます。チェックがシーンを書き込むのは`.godot/editor_tool_checks/`だけで、このフォルダは実行のたびに空になります。

## チェックの書き方

新しいチェックは適切なスイートへ`_check_…`関数と、その`_checks()`の1行を追加します。新しいスイートは`check_suite.gd`を継承する`tests/<topic>_checks.gd`を作り、`SUITES`へ1行加えます。共通ヘルパーは`check_suite.gd`にあり、次のとおりです。

| ヘルパー | 役割 |
|---|---|
| `_teleport(position)` | プレイヤーを停止して地点へ置き、数ティック待つ |
| `_run_until_arrived(target, max_time)` | 走行を命じ、到着までの時間、速度、距離、引っかかったティックを記録する |
| `_check_route(title, from, to, max_time)` | 時間内に引っかからず到着し、到達可能なら指定地点の正しい床に正確に着くか調べる |
| `_ticks(count)`、`_frames(count)`、`_wait_until(condition, max_ticks)` | 待機 |
| `_send_key()`、`_send_button()`、`_send_motion()` | 実際の入力イベント |
| `_expect(condition, what)` | 成功・失敗を数えて表示する |
| `_error_count()` | 予期したエラーを除く、これまでのエンジン・スクリプトエラー数。処理前後を比較する |
| `_tree.call(&"expect_error", "part of the message")`、`_tree.call(&"take_expected_errors")` | `check_suite.gd`ではなくランナーのメソッド。前者は意図的なエラーを事前に伝え、後者はまだ発生していない宣言済みエラーを返して待機を終える |
| `_find_non_finite(found)` | トランスフォームが有限でない（INFまたはNaN）メインシーン内の3Dノードを集める |
| `_same_values(a, b)` | 2配列の値が同じか。`==`と違いNaNを同じNaNとはみなさない |
| `_median()`、`_min()`、`_max()`、`_first_time_at_most()` | 記録値の統計 |

`Settings`自動読み込みにアクセスするクラス（設定ウィンドウのコントロール）をテストスクリプトの型として指定しないでください。テストは自動読み込み名が存在する前にコンパイルされるため、クラスの解決に失敗するとその実行全体が壊れます。設定ノードは`_tree.root.get_node(^"Settings")`で取得し、ダックタイピングで扱います。
