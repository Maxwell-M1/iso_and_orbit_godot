# 入力

> これは[英語の原文](../../en/systems/input.md)の翻訳です。内容が異なる場合は、英語版が正しいものとします。

2つのノードがプレイヤーの入力をコマンドに変換します。どちらも自身では何も動かしません。

- `PointClickMoveInput`：マウスと、右ボタンを押しながらのWASD → `NavigationMover.move_to()`、`steer()`、`stop()`。
- `CharacterActionInput`：ダッシュとジャンプのキー → `GroundCharacter.sprint_requested`と`jump()`。

どちらもキャラクターのシーンではなく`main.tscn`にあるので、同じキャラクターを代わりにAIで動かせます。プレイヤーから見た操作方法は[操作方法](../controls.md)を参照してください。

## PointClickMoveInput

| 入力 | コマンド |
|---|---|
| 地面をクリック | `move_to(point)`：カメラから`ground_mask`に対して飛ばしたレイが地点を見つける |
| 左ボタンを長押し | `hold_mode`に応じて、カーソルへの`steer()`か、カーソル下の地点への`move_to()` |
| 左右のボタンを長押し | カメラの向きへ`steer()`。AとDで斜め前へ曲がる（`keys_with_camera_steer`） |
| 右ボタンとWASD | カメラ基準で、横移動または旋回しながら`steer()`（`keys_with_camera`）。離すと`stop()` |

あるティックで誰がキャラクターを動かすかは、`_physics_process`の1か所で決まります。押されている左ボタンが優先され、そうでなければ右ボタンと組み合わせたキーです。そのため、右ボタンとWを押したまま左ボタンを離してもキャラクターは止まらず、すぐにキーが操作を引き継ぎます。

### クリックと長押し

押下は`hold_delay`（0.2秒）後に長押しになります。それまでキャラクターはそれまでの動作を続け（立ったまま、または走っていた方向へ走り続ける）、押した地点へのマーカーも経路もありません。

- **それより早く離した場合：クリック**。キャラクターはボタンを押した地点まで経路に沿って走ります。地点は押した瞬間に決まり、その後マウスが動いても変わりません。マーカーが表示されます（`destination_picked`）。マーカーは、キャラクターが到着するか、キーや長押しのために走行が放棄されると消えていきます。
- **それより長く押した場合：長押し**。キャラクターはすぐにカーソルを追って走り（`hold_started`）、先に押した地点の方を向くことはありません。そうしないと、その地点への経路を進み始めてしまい、障害物を迂回する経路はカーソルとはまったく別の場所へ向かうことがあるからです。

その代償として、クリックはボタンを離したときに作用し、押したときより約0.1秒遅れます。押下がクリックか長押しか不明な間は、`hold_pending_changed(true)`がカメラの追従モードを一時停止するので、短いクリックでカメラが動くことはありません。

左ボタンを押したときにすでに右ボタンが押されていれば、クリックにはなりません。キャラクターはすぐにカメラの向きに従って走ります。

### 長押しモード

`hold_mode`（設定 → 操作 → **左ボタン長押し**）：

- `STEER`（デフォルト）：経路なしで、カーソルに向かってまっすぐ進みます。キャラクターは障害物に沿って滑り、スロープのどこを指しても駆け上がります。キャラクターから`steer_dead_zone`（0.5 m）以内では方向が変わりません。これほど近いと、カーソルに対して敏感すぎるからです。ボタンを離すと、キャラクターは滑らかに止まります。
- `FOLLOW_POINT`：ナビゲーション経路に沿って、カーソル下の地点へ進みます。地点が動く間は経路が再構築されるので、高低差の近く（スロープ、プラットフォーム）では、あるルートから別のルートへ切り替わることがあります。ボタンを離すと、キャラクターは最後の地点まで走り続け、マーカーがその地点を示します（`destination_picked`）。`stop_on_release`がオンなら、その場で減速して止まります。

### 右ボタンと組み合わせるキー

キーは右ボタンを押している間だけ機能します。このときカメラはマウスで回転し、カーソルはキャプチャされています。右ボタンなしではWASDは何もしません。各モードは`OFF`か2つのバリエーションのいずれかで、右ボタンのみ（`keys_with_camera`）と両ボタン（`keys_with_camera_steer`）で別々に設定します。

| | `SIDESTEP` | `TURN` |
|---|---|---|
| 右ボタン + W | 前方、カメラの向きへ | 同じ |
| 右ボタン + A / D | 前を向いたまま横へ | 左 / 右へ向きを変えてその方向へ進む |
| 右ボタン + S | 前を向いたまま後ろへ、遅め | 振り返ってカメラの方へ歩く |
| 2つのキー（W + A、S + D…） | 前を向いたまま斜めに | 進む方向を向いて斜めに |
| 左右ボタン + A / D | 前を向いたまま斜め前へ | 進む方向を向いて斜め前へ |

スクリプトのデフォルトはどちらも`SIDESTEP`で、デモの設定のデフォルトはどちらも`TURN`です。

斜め移動は直進と同じ速さです。後退は遅くなります。`NavigationMover`は、移動方向が向きとどれだけ逆向きかに応じて速度を縮めます。[ロコモーション](locomotion.md#navigationmover)を参照してください。向きは`steer(direction, facing)`の第2引数として渡され、横移動のときはカメラの前方向です。停止後もキャラクターはそれまでの向きを保ちます。クリックや長押しをすると、再び走る方向を向きます。

キーか右ボタンを離すと、キャラクターは滑らかに止まります。キーを押さずに右ボタンだけを押しても、クリックした地点への走行は中断されないので、走りながらカメラを回せます。キーを押すと走行は中断され、マーカーが消えていきます。キーはアクション`move_forward`、`move_back`、`move_left`、`move_right`で、物理的な位置で割り当てられています。

### ボタン長押し中のカーソル

**非表示**（`hide_cursor_while_held`、デフォルトでオン）。走行中のカーソルはちらつくだけです。カメラが回転してカーソルが世界と一緒に動く間は特にそうです。カーソルは押下が長押しになった時点で隠れ（短いクリックでは何もしない）、離すと狙った位置に再び現れます。その間のマウスモードは`MOUSE_MODE_CONFINED_HIDDEN`です。単に隠しただけのカーソルはウィンドウの外に出て、ウィンドウの端に現れることがあるからです。macOSではエンジンがカーソルを自分で動かしてウィンドウ内に閉じ込めるため、狙いを保つ（後述）ためのカーソル移動を二重に数えてしまい、狙いがずれていきます。そのためmacOSでのモードは`MOUSE_MODE_HIDDEN`で、隠れたシステムカーソルは狙いを追いません。エディターのゲームタブ（Game）ではそうした移動が1〜2フレーム遅れて届き、旋回時にキャラクターががたつくからです。コンポーネントはマウスの動きで自前のカーソルを動かし、システムカーソルはウィンドウの端に達したら中央へ戻し、ボタンを離すと狙った位置に置きます。右ボタンでカメラを回している間はカメラがカーソルをキャプチャします。左ボタンを押したまま右ボタンを離すと、カーソルは再び隠れます。一時停止（設定ウィンドウ）や別のウィンドウへの切り替えでは、すぐにカーソルが表示されます。`is_cursor_hidden()`で、コンポーネントがカーソルを隠しているかどうかがわかります。

**狙いを保つ**（`keep_aim_on_camera_turn`、デフォルトでオン）。左ボタンを押している間、走る方向は画面上の一点であるカーソルから決まります。カーソルが画面上で静止したままカメラが回転すると、カーソルの下に地面の別の地点が来て、キャラクターはそちらへ向きを変え、カメラはキャラクターを追って回転し、キャラクターはぐるぐる回って走ることになります（デモの追従時間1.1秒では1.25秒で77.6°。「即時」ではその場で回るだけ）。そのため、ボタンを押している間、コンポーネントはシステムカーソルを世界と一緒に動かします（`Viewport.warp_mouse()`）。カーソルは地面の同じ地点の上にとどまり、キャラクターは狙った場所へ走り、カメラは徐々にその背後へ回り込みます。マウスを動かせば、いつも通りキャラクターの向きが変わります。ボタンを離した後は、カーソルには手を加えません。

オフにすると、カーソルは車のハンドルのように操縦します。キャラクターの右側にカーソルを置いておくと、カーソルが真正面に来るまでキャラクターは右へ曲がり続けます。システムがカーソルを動かせない環境（たとえばWayland）では、走る方向は保たれますが、カーソルはその場にとどまります。

カーソルは、そのフレームのカメラ位置が確定した後に`_process`で補正されます。コンポーネントの`process_priority`は1、カメラは0です。入力は`Camera3D`を直接読み、カメラリグについては何も知りません。

### プロパティ

| プロパティ | デフォルト | 意味 |
|---|---|---|
| `mover` | — | 命令する`NavigationMover`。必須 |
| `camera` | — | レイと方向に使うカメラ。空ならビューポートの現在のカメラ |
| `move_action` | `move_to_cursor` | クリックと長押し |
| `hold_mode` | `STEER` | 上記参照 |
| `keep_aim_on_camera_turn` | オン | 上記参照 |
| `hide_cursor_while_held` | オン | 上記参照 |
| `camera_steer_action` | `camera_rotate` | これを押している間、長押しでカメラの向きへ走る。空で無効 |
| `ground_mask` | レイヤー1 | クリックできる物理レイヤー。キャラクターのレイヤーを含めてはならない |
| `hold_delay` | 0.2秒 | 押下が長押しになるまでの時間 |
| `steer_dead_zone` | 0.5 m | `STEER`：カーソルがキャラクターにこれより近いと方向を変えない |
| `stop_on_release` | オフ | `FOLLOW_POINT`：離したとき、最後の地点まで走り続けずに減速して止まる |
| `ray_length` | 1000 m | カメラからのレイの長さ |
| `keys_with_camera` | `SIDESTEP` | 右ボタン + WASDのモード |
| `keys_with_camera_steer` | `SIDESTEP` | 左右ボタン + A/Dのモード |
| `move_forward_action` … `move_right_action` | `move_forward` … `move_right` | キー |

シグナル：`destination_picked(point)`、`hold_started`、`hold_pending_changed(pending)`。

コンポーネントは起動時に入力アクションが存在するかを確認し、見つからないものがあればエラーとして報告します。

## CharacterActionInput

| プロパティ | デフォルト | 意味 |
|---|---|---|
| `character` | — | 命令する`GroundCharacter` |
| `sprint_action` | `sprint` | Shift |
| `jump_action` | `jump` | スペース |
| `sprint_mode` | `HOLD` | `HOLD`：キーを押している間ダッシュ。`TOGGLE`：1回押すとダッシュがオン、次に押すとオフ。キャラクターが疲れ切ると自動でオフになり、休んでも戻らない |

このコンポーネントは入力を渡すだけです。ダッシュするだけのスタミナがあるか、今ジャンプできるかはキャラクターが判断します。物理ティックではキャラクターより先に実行されるので（`process_physics_priority = -1`）、押下と解放は余分なティックの遅れなくキャラクターに届きます。`is_sprint_toggled()`で`TOGGLE`の状態がわかります。

### Shiftは押しっぱなしにならない

`HOLD`モードでは、ダッシュは毎ティック`Input.is_action_pressed()`から読み取られるので、Shiftを離すと終わります。これは実際のイベントで確認しています。走行中、左ボタンを押しながら走っているとき、設定ウィンドウ内で離したとき、モードを切り替えた後です。

しかし、離した入力そのものがゲームに届かないことがあり、その場合エンジンはもう一度押されるまでShiftが押されたままだとみなします。これは、ゲームがエディターのゲームタブ（Game）に埋め込まれていてフォーカスがエディターに移ったとき（エディターのウィンドウにフォーカスがある間、`Input.release_pressed_events()`はリセットを省略します）や、システムのショートカットが離した入力を飲み込んだときに起こります。このような場合に備えて、コンポーネントはダッシュの状態を、すべてのマウスとキーボードのイベントが持っているShiftの実際の状態（`shift_pressed`。Windowsでは`GetKeyboardState`から取得）と照合します。ダッシュキー自体以外のマウスまたはキーボードのイベントが、Shiftは離されていると示せば、押しっぱなしの状態は解除されます。これは、ダッシュのアクションに割り当てられたキーがすべて修飾キー（Shift、Ctrl、Alt、Meta）である場合に機能します。

Windowsの固定キー機能（Sticky Keys）がオンになると（Shiftを5回続けて押す）、Shiftはシステム自体で押しっぱなしになります。Windowsの設定でオフにしてください。
