# 入力

[← ドキュメント目次](../index.md)

> これは[英語の原文](../../en/systems/input.md)の翻訳です。内容が異なる場合は、英語版を参照してください。

2つのノードがプレイヤー入力を命令に変えます。どちらもボディを直接動かしません。

- `PointClickMoveInput`：マウスと右ボタン＋WASD → `NavigationMover.move_to()`、`steer()`、`stop()`。
- `CharacterActionInput`：ダッシュとジャンプのキー → `GroundCharacter.sprint_requested`と`jump()`。

どちらもキャラクターシーンではなく操作可能なヒーローシーン（`playable_hero.tscn`）にあります。そのため同じキャラクターをAIでも動かせます。プレイヤー向けの操作は[操作方法](../controls.md)、完成済みヒーローのコピーは[自分のプロジェクトで使う](../integration.md#デモのヒーローを自分のプロジェクトへ移植する)、推奨する組み合わせは[構成](../configurations.md)を参照してください。

## PointClickMoveInput

| 入力 | 命令 |
|---|---|
| 地面をクリック | `move_to(point)`。カメラから`ground_mask`へ飛ばしたレイで地点を探す |
| 左ボタンを長押し | `hold_mode`により、カーソルへ`steer()`するか、その下の地点へ`move_to()`する |
| 右ボタンの後に左ボタン、または`hold_delay`内に両ボタン | カメラの向きへ`steer()`。A/Dは斜め前へ曲げる（`keys_with_camera_steer`） |
| 左ボタンの長押し後に右ボタン | 新しい命令は出さない。右ボタンでカメラを回す間も、長押し中の照準を保つ（`look_around_while_held`） |
| 右ボタン＋WASD | カメラ基準で、横移動または旋回しながら`steer()`（`keys_with_camera`）。離すと`stop()` |

各ティックの操作元は`_physics_process`の1か所で決めます。左ボタン長押しが最優先で、なければ右ボタンと組み合わせたキーです。したがって右ボタンとWを押したまま左ボタンを離しても停止せず、キーが即座に引き継ぎます。

逆に、両ボタンで走行中に右ボタンを離すと、カメラが見ていた進路を維持します（`keep_camera_course`）。マウスが8 pxを超えて動き、かつ`cursor_takeover_delay`の最初の0.2 sを過ぎるとカーソルが操作を引き継ぎます。この遅延中、手がまだカメラを回している可能性があります。引き継ぎ時にはキャラクターの4 m前方、進路上の地点から始めます。それまでは、左ボタンを離せば、2つのボタンを同時に離した場合と同様に進路上で止まります。ボタンをまったく同時に離すことは難しいための動作です。`keep_camera_course`がオフなら、右ボタンを離した時点でオービット前のカーソル位置が操作を引き継ぎ、急旋回する場合があります。

### 走行中に見回す

カーソルを追う長押し走行がすでに始まった後で右ボタンを押すと、カメラだけが回ります（`look_around_while_held`はオン）。プレイヤーは狙った方向へ走りながら、周囲を見たいからです。この設定がなければキャラクターはカメラの向きへ即座に曲がり、特にカメラ追従がオフなら意図しない進路になります。判定は右ボタンを押した瞬間の順序で決まります。

- すでにカーソル操舵の長押し中：見回す。
- 左ボタンが長押しになる前（`hold_delay`の0.2 s以内）に右ボタンを押した、または右ボタンが先：従来どおりカメラの向きへ走る。
- 右ボタンを離した後もカメラの進路を保つ長押し中（`keep_camera_course`）：再びカメラの向きへ走る。マウスが動いてカーソル操舵になれば、次の右ボタン押下は見回しになる。

これは`camera_steer_action`がカメラを回すことを前提にします。`OrbitCameraRig.rotate_action`と同じ`camera_rotate`です。ボタンを押す間、マウスは照準を動かしません。別のアクションを使う場合や、そのアクションでカメラが回らない場合は`look_around_while_held`をオフにします。見回し中、長押しが走行を制御するため、右ボタンがない場合と同じくキーは効きません。

見回し中、照準はマウスを追いません。照準はキャラクターの足を基準とした地面の地点であり、カメラ自身が回るときにも進路を保つ地点です（`keep_aim_on_camera_turn`）。マウスはカメラを回し、`STEER`モードではキャラクターが照準へ走ります。右ボタンを離すとカーソルがその場所へ戻り、再びマウスで操舵できます。大きく回して照準が画面外に出た場合、画面端で急旋回しないよう、同じ方向の近い地点へ照準を寄せます。

`FOLLOW_POINT`モードでも、見回し中とその後にマウスが動くまで、走行先の地点はキャラクターの足に対する相対位置を保ちます（`keep_camera_course`と同様、`cursor_takeover_delay`後に8 px超動くまで）。同じ方向へ走り続け、到着扱いにはなりません。別の角度から見た場合、画面上の同じ位置のカーソル下でもレイは手前の斜面や足場に当たり、地点が変わるためです。すでに地点へ着いた長押し（カーソルが足元にある状態）には保つ地点がなく、見回してもその場に留まります。解除後は、遮るものがなければ新しいカメラ角から同じ地点を狙います。

右ボタンでカメラを回している最中に左ボタンを離すと、隠れたカーソルはカメラの操作が終わったとき、元々右ボタンを押した位置ではなく、狙っていた地点の上へ現れます。

`keep_aim_on_camera_turn`をオフにすると、カーソルは画面上に固定され、オービットに合わせて走行方向も変わります（カメラを90°回すと進路も90°）。停止せずに見回しからカメラ方向への走行へ変えるには、右ボタンを押したまま左ボタンを押し直します。右ボタンが押されている状態の押下は直ちにカメラ方向へ走ります。`look_around_while_held`がオフなら、押す順序に関係なく右ボタンが進路を操舵します。

### クリックか長押しか

押下は`hold_delay`（0.2 s）後に長押しになります。その間キャラクターは従来の動作（静止、または以前の進路の走行）を続け、押下地点へのマーカーも経路もありません。

- **早く離せばクリック。** 押した瞬間の地点へ経路をたどります。その後にマウスが動いても地点は変わりません。マーカーが現れ（`destination_picked`）、到着時、またはキーや長押しへ走行を切り替えたとき消えます。
- **長く押せば長押し。** キャラクターはすぐカーソルを追い（`hold_started`）、最初に押した地点へ向き直りません。そこで先に経路をたどると、障害物を迂回する経路がカーソルとは違う場所へ向かい得るためです。

このためクリックは押下時でなく解除時、約0.1 s遅れて効きます。クリックか長押しか決まるまで`hold_pending_changed(true)`がカメラ追従を一時停止します（`playable_hero.tscn`では`OrbitCameraRig.set_follow_paused()`へ接続）。短いクリックでカメラが動かないようにするためです。

左ボタンを押した時点で右ボタンが押されていればクリックにならず、即座にカメラの向きへ走ります。

### 長押しのモード

`hold_mode`（設定 → 操作 → **左ボタン長押し**）：

- `STEER`（デフォルト）：経路なしでカーソルへまっすぐ進みます。障害物に沿って滑り、指した場所のスロープを上ります。キャラクターから`steer_dead_zone`（0.5 m）以内では方向を変えません。近すぎるとカーソルに敏感になるためです。解除時には滑らかに停止します。
- `FOLLOW_POINT`：ナビゲーション経路に沿ってカーソル下の地点へ進みます。地点が動けば経路を再構築するので、高低差の近くでは別の経路へ跳ぶ場合があります。解除すると最後の地点まで進み、マーカーが示します（`destination_picked`）。`stop_on_release`ならその場で減速します。この設定は長押しだけに効き、短いクリックは選んだ地点まで進みます。経路が空なら直進し、部分的な経路は要求地点より手前で終わる場合があります。[ロコモーション](locomotion.md#navigationmover)を参照してください。

### 右ボタンと組み合わせるキー

キーは右ボタンを押している間だけ機能します。その間、カメラはマウスで回り、カーソルは捕捉されます。右ボタンなしではWASDは何もしません。モードは`OFF`か2種類のいずれかで、右ボタンだけの`keys_with_camera`と両ボタンの`keys_with_camera_steer`を別々に設定します。

| | `SIDESTEP` | `TURN` |
|---|---|---|
| 右ボタン＋W | カメラが見る前方 | 同じ |
| 右ボタン＋A／D | 前を向いたまま横へ | 左／右へ向きを変えて進む |
| 右ボタン＋S | 前を向いて後退。速度は遅い | 振り返ってカメラの方へ歩く |
| 2つのキー（W＋A、S＋D…） | 前を向いたまま斜めへ | 進む方向を向いて斜めへ |
| 左＋右ボタン＋A／D | 前を向いたまま斜め前へ | 進む方向を向いて斜め前へ |

スクリプトでは両方とも`SIDESTEP`がデフォルトですが、デモの設定と`playable_hero.tscn`では両方とも`TURN`です。`keys_with_camera_steer = OFF`は両ボタン時のA/Dだけを無効にし、両ボタンによるカメラ方向への走行は残ります。それも無効にするには`camera_steer_action`を変える必要がありますが、見回しと右ボタン＋キーにも影響します。

斜め移動は直進と同じ速度です。後退は遅くなります。`NavigationMover`は移動が向きと逆向きになるほど速度を下げます。[ロコモーション](locomotion.md#navigationmover)を参照してください。横移動中は`steer(direction, facing)`の第2引数としてカメラの前方を渡します。停止後もキャラクターはその向きを保ち、クリックや長押しを始めると再び走行方向を向きます。

キーまたは右ボタンを離すと滑らかに停止します。キーなしで右ボタンだけを押しても、クリック地点への走行は中断しないため、走りながらカメラを回せます。キーを押すとその走行は中断し、マーカーが消えます。キーはアクション`move_forward`、`move_back`、`move_left`、`move_right`で、物理的なキー位置へ割り当てられます。

### 長押し中のカーソル

**非表示**（`hide_cursor_while_held`はデフォルトでオン）。走行中、特にカメラが回ってカーソルがワールドとともに動くと、表示したカーソルはちらつきます。押下が長押しになった時点で隠し、短いクリックでは変えません。解除時には狙っていた地点へ再表示します。コンポーネントは隠れたカーソルをゲームウィンドウ内に保ちます。macOSでは`MOUSE_MODE_HIDDEN`、それ以外では`MOUSE_MODE_CONFINED_HIDDEN`を使い、プラットフォーム側のカーソル移動が照準をずらさないようにします。右ボタンでオービット中はカメラがカーソルを捕捉し、左ボタンを押したまま右ボタンを離すと再び隠します。一時停止や別ウィンドウへの切り替えでは直ちに表示します。`is_cursor_hidden()`はこのコンポーネントが隠したかを返します。

**照準を保つ**（`keep_aim_on_camera_turn`はデフォルトでオン）。左ボタン長押し中の進路は、画面上のカーソルが指す地点から決まります。カメラが回ってカーソルだけ画面に固定されると、下の地面が変わってキャラクターも旋回し、カメラがそれを追ってまた回るため、走行が円を描きます。そこで長押し中はワールドの同じ地点へ照準を移し、カメラが背後へ回っても最初の方向へ走り続けます。マウスを動かせば通常どおり操舵できます。走行中に右ボタンで見回すときも同じ照準が進路を保ちます。

オフではカーソルが車のハンドルのようになります。キャラクターの右に置いておけば、真正面に来るまで右へ曲がります。Waylandなどシステムがカーソルを動かせない環境では進路は保たれますが、カーソルはその場に残ります。

カーソルの補正は、フレーム内でカメラの位置が決まった後の`_process`で行います。コンポーネントの`process_priority`は1、カメラは0です。入力は`Camera3D`を直接読み、カメラリグのことは知りません。

### プロパティ

| プロパティ | デフォルト | 意味 |
|---|---|---|
| `mover` | — | 命令先の`NavigationMover`。必須 |
| `camera` | — | レイと方向に使うカメラ。空ならビューポートのCurrentカメラ |
| `move_action` | `move_to_cursor` | クリックと長押し |
| `hold_mode` | `STEER` | 上記参照 |
| `keep_aim_on_camera_turn` | オン | 上記参照 |
| `hide_cursor_while_held` | オン | 上記参照 |
| `camera_steer_action` | `camera_rotate` | 押している間、長押しはカメラの向きへ走る。先に押した場合か長押し判定前に押した場合（`look_around_while_held`を参照）。空ならカメラ方向への走行、見回し、キーも無効になる |
| `look_around_while_held` | オン | カーソルを追う長押し中にカメラボタンを押すと、カメラだけ回して進路を保つ。オフなら順序に関係なく両ボタンでカメラ方向へ走る |
| `keep_camera_course` | オン | 長押し中にカメラボタンを離してもマウスが動くまでその進路を保ち、動くと前方へ置いたカーソルが操舵する。オフなら元の位置のカーソルが即座に引き継ぐ |
| `cursor_takeover_delay` | 0.2 s | `keep_camera_course`使用時、カメラボタン解除後、この時間内のマウス移動はまだ走行を引き継がない |
| `ground_mask` | レイヤー1 | クリックできる物理レイヤー。キャラクターのレイヤーや、見えない壁（レイヤー4、`bounds`）を含めない |
| `hold_delay` | 0.2 s | 押下が長押しになる時間 |
| `steer_dead_zone` | 0.5 m | `STEER`ではカーソルがキャラクターにこれほど近いと方向を変えない |
| `stop_on_release` | オフ | `FOLLOW_POINT`では解除時に最後の地点まで進まず、その場で減速して止まる |
| `ray_length` | 1000 m | カメラからのレイの長さ |
| `keys_with_camera` | `SIDESTEP`（デモは`TURN`） | 右ボタン＋WASDのモード |
| `keys_with_camera_steer` | `SIDESTEP`（デモは`TURN`） | 左＋右ボタン＋A/Dのモード |
| `move_forward_action` … `move_right_action` | `move_forward` … `move_right` | キー |

`ground_mask`はクリックレイが当たる物理面を選び、`NavigationMover.navigation_layers`は経路に使えるナビゲーションリージョンを選びます。別々のマスクです。キャラクターや見えない壁をクリックマスクから除かないと、地面の代わりにそれらを拾います。

表はコンポーネントのデフォルトで、ヒーローシーンでの`TURN`への上書きも示しています。デモでは`SettingsApplier`が起動時に保存済みの`hold_mode`、カーソル非表示、両方のキーモード、見回し、照準維持を適用します。設定システムなしで`playable_hero.tscn`をコピーすると、シーンの値を保ちます。

シグナル：`destination_picked(point)`、`hold_started`、`hold_pending_changed(pending)`、`run_requested`。最後は新しい地点へのクリック、長押しになった押下、右ボタン＋キーで始めた歩行など、プレイヤーが新しい走行を命じたときに出ます。すでに向かっている地点を再クリックした場合や、終えたばかりの長押しをキーが引き継いだ場合には出ません。`playable_hero.tscn`ではオービット後のカメラ待機を終わらせます（`CameraRig.end_follow_wait()`。[カメラ](camera.md#追従モード)を参照）。

`cancel()`は押下中の入力を忘れます。まだ解除していないクリックは地点へ走りません。長押しや右ボタン＋キーの走行は滑らかに止まり、`FOLLOW_POINT`でも最後の地点へ進まずに止まります。隠れたカーソルは狙っていた場所へ現れます。ボタンを押し続けたままなら次の押下からしか数えませんが、右ボタン＋キーは毎ティック読むためすぐ再び歩きます。クリック地点への走行はムーバーのもので続きます（`NavigationMover.halt()`なら止まります）。ヒーローはテレポート前と操作を無効にするときにこのメソッドを呼びます。

コンポーネントは起動時に入力アクションを検査し、欠けているものをエラーとして報告します。以後そのアクションは読まれず、キーやボタンは効きません。エンジンからの追加エラーはありません。一部の移動キーがなくてもほかのキーは使えます。`CharacterActionInput`とカメラリグも同様です。

## CharacterActionInput

| プロパティ | デフォルト | 意味 |
|---|---|---|
| `character` | — | 命令先の`GroundCharacter` |
| `sprint_action` | `sprint` | Shift |
| `jump_action` | `jump` | Space |
| `sprint_mode` | `HOLD` | `HOLD`は押している間ダッシュする。`TOGGLE`は押すたびオン／オフが切り替わり、疲労困憊でもオフになり、休んでも自動では戻らない |

このコンポーネントは入力を渡すだけで、ダッシュに足るスタミナやジャンプの可否はキャラクターが判断します。物理ティックではキャラクターより先に動くため（`process_physics_priority = -1`）、押下も解除も余分なティック遅延なしで届きます。`is_sprint_toggled()`は`TOGGLE`状態を返します。

### Shiftが押されたままにならない仕組み

`HOLD`モードでは毎物理ティックでダッシュ要求を読み、通常はShiftを離すと直ちに終わります。ただし埋め込みのGameタブに解除イベントが届かなかったり、OSが横取りしたりする場合があります。`sprint_action`に割り当てられたキーがすべて修飾キー（Shift、Ctrl、Alt、Meta）なら、`CharacterActionInput`は後から届くマウス・キーボードイベントの修飾キー状態も調べ、残ったダッシュ押下を解除します。現在の割り当てを読むため、実行中のキー変更にも対応します。修飾キー以外をダッシュに割り当てた場合、通常のアクション状態だけを使います。
