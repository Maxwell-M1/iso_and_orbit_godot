# カメラ

[← ドキュメント目次](../index.md)

> これは[英語の原文](../../en/systems/camera.md)の翻訳です。内容が異なる場合は、英語版を参照してください。

`OrbitCameraRig`は`Node3D`のターゲットを追い、マウスでその周りを回り、ホイールで距離と傾きを変えます。子の`CameraArm`はローカル+Z方向に`Camera3D`を配置し、近くの地形に入り込まないようにします。走行中の自動旋回、傾きの調整、ズームの調整は、それぞれ独立したオプションです。

```text
PlayableHero (テンプレート内の動かないルート)
├── Character (移動するターゲット)
└── CameraRig (OrbitCameraRig; target = ../Character)
    └── CameraArm (CameraArm)
        └── Camera3D (current = true)
```

リグは動くターゲットの子ではなく隣に置きます。リグ自身がグローバル位置と回転を設定するからです。リグ、アーム、カメラ、そしてそれらの親ノードのスケールを`(1, 1, 1)`に保ち、アームの長さと衝突半径が意図した大きさになるようにします。リグは`target.get_global_transform_interpolated()`から、描画フレームごとにカメラを配置し、`_ready()`で自身の物理補間を無効にします。子ノードは通常その設定を継承します。ターゲットが物理ティックで動くなら、プロジェクトの物理補間を有効にします。そうしないとターゲットがティックごとに段階的に動いて見えます。テンプレートでは有効です。`height_follow_time`を使えば、補間後の垂直方向の段差も滑らかにできます。

`Camera3D`のローカルトランスフォームは初期値にしておきます。アームがそのローカル位置と回転を設定します。テンプレートでは**Current**にしてあり、視野角45°、遠方クリップ距離300ワールド単位です。後から別のCurrentカメラがシーンに入るなら、ヒーローに視点を持たせたいときにこのカメラをCurrentにします。カメラまたはヒーロー全体のコピー方法は[組み込み](../integration.md#カメラ単体で使う)、入力アクションと物理レイヤーは[プロジェクトのセットアップ](../project-setup.md)を参照してください。

## どの値が有効になるか

以下のスクリプト値は、再利用可能なコンポーネントのデフォルトです。`gdscript/player/playable_hero.tscn`は一部を上書きします。さらにデモでは、メインシーンの開始時に`SettingsApplier`が保存済みの`Settings`値を適用します。ヒーローシーンをコピーしただけなら、デモの設定ウィンドウや自動読み込みなしで、シーンの値を使います。

| 設定 | スクリプトのデフォルト | 操作可能なヒーローのシーン／初期状態のデモ |
|---|---:|---:|
| 走行中の旋回、傾き、ズームの自動調整 | すべてオフ | すべてオフ |
| `follow_time` | 1.5 s | 1.1 s |
| `follow_pitch_angle`、`follow_pitch_time` | −40°、1.5 s | −22°、1.1 s |
| `follow_zoom_level`、`follow_zoom_time` | 0.55、1.5 s | 0.55、1.5 s |
| `follow_wait_after_rotate` | オフ | オン |
| `height_follow_time` | 0 s | 0.15 s |

旋回、傾き、ズームの時間と目標値は、それぞれの追従スイッチがオンのときだけ効きます。`height_follow_time`は手動オービット中も含め、常にターゲットの上下移動を滑らかにします。デモでは`user://settings.cfg`に保存した以前の選択が初期値を上書きする場合があります。`SettingsApplier`は設定ウィンドウの正の「見下ろし角」を負の傾きへ、0–100%の「高さ」をリグの0–1ズームへ変換します。

長さと速度はGodotのワールド単位で、テンプレートの1単位＝1 mのスケールならメートルです。`radians_as_degrees`が付いた角度と角速度はインスペクターでは度ですが、GDScriptからはラジアンを代入します。`follow_pitch_angle`には`deg_to_rad(-22.0)`、`sharp_turn_speed`には`deg_to_rad(360.0)`を使います。`playable_hero.tscn`に保存された`-0.383972...`は−22°です。

## オービット、傾き、ズーム

`camera_rotate`（テンプレートでは右マウスボタン）を押しながらマウスを動かすと、カメラがターゲットの周りを回ります。カーソルは捕捉され、ボタンを離すと元の位置に戻ります。フォーカスを失ったときや一時停止時にも解放されます。`mouse_pitch`がオフならマウスの上下移動は効かず、ホイールで傾きを選びます。オンにするとマウスで傾けられ、`invert_pitch`でその軸を反転できます。ホイールを上に回すとカメラは低く、下に回すと高くなります。滑らかなスクロールでは`zoom_step`の一部だけ動くこともあります。

ズームは0（近い）から1（遠い）の数値で、ホイールのデフォルト刻みは0.1です。アーム長は`near_distance`の5から`far_distance`の20ワールド単位へ補間されます。近距離ほど傾きが浅くなり、次の曲線に従います。

| ズーム | 距離 | 基本の傾き |
|---:|---:|---:|
| 0 | 5 | −22° |
| 0.2（`flatten_end_zoom`） | 8 | −22° |
| 0.5（`flatten_start_zoom`） | 12.5 | −38.5° |
| 0.55（`start_zoom`） | 13.25 | −40.15° |
| 1 | 20 | −55° |

ズーム0.2から0.5の間では、カメラを下げるほど傾きが素早く水平に近づき、前方の地面を見やすくします。0.2未満では距離だけが変わります。マウスによる傾きと追従による傾きは、この曲線にオフセットを加え、`min_pitch`と`max_pitch`（−80°と−8°）で制限します。`mouse_pitch`をオフにすると、`follow_pitch`が傾きを保持していない限り、マウスのオフセットは消えます。`rotation_sharpness`と`zoom_sharpness`はマウスとホイールの変化を滑らかにし、0なら対応する入力が即時に反映されます。

## 追従モード

`follow_movement`、`follow_pitch`、`follow_zoom`を任意の組み合わせで有効にすると、走行方向の後ろへカメラを回し、指定した傾きとズームへ近づけます。リグは任意の`Node3D`ターゲットから物理ティックごとの水平移動を測るため、キャラクターの速度プロパティを必要としません。`follow_min_speed`未満では追従せず、その速度から2倍の速度まで追従の強さが滑らかに増えます。停止したターゲットは、次に走り始めたとき新しい方向として扱われます。

有効な動きはそれぞれ独立したスプリングで滑らかに始まり、収束します。所要時間は、旋回速度の上限が作用しない全速走行で、静止状態から変化量の約95%に達するまでの時間です。0なら即時の変化を要求します。移動が止まるか追従が一時停止すると、進行中の動きは急停止せず減速します。減速率は`rotation_sharpness`と`zoom_sharpness`で決まります。追従はカメラを直接動かすため、入力の平滑化による二重の遅れはありません。

| プロパティ | スクリプトのデフォルト | 効果 |
|---|---:|---|
| `follow_movement`、`follow_time` | オフ、1.5 s | 水平走行の後ろへ回る。ほぼ回り終わるまでの時間 |
| `follow_max_turn_speed` | 0 | 自動ヨー回転の最高速度（°/s）。0で上限をなくし、即時旋回にも適用する |
| `follow_toward_camera_angle` | 30° | カメラへ真正面に向かう方向からこの角度内では旋回を無視する。角度の2倍で通常の強さになる。0で例外をなくす |
| `sharp_turn_speed` | 360°/s | 急な旋回や反転中の途中方向を無視し、新しい方向が決まってから追う。0でこの保護を無効にする |
| `teleport_speed` | 50ワールド単位/s | 物理ティック間の水平移動がこれより速ければ走行ではなくテレポートと扱う |
| `follow_pitch`、`follow_pitch_angle`、`follow_pitch_time` | オフ、−40°、1.5 s | ヨー回転とは独立して、指定した下向き角度へ傾ける |
| `follow_zoom`、`follow_zoom_level`、`follow_zoom_time` | オフ、0.55、1.5 s | ヨー回転と傾きとは独立して、この0–1のズーム値へ近づける |
| `follow_min_speed` | 1ワールド単位/s | 追従を始める最低水平速度。この2倍で全強度になる |
| `follow_wait_after_rotate` | オフ | マウスでオービットした視点を、ターゲットが`follow_min_speed`未満に減速するか新しい走行が通知されるまで保つ |

カメラへ向かう走行を除外する判定は、**旋回だけ**に作用します。真正面からカメラへ向かっても、オプションが有効なら傾きとズームは変わります。急旋回の保護も旋回だけに作用します。反転中も傾きとズームは続き、すでに始まった旋回は惰性で止まることがあります。テンプレートのヒーローでは`LocomotionSettings.turn_speed`が720°/sで、360°/sの急旋回閾値は反転を拾いつつ緩やかなカーブを通します。キャラクターの旋回速度を変えたら、`sharp_turn_speed`をその半分以下に保ってください。正の閾値がキャラクターの旋回速度に達すると`PlayableHero`が警告します。`follow_toward_camera_angle`を0にすると、カメラへ向かう走行でも意図的に後ろへ回れるようになります。

傾きとズームの両方を自動調整すると、ズームが距離を変え、傾きの調整がズーム曲線を補正します。視点は`follow_pitch_angle`と`follow_zoom_level`へそれぞれ独立して収束します。走行中もホイールとマウスは操作でき、追従が有効な動きはその後で目標へ戻ります。`height_follow_time`は別の機能で、特に階段でターゲットの**ワールドY位置**にリグが追従する過程を滑らかにします。ズーム値は変えません。0なら高さを正確に追い、ヒーローシーンの0.15秒では上下移動の約95%をその時間で追います。

### 追従が一時停止するとき

右ボタンを押している間、3つの追従動作はすべて視点を引っ張りません。`follow_wait_after_rotate`がオンなら、0.2秒以上または2 px以上動かしてオービットを終えた後も、現在の走行中は選んだ視点を保ちます。右ボタンを離す前にフォーカスを失ったりゲームを一時停止したりした場合も同じです。短いタップでは待機を始めません。オプションがオフなら、オービット終了時に追従を再開します。待機が終わるのは、移動速度が`follow_min_speed`未満になったとき、`end_follow_wait()`が新しい走行を通知したとき、`snap()`が呼ばれたとき、ターゲットが変わったとき、または移動が`teleport_speed`を超えたときです。前の走行が止まる前に次が始まることもあるため、このオプションを使うなら入力の`run_requested`シグナルを`end_follow_wait()`へ接続します。新しい走行を通知できないゲームでは、動き続けるターゲットに対してカメラがずっと待機する場合があるので、オプションをオフにします。

`playable_hero.tscn`では、`PointClickMoveInput.hold_pending_changed`も`set_follow_paused()`へ接続されています。これにより、左ボタンを押してからクリックか長押しかを判定する最初の0.2秒は追従が一時停止します。`run_requested`シグナルは、新しいクリック、長押し、右ボタン＋キーによる走行の際に、オービット後の待機を終わらせます。左ボタンで走行中に右ボタンを押して見回すこともできますが、その走行は右ボタンを離した後の新しい走行とは数えられません。次の停止または新しい走行まで、視点はプレイヤーが残した位置に保たれます。入力の`keep_aim_on_camera_turn`はカメラが動いてもカーソルの照準を同じワールド地点に保ち、走行方向がカメラの動きを追いかけないようにします。

`Engine.time_scale`が0の間は追従動作の状態が保たれ、時間が進むと再開します。ターゲットを手動で動かしたり、`teleport_speed`の判定を引き起こさない短い距離をテレポートさせたりした場合は、`snap()`でカメラとアームを配置し直し、移動履歴をリセットしてください。

## プロパティ

| グループ | プロパティ | スクリプトのデフォルト | 意味 |
|---|---|---:|---|
| ターゲット | `target` | なし | 追従する`Node3D` |
| ターゲット | `arm`、`camera` | なし | 未設定なら一致する最初の直接の子を使う。`camera`はアームがない場合だけ使う |
| 入力 | `rotate_action`、`zoom_in_action`、`zoom_out_action` | `camera_rotate`、`camera_zoom_in`、`camera_zoom_out` | Input Mapのアクション。欠けていると起動時にエラーを報告する |
| 入力 | `mouse_sensitivity`、`mouse_pitch`、`invert_pitch`、`zoom_step` | 0.25 °/px、オフ、オフ、0.1 | マウスのオービット速度、マウスでの傾き操作、ホイールの刻み |
| 構図 | `focus_height` | 1.2ワールド単位 | ターゲットの原点から上にある注視点 |
| 構図 | `near_distance`、`far_distance` | 5、20 | ズーム0と1でのアーム長 |
| 構図 | `near_pitch`、`far_pitch` | −22°、−55° | ズーム0と1での基本の傾き |
| 構図 | `flatten_start_zoom`、`flatten_end_zoom` | 0.5、0.2 | 傾きをより速く水平に近づけるズーム区間 |
| 構図 | `min_pitch`、`max_pitch` | −80°、−8° | マウスと追従のオフセットを含む最終的な傾きの範囲 |
| 構図 | `start_zoom`、`start_yaw` | 0.55、45° | 初期ズームとワールド軸でのヨー角。後から`look_along()`で変えられる |
| 平滑化 | `rotation_sharpness`、`zoom_sharpness` | 30、10 | 大きいほどマウス／ホイールの目標に早く届く。0なら即時 |
| 平滑化 | `height_follow_time` | 0 s | ターゲットの上下移動の約95%を追う時間。0なら正確に追う |

`look_along(direction)`は**ワールド空間**の方向の水平成分へ直ちに視点を向け、進行中の自動旋回を止めます。`snap()`は現在のヨー角、傾き、ズーム、ターゲット位置、アームの衝突反応を直ちに適用します。テレポート後に使います。`get_zoom()`は現在の0–1ズームを返します。`is_rotating()`、`is_follow_paused()`、`is_follow_waiting()`、`is_target_turning_sharply()`は各状態を報告します。`set_follow_paused(paused)`と`end_follow_wait()`は前述の一時停止を制御します。

リグにはアームまたはカメラの子（もしくは明示的な`arm`／`camera`プロパティ）が必要です。なければデバッグビルドでアサーションが起こります。リグはグローバル回転を設定するため、動かないヒーローのルートが回っていても、`start_yaw`、`look_along()`、自動旋回はワールド軸を使います。

## 障害物、遮蔽、フェード

通常、`CameraArm`は`keep_out_of_geometry`を使い、目的のカメラ位置に置いた球が物理ボディの外に収まるようにします。壁、斜面、屋根にカメラが入り込むなら、アームは即座に短くなります。ターゲットとカメラの間に柵があっても、柵の後ろにカメラを置ける空間があれば短くなりません。ターゲットを隠す柵の手前へ意図的にカメラを動かすには`pull_in_on_occlusion`を有効にします。アームは遮蔽が続くのを待ち、少なくとも`min_pull_in_length`の長さが残る場合だけ短くなります。視界が戻ると少し待ち、滑らかに戻ります。戻る経路に障害物があれば、突き抜けて飛ぶ代わりに飛び越します。

### アームが障害物の後ろの空間とボディ内部を見分ける方法

アームはまず、目的の終点にカメラ球が収まるか調べます。終点が空いていれば、ターゲットとの間に柵があってもその後ろに留まれます。終点がボディに接触するか内部にあるときは、ターゲットへ近い空間を探します。Joltのシェイプキャストは開始地点ですでに接触・侵入しているボディを報告しないため、アームは開始空間を別に調べます。2つのボディが近接している場合は、ターゲット寄りの地点から探し直します。これによって、すぐ後ろに崖がある柵にもカメラが入り込まずに済みます。

球と視線レイはどちらも`collision_mask`（2進数`0b101`、レイヤー1と3）を使います。テンプレートではレイヤー1が固体のワールド形状、レイヤー3が`RoofCameraBlocker`などのカメラ専用形状です。レイヤー2のキャラクターとレイヤー4の見えないキャラクター境界はアームを動かしません。`camera_ignore`グループに入るボディ、またはそのグループのノードの下にあるボディは無視されます。小道具のルートにグループを設定すれば、すべてのインスタンスに効きます。ほかのプロジェクトへコピーするときはレイヤー番号が重要で、名前はラベルにすぎません。`keep_out_of_geometry`をオフにすると、引き寄せの設定に関係なく、アームは背後の地形からカメラを守らなくなります。

デフォルトの5つの`occlusion_points`は、ターゲットの胸、頭、膝、両脇を調べます。これらはアームの**始点**を基準とし、リグがターゲットの原点から`focus_height`だけ上に置きます。xはカメラの右、yは上、zは水平にカメラへ向かう方向です。`occlusion_share = 0.75`は5点中少なくとも4点が遮られる必要があることを意味します。背の高いモデルや浮遊モデルでは点と`focus_height`を調整します。テンプレートの`CharacterHover`は見えるモデルをボディから0.35ワールド単位持ち上げられます。

`fade_target`は任意です。設定すると、アーム長が`fade_start_length`より短くなるにつれ、その子孫の`GeometryInstance3D`の`transparency`を変更し、`fade_end_length`で`fade_transparency`に達します。ヒーローでは`Character/Visual`を指定しています。この近距離でのフェードは、障害物越しにキャラクターを描く任意の`OccludedSilhouette`アドオンとは別の機能です。

| プロパティ | スクリプトのデフォルト | 意味 |
|---|---:|---|
| `length`、`camera` | 10、なし | 目的のアーム長（通常はリグが設定）、および未指定なら最初の直接の子である`Camera3D` |
| `keep_out_of_geometry`、`probe_radius` | オン、0.3 | カメラ球をマスクに含まれるボディの外に保つ |
| `collision_mask`、`ignored_groups` | レイヤー1＋3、`camera_ignore` | 衝突・遮蔽判定の対象ボディと、除外するグループ |
| `pull_in_on_occlusion`、`min_pull_in_length`、`pull_in_sharpness` | オフ、2.5、10 | 引き寄せスイッチ、最短長、近づく速さ（0なら即時） |
| `occlusion_points`、`occlusion_share`、`occlusion_delay` | 5点、0.75、0.25 s | 視線サンプル、遮られる割合、引き寄せまたは戻るまでの遅延 |
| `return_delay`、`return_sharpness` | 0.3 s、4 | アームを伸ばすまでの待機と速さ（sharpnessが0なら待機後に即時） |
| `fade_target`、`fade_start_length`、`fade_end_length`、`fade_transparency` | なし、1.5、0.7、0.75 | 任意のモデルフェード。0.7単位以下で最大 |
| `debug_draw` | オフ | 目的／現在のアーム長、カメラ球、視線レイを描く。別のカメラからの確認に便利 |

`CameraArm.snap()`は衝突を再計算し、戻りの遅延なしでカメラを配置します。`get_current_length()`は障害物に対応した実際のアーム長を返し、`is_pulled_in_by_occlusion()`はターゲットの遮蔽によって内側へ移動中かを示します。

上記の動作は[`tests/camera_checks.gd`](../../../tests/camera_checks.gd)と[`tests/camera_arm_checks.gd`](../../../tests/camera_arm_checks.gd)で検査されています。追従の時間、カメラへ向かう走行と急旋回の保護、マウスオービット後の待機、傾き／ズームの調整、階段での上下方向の平滑化、障害物の回避、任意の引き寄せ、無視するグループ、フェードを扱います。
