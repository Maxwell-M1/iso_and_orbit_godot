# ワールドとナビゲーション

[← ドキュメント目次](../index.md)

> これは[英語の原文](../../en/systems/world-and-navigation.md)の翻訳です。内容が異なる場合は、英語版が正しいものとします。

デモの開始レベルは`shared/world/world.tscn`の草原で、木の柵に囲まれた80 × 80 mの草地です。すべてプリミティブとシェーダーで作られ、表面の細部はベイク済みテクスチャを使います。古代の円環のそばのテレポートパッドから2つ目のレベル、孤島へ行けます。両方の説明は[レベル](levels.md#デモのレベル)を参照してください。

## 物理レイヤーとナビゲーション

障害物はレイヤー1（`world`）の`StaticBody3D`、キャラクターはレイヤー2（`characters`）、カメラ専用のボディはレイヤー3（`camera`）、レベル端の見えない壁はレイヤー4（`bounds`）です。[プロジェクトのセットアップ](../project-setup.md#物理レイヤー)を参照してください。ナビゲーションメッシュはレイヤー1の衝突形状からベイクします（島では端の壁も含むレイヤー4からも）。エージェント半径は0.5 mで、キャラクターのカプセル半径0.35 mより大きく、経路が角から距離を保ちます。

| `NavigationMesh`のパラメーター | 値 | 理由 |
|---|---|---|
| `agent_radius` | 0.5 m | 経路が角から離れる |
| `agent_height` | 1.75 m | デモの既存ベイク値。天井がある新しいレベルでは衝突形状の全高以上にする（ヒーローのカプセルは1.8 m） |
| `agent_max_slope` | 40° | 山の斜面がメッシュに含まれない |
| `cell_height` | 0.025 m | 下記の登坂を測れるほど細かい |
| `cell_size` | 0.25 m | 水平方向のベイク解像度。ナビゲーションマップと合わせる |
| `agent_max_climb` | 0.3 m（12セル） | キャラクターが上れる段（`GroundCharacter.max_step_height`） |
| `geometry_parsed_geometry_type` | Static Colliders | 見えるメッシュではなく衝突形状からベイクする。下の衝突マスクはコライダーに適用され、メッシュのない見えない壁もこの方法なら含まれる |
| `geometry_collision_mask` | レイヤー1、島では1と4 | 障害物と見えない壁を含める |
| `filter_walkable_low_height_spans` | デモではオフ | 天井がある新しいレベルではオンにして、`agent_height`より低い空間を除く |

**ナビゲーションを衝突ボディに合わせます。** `agent_max_climb`は`GroundCharacter.max_step_height`（ここでは0.3 m）以下、ナビゲーションの斜面上限はボディの床上限以下（ここでは40°と45°）にします。どちらかを変えたら再ベイクします。ナビゲーションはセルへ離散化されるため、数値を合わせてもすべての縁で通れる保証はありません。通したい最高の段と、通したくない最低の段を実際に試します。デモでは0.2 mの段を通し、0.4 mのブロックを拒否します。細かな0.025 mの垂直セルで小さな高さの差を区別できます。

新しいレベルではAgent Heightをカプセル全高以上にし、`filter_walkable_low_height_spans`を有効にします。高さの設定だけでは空間を調べるフィルターは有効になりません。天井のコライダーもベイクに含めます。浮遊モデルはボディより上へ伸びるため、見た目の頭上の余裕は別に確認します。半径は壁の周りの経路の余裕を決めます。カプセル半径を変えたら狭い通路を確認し、再ベイクします。

マップとメッシュの`cell_height`と`cell_size`を一致させます。デモでは垂直0.025 m、水平0.25 mで、対応するプロジェクト設定は`navigation/3d/default_cell_height`と`navigation/3d/default_cell_size`です。Godotの[NavigationMeshリファレンス](https://docs.godotengine.org/en/stable/classes/class_navigationmesh.html)にベイク解像度、丸め、空間フィルターが説明されています。

ベイク済みの面は衝突する床より少し高い場合があります。`NavigationMover`は経路の進みをXZ平面で比較し、物理処理がボディの実際の高さを決めます。物理レイヤーはベイクする形状を選び、リージョンのナビゲーションレイヤーと`NavigationMover.navigation_layers`は使える経路を選びます。

ナビゲーション結果が空なら直接移動に切り替わり、部分的な経路は到達不能な目標の手前で終わる場合があります。悪い経路を移動値で補う前に**Debug → Visible Navigation**とデモの**キャラクターの経路線**を確認します。[ロコモーション](locomotion.md#navigationmover)を参照してください。


## ナビゲーションメッシュを再ベイクする

メッシュは事前にベイクされ、`shared/world/world.tscn`と`shared/world/island/island.tscn`の各レベルシーン内（`NavigationRegion3D`の`NavigationMesh`リソース）に保存されます。ゲームは再計算しません。レベルを編集したら、そのメッシュを再ベイクします。両方のパラメーターは衝突マスク以外同じで、島はレイヤー1と4からベイクします。

**再ベイクが必要なとき：**レイヤー1（`world`）の衝突形状を持つ岩、木箱、壁、木、小道具、NPC、山を移動、追加、削除、サイズ変更したときです。島ではレイヤー4（`bounds`）の見えない壁も含みます。メッシュやマテリアルなど見た目だけの変更、レイヤー3（`camera`）のボディ、レイヤー2のプレイヤー、`Area3D`には不要です。忘れると経路が移動後の物体を通り抜けたり（キャラクターはぶつかって滑ります）、以前物体があった空間を迂回したりします。

**エディターでの手順**：

1. 対象レベルのシーンを開きます。
2. シーンツリーで`NavigationRegion3D`を選択します。
3. 3Dビューの上のツールバーで**ナビゲーションメッシュをベイク**（Bake NavigationMesh）を押します。数秒後にビュー内の青いメッシュが更新されます。オブジェクトの周りにエージェント半径（0.5 m）分の穴が開き、以前オブジェクトがあった場所はメッシュで埋まります。
4. シーンを保存します（Ctrl+S）。メッシュはシーンに埋め込まれます。

ベイクのパラメーターはリソース自体にあります。`NavigationRegion3D`を選択し、インスペクター（Inspector）で`Navigation Mesh`を展開してください。

再ベイクした後は、テストを実行してください（[テスト](../testing.md)）。テストのルートはメッシュに従います。実行中のゲームでは、エディターのデバッグ → ナビゲーションを表示（Debug → Visible Navigation）でメッシュが表示され、設定（F10）→ インターフェース → **キャラクターの経路線**でキャラクターの経路が表示されます。

## レベル

- **中央**はスポーン地点です。その周りには、崩れた列柱の輪、スポーン地点に向かって開いたU字型の罠、隙間のある長い壁、木箱、木立、生け垣の迷路、西側にスロープ、東側に階段（高さ0.2 m、踏み面0.4 mの段が7つで、7つの箱からなる1つの静的ボディ）がある高さ1.6 mのプラットフォームがあります。テストはこれらすべてを使うため、位置を保っています。
- **道**は土の帯で、南の柵から壁の隙間を抜けてスポーン地点へ、さらに山、遺跡、野営地、スロープへと続きます。農家への道は壁の南で分岐します。道は模様にすぎず（`shared/world/terrain.gdshaderinc`のセグメント`ROADS`）、移動には影響しません。地面と山のふもとのなだらかな草地の両方が道を描くので、道は途切れずに山道へつながります。道は西から山道の起点に達します。山道の起点の東側では、山は高さ4 mまでの切り立った崖になっています。
- `shared/world/props/`の**プロップ**：北西と周縁の森、茂み、岩、東の野営地（テント、揺らめく光のたき火、樽）、南西の農家（家、井戸）。
- 北東の**山**は高さ10 mで、頂上へ続くらせん状の山道が1本あります。
- **10種類の主人公の外見**は、隙間の東側で南の壁を背にして一列に並んでいます（[キャラクター](characters.md#主人公の外見)を参照）。

配置を変えるにはレベルシーン内の小道具インスタンスを編集し、ナビゲーションを再ベイクします。回帰テストはデモの特定の経路と障害物位置を使います。独自の配置には別のレベルを用意するか、テスト用の形状とともにテストを更新してください。

### 場所とNPC

4つの場所は`PointOfInterest`エリアです。プレイヤーが初めてそこに入ると、画面上部に「発見：…」が数秒間表示されます。各場所にはNPCが頭上に名前のラベル（`Label3D`）を付けて、場所の中心を向いて立っています。騎士だけは道の先を向いています。

| 場所 | 位置 | いる人物 |
|---|---|---|
| 吹きさらしの峰 | 北東の山の頂上 | 魔法使い。水晶のある祭壇のそば |
| 旅人の野営地 | 東：テント、たき火、樽 | たき火のそばのレンジャーとドワーフ |
| 井戸のそばの農家 | 南西：家、井戸 | 道のそばで見張りをする騎士 |
| 古代の円環 | スポーン地点の北西にある列柱の輪 | 祭壇のそばの盗賊 |

各NPCは、レイヤー1にカプセルを持つ`StaticBody3D`です（`World/NavigationRegion3D/Characters`）。ナビゲーションメッシュはNPCを避け、誰もNPCを通り抜けません。野営地、農家、遺跡は`World/Places`の下にあり、峰は`mountain.tscn`にあります。

**新しい場所：**衝突形状と`title`を持つ`PointOfInterest`（`collision_mask`にキャラクターのレイヤー2を含む`Area3D`）をワールドシーンに追加します。トーストは後から読み込んだレベルも含めグループから全場所を探すため、接続は不要です。タイトルを翻訳に追加してください（[UI](ui.md#翻訳)）。孤島には5つ目の場所、隠者のキャンプがあります。

## 表面

ほぼすべての表面は、`shared/world/`のシェーダーと`shared/world/materials/`のマテリアルでできています。例外は通常の`StandardMaterial3D`マテリアルで、この節の最後に挙げています。オブジェクトの大きさや形に依存するものはシェーダーが計算しますが、その負荷は軽いものです：箱の高さに合わせた石積みの段、板、枠と柱、木骨組み、樽の側板とたが、柱の溝と石筒、`ROADS`に沿った道、高さによる岩の層。そのため、どんな大きさの箱でも模様が引き伸ばされません。細かいディテール（草の葉、小石、木の葉、樹皮、石の粒）はベイク済みテクスチャから来ています。下記を参照してください。

| 表面 | シェーダー | 見た目 |
|---|---|---|
| 壁、プラットフォーム、スロープ、階段 | `stone_masonry` | 互い違いの段に積まれ、目地のあるブロック。ブロックごとに独自の色合い、粒、欠けがあり、法線による起伏、地面近くの汚れと苔。上面は短辺方向に並んだ石の段 |
| 生け垣の迷路 | `hedge_foliage` | 2層の葉。それぞれ独自の回転、大きさ、色合い、傾きを持つ。隙間には茂みの奥行きによる影。刈り込んだ茂みのような不均一な側面 |
| 木箱、柵 | `wood_planks` | 年輪、繊維、節、隙間のある板。木箱は各面に板の枠、斜めの筋交い、釘がある。柵は2.5 mごとの柱に風化した長い板を渡している |
| 柱、井戸 | `stone_column` | 法線による円周方向の溝、地面から0.8 mごとの目地のある石筒、滑らかな台座、筋、まれなひび、地衣類、地面近くの苔。井戸は円形のブロック積み（`blocks_around`）を使う |
| 岩、立石 | `rock` | 筋とひびのある粒状の石、上部の地衣類、地面近くの苔。模様はトライプラナー（`triplanar.gdshaderinc`）で、岩ごとに異なる |
| 家の壁 | `timber_plaster` | 木骨組み：柱と梁の枠の中にしみと細かいひびのある漆喰、石の土台 |
| 家と井戸の屋根 | `thatch` | 束を並べた茅葺き、各列の下の影、斜面に沿った藁、縛った棟、苔 |
| テント、垂れ布、旗 | `canvas` | 織った帆布：縫い目、ひだ、継ぎはぎのあるパネル。旗には縁取りと紋章がある |
| 樽 | `barrel` | 隙間のある側板、錆びた鉄のたが、板のふた |
| 丸太、幹、旗竿 | `bark` | 地面近くと北側に苔の付いた溝のある樹皮。たき火の丸太は焦げてくすぶっている |
| 木の樹冠、茂み | `foliage` | 3つの軸平面上の2層の葉、塊、明るめの上部。松には針葉、秋のオークにはオレンジと赤 |
| 地面 | `ground_grid` | 下記参照。島の草地は道路（`roads`）をオフにした同じ地面の`island_ground.tres` |
| 山 | `mountain` | 面の色で選ばれる草、山道、岩の層 |
| 井戸と島の湖の水 | `water` | ゆっくりとした波紋。湖の`lake_water.tres`はより明るい青で、波紋も強い（`ripple`は0.35に対して0.55） |

石積みの模様はメッシュの面に沿い、箱の大きさを把握します。面の分割がない`BoxMesh`は各角にだけ頂点を持つので、`abs(VERTEX)`で半分のサイズが得られます。それを`flat`のvaryingでピクセルへ変えずに渡します。補間するとピクセルごとに末尾の桁が異なり、ちょうど半端な段数（高さ1.4 mの段に0.4 mの石積みなど）の丸めが場所によって上下してちらつきます。漆喰、板、布のシェーダーも同様に箱の大きさを渡します。側面の段は高さに合い、最上段は上面の石の縁になって目地がつながります。薄いスロープはそのような1段で、端の目地が上面と一致します。一方、迷路の箱は25 cmごとに面を分割します（`subdivide_*`）。側面がワールド座標のノイズで変位し、辺上の複製頂点を一緒に動かして面が裂けないようにするためです。衝突形状は単純な箱のままで、葉は数センチはみ出します。

**地面**（`ground_grid.gdshader`、共通部分は`terrain.gdshaderinc`）：複数のスケールの草（濃い草・普通の草・枯れた草の大きなまだら、草むら、傾いた法線と根元の影を持つ2層の葉、開けた場所に散らばる花）と道（草の房がある不揃いな縁、踏み固められて明るくなった中央、浅いわだち、粒、乾いた場所の細かいひび、影のある小石。小石は縁ほど多い）。細かいディテールはベイク済みテクスチャから3.84 mごとにタイル状に繰り返され、大きなまだらは地面全体にかかるマスクから来ています。遠くではテクスチャのミップレベルによってディテールが平均色へ溶け込みます。山の草と山道も同じコードを使います。5 mごとに太線が入る1 mのグリッドはデフォルトでオフです。速度や距離を測るには、`shared/world/materials/ground.tres`の`grid_strength`でオンにしてください。

負荷の軽いシェーダーノイズ（石や板の乱数、葉の塊）は`noise.gdshaderinc`に、葉は`leaves.gdshaderinc`にあります。いくつかのマテリアルは通常の`StandardMaterial3D`のままです：キャラクターの装備（杖、弓、斧）が使う`dark_wood.tres`と`wood.tres`、光る`crystal.tres`と`fire.tres`。

## ベイク済みテクスチャ

表面の模様（葉と花のある草、小石のある土、木の葉、樹皮、石の粒、漆喰、木の繊維、茅葺き、織物）はノイズシェーダーとして設計されましたが、ゲームはそれをピクセルごとに計算しません。一度だけ`shared/world/textures/`のシームレステクスチャにベイクし、ワールドのシェーダーがそれをタイル状に並べます。

ベイクによって、ピクセルごとに繰り返すノイズ計算をテクスチャのサンプルへ置き換えています。テクスチャを交換するときは以下のインポート設定を保ってください。複数のチャンネルには通常の色ではなくシェーダー用データが入っています。

- **シームレス**。模様のノイズはタイルと一緒に繰り返し、タイルあたりの特徴の数が整数なので、継ぎ目は見えません。例外は`ground_mask`で、96 mの地面全体にかかる大きなまだらと道であり、タイル状には繰り返しません。
- **色はワールドのシェーダーに残します**。木の葉、柱の石、樹皮、木の繊維は色なしでベイクし（葉の色合い、影、葉か隙間か、しみ、法線の傾き）、ワールドのシェーダーがマテリアルのパラメーターから色を作ります。1枚の葉のテクスチャで、オーク、秋のオーク、生け垣をまかなえます。色がベイクされているのは、草（まだらの色合いの乗数）、花、小石だけです。
- **起伏**は2チャンネルの法線の傾きで、ベイク時に高さの差から計算します。
- **ファイル**：可逆WebP（アルファが0の部分のデータもそのまま残る）。アルファにデータを持つため、GPU圧縮（BPTC）、ミップマップあり、透明ピクセルの色修正なしでインポートしています。テクスチャを置き換えるときは、これらのインポート設定を保ってください。

## 山と吹きさらしの峰

山はワールドの端の角に立ち（斜面は柵の外まで続く）、どこからでも見えます。頂上への山道は幅3 mで、道の終点（23, 0, −19）から始まり、12°の勾配で山をほぼ一周（340°）します。両側の斜面は急で（山道の上側が76°、下側が60°）、歩いて登ることも（ボディが立てるのは45°以下の斜面だけ）、経路で登ることも（ナビゲーションメッシュが扱う斜面は40°まで）できません。落下防止がキャラクターを山道から落ちないようにします。地上から頂上をクリックすると、山道に沿って進みます：51 mを9.8秒。

頂上には祠があります：上に光る水晶が浮かんでゆっくり回る祭壇、5つの立石、旗です。頂上が場所「吹きさらしの峰」です。

山はスクリプトで生成したハイトマップです：面の色とフラットシェーディングを持つメッシュに、マテリアル`materials/mountain.tres`を重ね（面の色に応じて、葉のある草、小石のある山道の土、ひびと地衣類のある岩の層）、同じ三角形からコリジョンシェイプを作っています（`shared/world/mountain/*.res`）。山道に沿って経路が作られるようにするために必要だったこと：

- 山道は横断方向に高さが一定なので、内側の縁は中心線より急になります（中心線の半径と縁の半径の比の分だけ）。曲がりはきつくなく（半径9.5 → 7 m）、頂上付近でも内側の縁は16°より緩やかです。これより急だと、0.25 mのセルあたり0.075 mの登坂を持つナビゲーションメッシュでは山道が途切れてしまいます。
- 道からの入口：ふもとでは、山道が1 mより低い間は外側の斜面がなだらかです。そうしないと山道は起点から外側に落ち込み、入口がエージェントのマージンより細い帯にまで狭まってしまいます。
- 山道の最後の3 mは頂上と同じ高さなので、山道は1点ではなく帯状に頂上とつながります。

カメラはデフォルトで南東から見ているので、山道の奥側では山が主人公を隠し、主人公はシルエットで表示されます（[キャラクター](characters.md#occludedsilhouette1つの形輪郭付きの武器縁取り)を参照）。
