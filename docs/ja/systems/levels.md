# レベル

[← ドキュメント目次](../index.md)

> これは[英語の原文](../../en/systems/levels.md)の翻訳です。内容が異なる場合は、英語版を参照してください。

このページでは、ゲームがレベルを切り替える仕組みを説明します。レベルホストとローディング画面、ポータルとスポーン地点、レベル間を移動する操作可能なヒーロー、デモの2つのレベルを扱います。コンポーネントは`addons/iso_orbit/levels/`にあります。ヒーロー、移動の案内、ゲーム全体をつなぐ部分はコンポーネントを使って作ったデモのファイルです。

## ゲーム全体のシーン

`gdscript/main.tscn`はゲームの実行中ずっと残るシーンです。現在のレベルはレベルホストの子であり、ヒーローとインターフェースはその兄弟ノードです。そのため、レベルだけを入れ替えられます。

| ノード | クラス | 役割 |
|---|---|---|
| `Levels` | `LevelHost` | 現在のレベルを唯一の子として保持し、切り替える |
| `Levels/World` | | エディターで配置した開始レベル`shared/world/world.tscn` |
| `Hero` | `PlayableHero` | 入力、カメラ、クリックマーカー、経路線を持つプレイヤーのキャラクター |
| `Hud/TravelPrompt` | `TravelPrompt` | パッド上で表示する移動先の案内 |
| `LoadingScreen` | `LoadingScreen` | レベル読み込み中の画面 |

`gdscript/main.gd`がこれらを接続します。

| シグナル | ゲーム全体の処理 |
|---|---|
| `LevelHost.portal_entered(portal)` | ポータルが自動移動でなければ、その案内を表示する。2つのポータルに同時にいるときは、後から入った方を案内する |
| `LevelHost.portal_exited(portal)` | その案内を隠す。ヒーローがもう一方のポータルにも立っていれば、その案内を表示する |
| `TravelPrompt.confirmed(portal)` | `portal.travel()`を呼ぶ |
| `LevelHost.level_change_started` | 案内とHUDを隠し、ヒーローの操作を無効にする |
| `LevelHost.level_loaded(level, spawn)` | 以前見つけた場所を発見済みにし、カメラを後ろに向けてヒーローを`spawn`に置き、画面の背後でHUDを表示する |
| `LevelHost.level_change_finished` | 操作を戻す |
| `LevelHost.level_change_failed` | HUDと操作を戻し、ヒーローがまだポータル上にいれば案内を再表示する |

開始時には、ゲームは開始レベルの`default`スポーン地点へヒーローを配置し、カメラには自身の開始角度（`OrbitCameraRig.start_yaw`）を使います。ポータルで到着したときは、カメラをスポーン地点の向きへ回します。発見済みの場所は、そのレベルのファイルと内部の場所のパスでセッション中記憶されます。レベルを再読み込みしたときは`PointOfInterest.mark_discovered()`で発見済みにし、再通知しません。セーブゲームを作るなら同じ一覧を保存できます。

ヒーローのインスタンスは切り替え後も残り、スタミナ、外見、浮遊状態を維持します。テレポートで移動状態が消去され、カメラ追従がリセットされます。プレイヤーの設定は`Settings`の自動読み込みに残ります。

## レベル切り替えの流れ

プレイヤーがパッド上でEを押すか、案内をクリックすると、次のように進みます。

1. ポータルが移動を要求します。レベルホストはファイルを確認してローダーに要求し、すぐに応答します。切り替えそのものは要求の直後に始まり、要求の実行中には始まりません。ポータルは物理コールバックから要求するため、その最中にレベルをツリーから外せないからです。最初に`level_change_started`が発信されます。
2. まだ一時停止していなければゲームを一時停止します。停止中、カメラはカーソルを解放し、入力側がカーソルを表示します。
3. ローディング画面は次に描画されるフレームを取り込みます（HUDはすでに非表示）。それをぼかして暗くし、0.35秒かけて表示します。背景はゆっくり6%拡大し、場所の名前とヒントが現れ、進捗バーが動き始めます。
4. レベルシーンをバックグラウンドで読み込みます（`ResourceLoader.load_threaded_request`）。ファイルの読み込みでバーが85%まで、組み立てたレベルで90%まで進みます。
5. 古いレベルをツリーから外して解放し、新しいレベルを入れます。`level_loaded`でヒーローの配置場所を通知します。新しいポータルを接続し、古いポータルはツリーから外す前に切断します。途中で別の処理が一時停止を解除していても（ウィンドウを閉じた場合など）、ホストが入れ替え前に再度一時停止します。
6. 一時停止のまま、新しいレベルをナビゲーションマップが取り込むまで待ちます（95%）。レベル内の全ナビゲーションリージョンがマップに入れば終了し、長くても時計で`navigation_timeout`までです。ナビゲーションサーバーはゲームの一時停止中も動くため、再開した最初のフレームから新しいレベルで経路を探せます。
7. 一時停止を解除し、画面の背後で`warmup_frames`フレームを描画します。新しいレベルのシェーダーがコンパイルされ、ヒーローは地面へ落ち着きます。
8. 開始から`min_loading_time`が過ぎるとバーが最後まで進み、画面が消えます。その後に`level_change_finished`が発信されます。

レベルホストの設定：

| プロパティ | デフォルト | 意味 |
|---|---|---|
| `loading_screen` | 空。デモでは`LoadingScreen`を設定 | レベル読み込み中にゲームを覆う画面。空ならプレイヤーの目の前でレベルが切り替わる |
| `min_loading_time` | 0.6 s | 画面の最短表示時間。素早い読み込みでも点滅しないようにする |
| `warmup_frames` | 3 | 画面が消える前に背後で描画するフレーム数。新しいレベルのシェーダーを見えないところでコンパイルする |
| `navigation_timeout` | 2 s | ナビゲーションマップを待つ最長時間。時計で測り、新しいレベルの全リージョンがマップへ入ればすぐ終わる。0なら待たず、取り込み前の経路探索は古いレベルか空のマップで行われ得る |

レベルホストのシグナルとメソッド：

| シグナルまたはメソッド | 意味 |
|---|---|
| `level_change_started(path)` | 切り替え開始。古いレベルはまだある |
| `level_loaded(level, spawn)` | 新しいレベルが入り、古いレベルはなくなった。キャラクターを`spawn`へ配置する。画面はまだゲームを覆う |
| `level_change_finished(level)` | 切り替え終了。画面が消えた |
| `level_change_failed(path, error)` | 切り替えに失敗し、現在のレベルが残る。読み込み失敗は`ERR_CANT_OPEN`、シーンのルートが`Node3D`でなければ`ERR_INVALID_DATA`。`level_change_finished`の代わりに届く |
| `portal_entered(portal)`、`portal_exited(portal)` | 移動者が現在のレベルのポータルに入る、または出る |
| `change_level(path, spawn_name = &"default", title = "")` | 切り替えを開始してすぐ戻る。詳細は以下 |
| `get_current_level()` | ゲームの現在のレベル。最初のレベルより前は`null` |
| `is_changing()` | 受け付けた`change_level()`から`level_change_finished`または`level_change_failed`までの切り替え中かどうか |
| `find_spawn_point(spawn_name = &"default", level = null)` | レベル内のスポーン地点。[スポーン地点](#スポーン地点)を参照 |

エディターで配置した開始レベルは通知されず、`level_loaded`も来ません。`gdscript/main.gd`と同様に、ゲームの`_ready()`で`get_current_level()`と`find_spawn_point()`を使って準備します。

切り替え中の要求は`ERR_BUSY`で拒否されるため、Eを再び押しても、その間にポータルへ入っても何も起きません。`change_level()`はファイルを直ちに確認します。存在しなければ`ERR_FILE_NOT_FOUND`、シーンファイルでなければ`ERR_INVALID_PARAMETER`を返し、何も変更しません。読み込みに失敗したシーンや、ルートが`Node3D`でないシーンでは、現在のレベルが残ります。出力にエラーが表示され、一時停止が解除され、`min_loading_time`を待たずに画面が消え、`level_change_failed`が届きます。失敗した読み込みは回収されるため、修正後などに再要求するとファイルを新たに読み込みます。

ホストが解除するのは、自身が開始した一時停止だけです。ゲームを一時停止するウィンドウ（メニューなど）は`level_change_finished`の後で開きます。切り替え中に開くと、ウィンドウはすでに停止中のゲームを見て一時停止をホストに任せますが、ホストが解除するとウィンドウの背後でゲームが進みます。デモでは、ローディング画面が閉じるまでF10を含む入力を通さないため、このルールが自然に守られます。切り替え中にウィンドウを閉じても問題ありません。ホストが入れ替え時に再度一時停止します。切り替えの途中でホストがツリーから外れた場合（ゲームシーン自体を変更した場合）、切り替えとホストの一時停止も終わります。

画面、進捗バー、`min_loading_time`は、`Engine.time_scale`の値によらず実時間で進みます。スローモーション中でも通常時と同じ長さです。

ウォームアップは初回使用時の処理の一部を画面の背後に隠しますが、その後のシェーダーやアセットの停止を防ぐ保証はありません。実際のレベル内容と対象レンダラーで切り替えを測ってください。

## ポータル

`LevelPortal`は`Area3D`で、パッド、ドア、マップの端などに使えます。コリジョンシェイプと、移動者のレイヤー（キャラクターは2）を検出する`collision_mask`が必要です。ポータル自身の物理レイヤーは不要です。レベルホストは現在のレベル内のポータルを接続します。クエスト後に開くポータルのように、後から追加されたものも対象です。

| プロパティ | デフォルト | 意味 |
|---|---|---|
| `target_level` | | 移動先レベルのシーンファイル。読み込み済みシーンではなくパスなので、2つのレベルを相互に接続できる。インスペクターで選んだ`uid://`パスも使える |
| `target_spawn` | `default` | 到着先のスポーン地点 |
| `title` | | 移動先の場所の名前。案内、ローディング画面、看板で使い、表示時に翻訳される |
| `title_label` | | ポータル上の`Label3D`。ポータルが`title`を書き込む |
| `traveller_group` | `player` | 移動できるボディが属するグループ |
| `auto_travel` | オフ | 案内を出さず、移動者が入った時点で移動する |

組み合わせ：

- **デフォルト、デモのパッド：**ポータルが移動者の出入りを通知し（`traveller_entered`、`traveller_exited`）、レベルホストは`portal_entered`、`portal_exited`として伝え、ゲームが何を案内するか決めます。メインシーンは「E ○○へテレポート」を表示し、離れると隠します。ヒーローがダッシュしながらパッドに乗ることが多いため、Shiftなどの修飾キーを押していてもEが効きます。`travel()`で切り替えを始めます。
- **`auto_travel`をオン：**ドアやマップの端に向いています。移動者が入るとすぐ切り替え、案内は表示しません。
- **ローディング画面なし：**`LevelHost.loading_screen`を空にします。バックグラウンド読み込みと、入れ替え・ナビゲーション中の一時停止は続きますが、プレイヤーには入れ替えが見えます。
- **コードから使うポータル：**`LevelHost.change_level(path, spawn_name, title)`はポータルと同じ切り替えを行います。カットシーンやメニューから呼べます。

`travel()`、および入場時の`auto_travel`は`travel_requested(portal)`を発信します。レベルホストがあれば接続し、ないゲームでは自分で接続します。`has_traveller()`は現在ポータル内に移動者がいるかを返します。すべてのポータルは`level_portals`グループに入ります。

ポータルのエリア内にキャラクターが到着すると、すぐ戻る案内が出ます。`auto_travel`のポータル内では、ウォームアップ中に物理処理が再開したとき検出されます。その時点で切り替えが続いていれば要求は`ERR_BUSY`となり、ホストが無視します。キャラクターは外へ出て入り直すまで移動しません。切り替えがすでに終わっていれば、すぐ元へ戻ります。そのためスポーン地点はパッドの隣、ポータルのエリア外に置きます。

## スポーン地点

`SpawnPoint`は`spawn_name`を持つ`Marker3D`で、デフォルト名は`default`です。キャラクターはマーカーの位置に現れ、ノードの前方である−Zを向きます（ギズモの青い軸は逆向きです）。`get_facing()`はその水平方向を返します。マーカーは地面に置きます。キャラクターの足がそこへ来るため、高く置けば落下します。すべてのスポーン地点は`spawn_points`グループに入ります。

`LevelHost.find_spawn_point(name, level)`は、指定した`level`（省略時は現在のレベル。ツリー内になければならない）からその名前の地点を返します。見つからなければ`default`、それもなければ`null`です。切り替え中に地点が見つからないと出力に警告が出ます。地点が1つもなければホストはレベル自体を`spawn`として渡し、キャラクターはレベルの原点に到着します。すべてのレベルに`default`地点を用意してください。ゲームはそこから始まり、`target_spawn`を指定しないポータルもそこへ到着します。名前はノード名ではなく`spawn_name`です。`default`もノード名ではなくこの値を指します。デモの`default`地点のノード名は`Start`と`Arrival`です。ほかの地点には固有名を付けます。2つ目を`default`のままにすると、同じ名前で要求された場合、ツリー順で最初のものが選ばれます。

## ローディング画面

`LoadingScreen`はウィンドウより上のレイヤー20にある`CanvasLayer`で、ゲームの一時停止中にも動きます。表示中、入力イベントはゲームへ届きません。クリックもF10も効きません（`Input`は押されているキーを引き続き返します）。

| プロパティ | デフォルト | 意味 |
|---|---|---|
| `tips` | 空。デモでは`gdscript/main.tscn`内のインスタンスに6つの操作ヒントを設定 | ランダムな順で1つずつ表示する。各ヒントは翻訳後に`tip_format`へ渡される |
| `tip_format` | 空（コードで設定する`Callable`）。デモでは`gdscript/main.gd`で`InputNames.format`を設定 | 翻訳済みヒントを表示文に変える。デモのヒントは`{sprint}`などのトークンでキーを表し、`InputNames.format`が現在の割り当てを埋め込む。[文章内のキー名](ui.md#文章内のキー名)を参照。空なら翻訳したまま表示 |
| `tip_time` | 6 s | 各ヒントの表示時間。その後0.25秒で消え、文が変わり、次のヒントが0.25秒で現れる |
| `fade_time` | 0.35 s | 画面が現れる時間と消える時間 |
| `zoom` | 0.06 | 背景が元の大きさに対してどれだけ拡大するか |
| `zoom_time` | 12 s | その拡大にかける時間 |

背景には最後のゲームフレームを使います。8分の1に縮小した画像を、シェーダー`loading_background.gdshader`でさらに少しぼかし、暗くし、四隅と文字の下側を強く暗くします。ウィンドウが描画されない状況（ウィンドウなしの実行や最小化中）ではフレームがなく、画面は単色の暗い背景になります。進捗バーは報告値より大きく遅れているとき素早く追いつき、ローダーから以前より小さい値が報告されても後戻りしません。

見た目は画面ルートのテーマ`loading_screen_theme.tres`にあります。タイプバリエーションは`LoadingTitle`（44 px、影付きの暖かい白）、`LoadingBar`（細い金色のバー）、`LoadingTip`（18 px）です。別の見た目にするにはルートへ別のテーマを設定するか、`loading_screen.tscn`をコピーして独自の画面を作ります。ノードの位置や種類を変えても、スクリプトには`Control`の`Root`、およびユニーク名で参照できる`TextureRect`の`Background`、`Label`の`Title`と`Tip`、`ProgressBar`の`Bar`が必要です。`LoadingScreen`を継承したスクリプトでは`open()`、`set_progress()`、`close()`を上書きできますが、シーンにはこれらのノードが必要です。問い合わせには`is_open()`（表示中、表示・非表示への遷移中を含む）、`get_shown_progress()`（バーの充填率0から1）、`get_tip()`（表示中ヒントの元テンプレート。ヒントがなければ空）があります。`refresh()`はタイマーを再開せず、そのヒントを再翻訳・再整形します。デモはローディング画面を`ActionTexts.GROUP`に追加するため、キー名の更新時には表示中のヒントも更新されます。

## 操作するヒーロー

`gdscript/player/playable_hero.tscn`は、ゲームシーンへすぐ配置できるプレイヤー用のヒーローです。キャラクター（`player.tscn`、`player`グループ）、`PointClickMoveInput`、`CharacterActionInput`、アームとカメラを持つカメラリグ、クリックマーカー、経路線が設定とともにあり、シーン内で6つの接続が行われています。キャラクターシーン自体にはこれらが含まれないので、同じ`player.tscn`をAIで操作することもできます。

`PlayableHero`（`playable_hero.gd`）は各部分を型付きプロパティ（`character`、`input`、`actions`、`camera_rig`、`camera_arm`、`camera`、`click_marker`、`path_view`、キャラクターの`sounds`、`appearance`、`hover`、`silhouette`）で公開し、次の3つの操作を提供します。

| 呼び出し | 効果 |
|---|---|
| `teleport(position, facing = Vector3.ZERO, turn_camera = true)` | 押下中の入力を忘れ（`PointClickMoveInput.cancel()`）、キャラクターを即座に配置し（`GroundCharacter.teleport()`）、指定されたらカメラを`facing`に沿って向け、位置を瞬時に合わせて追従を初期化する。`facing`を`Vector3.ZERO`のままにすると、キャラクターとカメラはそれぞれの向きを維持する |
| `place_at(marker, turn_camera = true)` | マーカーの−Z方向へ向けて`teleport()`する |
| `controls_enabled` | オフにすると押下中の入力とダッシュキーを解除し、入力ノードを止める。カメラの操作は残る。クリック済みの地点への走行は続くため、止めるには`character.mover.stop()`または`teleport()`を使う。オンにすると操作が戻り、入力ノードは以前のように処理する |

ヒーローのルートは動きません。内部のキャラクターが動き、カメラがそれを追います。ヒーローはレベルコンポーネントなしでも使えます。独自のレベルシステムがあるゲームでは、レベルが準備できたところで`place_at()`を呼びます。

## デモのレベル

**草原**（`shared/world/world.tscn`。[ワールドとナビゲーション](world-and-navigation.md)を参照）の`Travel`の下には、原点で北を向く`Start`スポーン地点（`default`）、古代の環のそばで開始地点から北へ12 mの位置にあり、そこから見える島行きの`IslandPad`、そしてパッドの隣で東を向き、パッドがヒーローの左やや後ろに来る`FromIsland`スポーン地点（`from_island`）があります。

**孤島**（`shared/world/island/island.tscn`）は湖にある直径30 mの丸い島です。草原の小道具、マテリアル、シェーダーを再利用し、独自のファイルは2つのマテリアルだけです。

- 草地の`island_ground.tres`は、草原の地面から未舗装道路（`roads`）をオフにしたものです。道路はワールド座標で描画され、草原用だからです。
- 湖の`lake_water.tres`は井戸の静かな水を明るい青にし、波紋を強めたもので、地平線まで広がる600 mの平面です。
- 草地の縁の下には岩の岸があり、浅瀬には大きな岩があります。
- 半径14.5 mの環状の見えない壁（`Edge`、24個の箱）がヒーローを島に留めます。物理レイヤー`bounds`（4）にあり、キャラクターは衝突しますが、クリックとカメラには見えません。水をクリックしても壁には当たらず、カメラは壁を通過します。島のナビゲーションメッシュはレイヤー1と4からベイクされるため、経路は壁を避けます。
- 北の隠者のキャンプにはテント、焚き火、樽があり、発見できる場所です（`PointOfInterest`は`Places`の下）。
- 南にはキャンプへ向けて北を向く`Arrival`スポーン地点（`default`）と、ヒーローの左後ろに草原の`from_island`地点へ戻る`HomePad`があります。
- 草原と同じ方法でベイクした独自のナビゲーションメッシュがあります（[ナビゲーションメッシュの再ベイク](world-and-navigation.md#ナビゲーションメッシュを再ベイクする)を参照）。

両レベルは環境リソース`shared/world/world_environment.tres`（空、霧、環境光）を共有します。太陽（`Sun`）はそれぞれに別のインスタンスがあります。

パッド（`shared/world/props/teleport_pad.tscn`）は共通のシーンです。`LevelPortal`に石の円盤、光る模様、頭上で回転する結晶、ライト、場所の名前を示す看板が付いています。衝突はないため、その下のナビゲーションメッシュを変える必要はありませんでした。

## レベルを追加する

1. `Node3D`をルートにするシーンを作ります。レベルのライトと環境、地面と小道具を持つ`NavigationRegion3D`、地面上で`spawn_name`を`default`にした`SpawnPoint`を用意します。端の見えない壁はレイヤー4（`bounds`）に置きます。
2. このレベル用のユニークな`NavigationMesh`を作り、静的コライダー、物理レイヤー1、見えない端の壁があるならレイヤー4も使ってベイクします。マップのセル高0.025 m、セルサイズ0.25 mに合わせ、半径0.5 m、最大登坂高0.3 m、最大斜面40°から始めます。付属の高さ1.8 mのカプセルにはAgent Height 1.8 mを使い、`filter_walkable_low_height_spans`をオンにして低い天井を除きます。デモのメッシュリソースをコピーするなら、再ベイク前にユニークにし、高さとフィルターの設定を確認してください。[ワールドとナビゲーション](world-and-navigation.md#物理レイヤーとナビゲーション)を参照してください。
3. 別のレベルから入るポータルを追加します。`teleport_pad.tscn`のインスタンスまたは独自の`LevelPortal`で、`target_level`に新しいシーンを設定し、戻り用のポータルも作ります。各パッドの隣にスポーン地点を置き、向こう側のパッドの`target_spawn`にその名前を設定します。
4. ポータルと場所の名前を翻訳に追加します。`localization_checks.gd`は開始レベルからポータルで到達できる全レベルを調べ、文字列が欠けていると報告します。コードの`change_level()`だけで到達するレベルは検査されません。
