# エディターでのシーン編集

[← ドキュメント目次](index.md)

> これは[英語の原文](../en/editor_authoring.md)の翻訳です。内容が異なる場合は、英語版が正しいものとします。

デモのシーンは、エディターで編集することを前提にしています。ノードどうしはインスペクターで結び付けます。コンポーネントは自身の設定をチェックし、何かが欠けているか誤っている間はSceneドックに警告を表示します。また、ゲームが開始時に整えるもの（カメラの視点、キャラクターのモデルと頭上の名前、ポータルの看板の行き先名、小道具の大きさ）もエディターに表示されます。これらのプレビューは保存されません。保存したシーンには自分が設定した内容だけが入るので、差分には自分の変更だけが現れます。

## 参照と警告

ほかのノードと連携するコンポーネントは、それらへの参照をプロパティとして持ちます。`PlayableHero.character`、`GroundCharacter.mover`、`OccludedSilhouette.target`などです。インスペクターでノードをフィールドへドラッグして設定します。コンポーネントに必要な参照が空の間や、ノードが機能できない場所にある間（動かすボディの下にない`NavigationMover`、行き先シーンのない`LevelPortal`、Input Mapにない入力アクション）は、Sceneドックでそのノードの横に警告マークが表示されます。マウスを重ねると理由がわかります。警告は編集に追従します。プロパティを変更したり、子を追加・削除したり、ルートのカーブ、崖ガードの`max_drop`、キャラクターの落下設定を編集したりすると、警告が現れたり消えたりします。シーンを開き直す必要はありません。

コンポーネントがエディター内で自身をチェックできるのは、そのスクリプトがツールスクリプトだからです。エディターではチェックとプレビューだけを行います。入力、物理処理、タイマーはそこでは動かず、計算した結果がシーンに書き込まれることもありません。ゲーム内では従来どおりに動作します。

## 開始レベル

`gdscript/main.tscn`はレベルホスト`Levels`を持ち、その子が開始レベル`World`で、`Levels.initial_level`がそれを指定します。指定がなければ、ホストは最初の`Node3D`の子で開始します。3Dの子が複数あり、どれも指定されていなければ警告を表示します。[レベル](systems/levels.md)を参照してください。

## エディターでのカメラ

`Hero/CameraRig`はゲーム開始時の視点を表示します。リグはターゲットから`focus_height`だけ上に立ち、`start_yaw`の分だけ回り、`start_zoom`が決める傾きと距離をとります。アームはその距離にカメラを表示します。これらのプロパティを変更して開始時の構図を決めてください。3Dビューはすぐに追従します。

ゲームはリグのトランスフォーム、カメラのトランスフォーム、そしてリグの下にあるアームの`length`を毎フレーム設定するため、エディターではこれらもプレビューです。手で動かしたリグやカメラは、ゲームが置く位置へ戻ります。リグの下では、アームの`length`は読み取り専用です。保存時にはシーンを読み込んだときの値が保たれるので、プレビューが差分に現れることはなく、ヒーローを配置するシーンにカメラの位置のコピーが入ることもありません。ターゲットのないリグは別です。ゲームはそれを動かさないため、位置は自分で決めたとおりになり、そのまま保存されます。プレビューされるのは向きだけです。

## 設定ウィンドウからの設定

`SettingsApplier`は、シーンで設定された値の上に、プレイヤーの保存済み設定（F10）を適用します。シーンの値はデフォルト値でもあります。プレイヤーが変更していない設定はシーンの値のままで、**すべてリセット**でもその値に戻ります。インスペクターで調整する間、シーンのノードを設定どおりに動かすには`SettingsApplier.use_saved_settings`をオフにします。すると設定ウィンドウはそれらに手を付けず、エンジンの設定（フルスクリーン、フレームレート、V-Sync、物理補間、UIスケール、言語、音量）だけを変更します。[設定](settings.md)を参照してください。

## 固体の小道具

固体の小道具は、`StaticProp`のルートノード（`shared/world/props/static_prop.gd`を付けた`StaticBody3D`）を持つシーンです。見える部品と衝突形状はルートノードの子で、グループ化されているため、3Dビューでクリックすると小道具全体が選択されます。

- **移動**はルートノードで行います。
- **サイズ変更**は`dimensions`で行います。小道具自身の軸に沿ったメートル単位で、見える部品と衝突形状が一緒に変わります。ある軸で0なら、その軸では部品の大きさを保ちます。そのため、`(0, 0, 0)`の新しい小道具は作ったときの大きさのままで、柱を高くするには高さだけを指定すれば済みます。ルートノードはスケールしないでください。スケールすると警告が出ます。子もスケールしないでください。メッシュを大きくしたり小さくしたりしたら、その衝突形状も合わせて変更する必要があります。
- **色の変更**は`surface_material`で行います。見えるすべての部品のマテリアルを置き換えます。空なら各部品自身のマテリアルを保ちます。

レベル間で共有する小道具は、`shared/world/props/`にあるシーンです。`stone_pillar.tscn`、`solid_box.tscn`（壁、木箱、プラットフォームとそのスロープ）、`grove_tree.tscn`、`rock.tscn`、そして森、野営地、農家の固体の小道具です（茂みは衝突を持たず、`StaticProp`ではありません）。インスタンスはそれぞれ独自の`dimensions`と`surface_material`を設定します。すべてのインスタンスを変えるには、小道具のシーンを編集します。一度しか使わない部品は、独自の`StaticProp`ルートノードを持ち、そのレベルの中に直接置かれています。草原の地面、台地の階段、迷路の生け垣、各場所の人物、10種類のヒーローの外見、島の地面と縁の壁です。生け垣はメッシュの大きさを保ちます。葉には約25 cmのセルに分割されたメッシュが必要なので、別の大きさの生け垣には`dimensions`ではなく、その大きさのメッシュを使います。

部品はいつもどおり編集できます。子を動かす、メッシュや形状を変える、部品を追加する、といった操作です。小道具はその変更を新しい形として受け取ります。`dimensions`が0の軸では部品の新しい大きさを取り、それ以外の軸では引き伸ばしを保ちます。新しい小道具は自動ではグループ化されません。ルートノードを選択し、3DビューのツールバーにあるGroupボタンを押してください。保存時には部品は作ったとおりに保たれます。サイズ変更はプレビューで、シーンを開いたときとゲームの開始時に改めて適用されます。サイズを変えた形状はそれぞれ独自のコピーなので、あるインスタンスのサイズを変えても別のインスタンスは変わりません。丸い形状や回転した形状を不均等に引き伸ばすと、同じように引き伸ばした凸形状になります。

動く部品は通常の`Node3D`の下に置いてください。自身をアニメーションさせるノードを、小道具がサイズを変えるノードにしてはいけません。山では、小道具が`CrystalAnchor`のサイズと位置を決め、その子の`Crystal`が回転しながら上下に揺れます。

小道具の衝突を変えたら（移動、サイズ変更、編集）、ナビゲーションメッシュを再ベイクします。[ワールドとナビゲーション](systems/world-and-navigation.md#ナビゲーションメッシュを再ベイクする)を参照してください。

## 巡回

草原の騎士はルートを歩きます。`shared/world/world.tscn`を開き、`Path3D`である`Routes/KnightPatrol`を選択して、3Dビューでカーブツールを使ってそのカーブを編集すると、騎士はそこに描かれた線の上を、曲がり目ではなめらかに曲がりながら歩きます。角を丸めるには、ツールバーで**Select Control Points**をオンにし、Shiftを押しながらポイントからドラッグしてハンドルを引き出します。線は生け垣から騎士の幅ほど離してください。線に沿って歩く間、騎士は生け垣を迂回する道を探しません。騎士（`NavigationRegion3D/Characters/Knight`、`gdscript/npc/knight_patrol.tscn`のインスタンス）は**Route**でそれを参照します。騎士は家のそばの持ち場からルートの最初のポイントまで歩き、最後のポイントのあとは最短の道で戻ります。この二つの道は描かれた線に含まれません。ルートはレベルに属するので、同じキャラクターが別のレベルでは別のルートを歩けます。島のレンジャー（`island_patrol.tscn`）は島の`Routes/IslandPatrol`を歩きます。ポイントのないルートや、キャラクターの中にあるルートでは、キャラクターのルートノード`Knight`に警告が表示されます。

エディターでは、巡回するキャラクターがモデルと頭上の名前を表示します。どちらもシーンには保存されません。ルートノードでは**Model Scene**、**Speaker Name**（頭上と字幕に表示）、**Blocked Line**（誰かが十分長く行く手に立っていたときのセリフ）を設定します。歩き方は`Character/PatrolController`で設定します（**Editable Children**をオンにします）。**Cycle Wait**は1周の後に持ち場で待つ時間（10 s）、**Waypoint Wait**はカーブの各ポイントで止まる時間、**Blocked Delay**はセリフまでに誰かが行く手に立ち続ける必要がある時間（騎士では2.5 s）、**Blocking Distance**と**Blocking Angle**は誰かがいると騎士が止まる前方の範囲です。懐中電灯の光のように、1 m先まで、左右へ25°ずつ広がります。横や後ろでは誰も騎士を止めません。[ロコモーション](systems/locomotion.md#patrolcontrollerルートを歩く)を参照してください。

## エディター側の部分のチェック

`tests/run_checks.gd`はゲームをチェックしますが、エディターは動かせません。エディター側の部分、つまり編集に追従する警告、プレビュー、シーンが保存される内容には専用のチェックがあります。`tests/editor_tool_checks.tscn`を開き、インスペクターで**Run Checks**を押してください。結果はそこの**Status**と**Results**に表示され、`.godot/editor_tool_checks/results.json`にも書かれます。出力にはステータス行が出ます。チェックがシーンを保存するのはそのフォルダだけで、フォルダは実行のたびに空になります。プロジェクトのシーンやプレイヤーの設定が書き込まれることはありません。[テスト](testing.md#エディターでのチェック)を参照してください。
