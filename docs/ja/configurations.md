# 操作するヒーローの設定

[← ドキュメント目次](index.md)

> これは[英語の原文](../en/configurations.md)の翻訳です。内容が異なる場合は、英語版を参照してください。

[移植ガイド](integration.md)の手順を終えたら、`gdscript/player/playable_hero.tscn`を出発点にします。以下の3つの構成では、付属のキャラクターの大きさ、移動リソース、カメラの衝突設定を維持します。速度やスムージングに根拠のない値を足さず、ヒーローの操作方法と見え方だけを変えます。

| 構成 | 向いている用途 | 主な違い |
|---|---|---|
| [標準：手動オービット](#標準手動オービット) | クリック移動と直接操作の両方を使い、エリアを安定した視点で見渡す | カメラの向きはプレイヤーが決める |
| [経路に沿うマウス移動](#経路に沿うマウス移動) | マウスボタンを押し続けて、ベイク済みの障害物を迂回する | スロープや高さが重なる場所の近くでは経路が切り替わり得る |
| [移動方向に追従するカメラ](#移動方向に追従するカメラ) | 長い距離を移動し、カメラを走行方向の後ろへ戻したい | 経路が変わると視点も回転する |

## 設定値を変更する場所

値の供給元は3つあります。どれを編集しているか確認してください。

| 供給元 | 適用される場面 | 例 |
|---|---|---|
| スクリプトのデフォルト値 | シーン側で上書きしていない新しいコンポーネント | `PointClickMoveInput.keys_with_camera`の初期値は`SIDESTEP` |
| 保存済みのシーンやリソース | 付属シーンのインスタンス | `playable_hero.tscn`では`TURN`を選択し、カメラの追従時間は1.1秒 |
| デモの設定 | 起動時やメニュー設定の変更時に`SettingsApplier`が実行されるとき | シーンではカメラ追従がオフでも、`user://settings.cfg`でオンにできる |

デモで構成を比較するときは、最初に**設定 → すべてリセット**を実行します。メニューでの変更は保存されますが、実行中のシーンを**Remote**インスペクターで変更した結果は一時的です。単独で使うヒーローでは、コピーしたシーンを編集するか、`playable_hero.tscn`から継承シーンを作り、構成ごとに別々に保存してください。入れ子のノードを編集する必要がある場合は、シーンインスタンスの**Editable Children**をオンにします。これらの値を`SettingsApplier`に管理させるつもりがないなら、コピーする必要はありません。

以下のパスはヒーローのインスタンスからの相対パスです。

| 調整するもの | ノードまたはリソース |
|---|---|
| クリック、長押し、キー、カーソル | `PlayerInput`（`PointClickMoveInput`） |
| ダッシュキーのモードとジャンプ入力 | `PlayerActionInput`（`CharacterActionInput`） |
| 速度、加速、減速、旋回速度 | `Character/NavigationMover` → `settings`、通常は`player_locomotion.tres` |
| ジャンプ、重力、階段、スタミナ消費 | `Character`（`GroundCharacter`） |
| 崖からの落下防止／スタミナ回復 | `Character/LedgeGuard`／`Character/Stamina` |
| オービット、追従、上下角、ズーム | `CameraRig`（`OrbitCameraRig`） |
| カメラと障害物の衝突、モデルのフェード | `CameraRig/CameraArm`（`CameraArm`） |
| モデルの浮遊 | `Character/Visual/Hover`（`CharacterHover`） |

リグの角度フィールドと移動リソースの旋回速度は、**インスペクターでは度**で表示されますが、GDScriptから代入するときは**ラジアン**です（`deg_to_rad(30.0)`）。`Camera3D.fov`は例外で、コードでも度を使います。カメラを下向きに傾ける角度は負の値です。デモの**見下ろし角**スライダーは正の度数、**高さ**はパーセントを使います。メニューの55%は`follow_zoom_level = 0.55`であり、メートル単位の高さではありません。

## 標準：手動オービット

これは付属のヒーローシーン、およびReset all後のデモの構成です。クリックすると障害物を迂回する経路を進み、左ボタンを押し続けると直接向きを指定できます。右ボタンを押しながらWASDを使うと、カメラを基準に移動します。カメラはボディの位置を追いますが、走行方向の後ろへ自動では回転しません。

| 部分 | 維持する値 |
|---|---|
| 移動リソース | `max_speed = 5.5`、`sprint_speed_multiplier = 1.5`、`acceleration_time = 0.18`、`stop_time = 0.22`、`turn_speed = 720°/s` |
| キャラクター | `jump_height = 1.0`、`gravity_scale = 3.0`、`max_step_height = 0.3`、`sprint_tires = true`、`sprint_duration = 5.0` |
| 入力 | `hold_mode = STEER`、`hold_delay = 0.2`、両方のキーモードが`TURN`、`look_around_while_held = true`、`keep_aim_on_camera_turn = true` |
| カメラ | `follow_movement = false`、`follow_pitch = false`、`follow_zoom = false`、`mouse_pitch = false`。ターゲットの高さの平滑化は`height_follow_time = 0.15 s`で有効のまま |
| 最初の視点 | `start_yaw = 45°`、`start_zoom = 0.55`、カメラFOV 45° |
| カメラアーム | `keep_out_of_geometry = true`、`pull_in_on_occlusion = false`、衝突レイヤー1と3 |

崖ガードは有効のままにし、付属の`Visual`をカメラアームのフェード対象にします。壁の向こうではシルエットがヒーローを見えるようにし、アームはカメラが地形に入り込むのを防ぎます。役割は別々です。

**確認：**壁の向こう側に迂回できる地点をクリックし、次にマウスを壁の方向へ押し続け、移動しながらカメラを回してみます。クリック時は経路をたどり、長押し時は衝突に沿って滑るか停止するはずです。見回しても進行方向が保たれることを確認します。移動値を変える前に、0.2 mの段差とジャンプを別々に試してください。

## 経路に沿うマウス移動

標準構成から始め、`PlayerInput`の次のプロパティを変更します。

| プロパティ | 値 | 効果 |
|---|---|---|
| `hold_mode` | `FOLLOW_POINT` | マウスボタンを押し続けると、まっすぐ操舵せずナビゲーションの目的地を更新する |
| `stop_on_release` | `true` | 長押しを解除した位置で減速して止まる |
| `keys_with_camera` | `OFF` | 右ボタン＋WASDを無効にする |
| `keys_with_camera_steer` | `OFF` | マウスの両ボタンを押したときのA/Dによる操舵を無効にする |

カメラ追従の3つのスイッチはすべてオフのままにし、向きを手動で決められるようにします。標準の移動リソースはすでに素早く加減速するため、この入力方式のために速度を変える必要はありません。

短いクリックでは目的地まで移動します。`stop_on_release`が影響するのは**長押しだけ**で、デモのメニューにはありません。シーンまたはコードで設定してください。両方のキーモードをOffにしても、両ボタンでの移動は**無効になりません**。右ボタンの後で左ボタンを押すと、ナビゲーション経路を使わず、カメラの向きへまっすぐ走ります。

この構成は、信頼できるベイク済みメッシュがあり、カーソルの下の地面がほぼ一意に決まるレベルに向いています。スロープや足場の近くでは、レイが別の高さを選び、経路を再構築することがあります。そのような地形で正確な直接操作が必要なら、標準の`STEER`モードを使います。空の経路は、このコントローラーでは安全な「移動しない」という結果ではありません。ヒーローが障害物へまっすぐ向かう場合は、ナビゲーションメッシュを調べてください。

**確認：**壁の向こう側を押し続け、カーソルを別の到達可能地点へ動かし、途中でボタンを離します。ヒーローが壁を迂回し、新しい地点へ向かい、解除時に減速するはずです。続けて短くクリックし、目的地まで移動することも確認します。

## 移動方向に追従するカメラ

標準の入力モード`STEER`と`TURN`から始めます。`CameraRig`の次のプロパティをオンにします。

| プロパティ | 値 | 理由 |
|---|---|---|
| `follow_movement` | `true` | クリック移動やカーソル操作による走行の後ろへ回転する |
| `follow_time` | 1.1 s | 付属シーンで調整済みの旋回時間。新しい方向へ滑らかに近づく |
| `follow_toward_camera_angle` | 30° | カメラへほぼ正面から向かって走るときは、視点を反転させない |
| `sharp_turn_speed` | 360°/s | 付属キャラクターの720°/sの旋回速度の半分。方向転換の途中に生じる方向を追わない |
| `follow_wait_after_rotate` | `true` | 手動で選んだ視点を、停止または次の走行まで保つ |
| `follow_pitch` / `follow_pitch_angle` / `follow_pitch_time` | `true` / −22° / 1.1 s | 進行方向を見渡せる浅い角度へ戻す |
| `follow_zoom` / `follow_zoom_level` / `follow_zoom_time` | `true` / 0.55 / 1.5 s | 移動中に付属シーンの初期ズームへ戻す |

角度、ズーム、時間は付属シーンとデモの設定から取っています。向きの追従、上下角の調整、ズームの調整はそれぞれ独立しています。ホイールで選んだズームを保つなら`follow_zoom`をオフにします。ホイールによる通常の上下角操作を維持するなら`follow_pitch`もオフにします。

デモでは、カメラタブの**走る方向へカメラを回す**、**走る間カメラの傾きを揃える**、**走る間カメラの高さを揃える**が対応するスイッチです。目標値のデフォルトはすでに表と一致しています。

右ボタンによるオービットは自動追従より優先されます。WASDには右ボタンが必要なので、右ボタン＋WASDで移動中はカメラが自動で後ろへ回りません。オービット後に右ボタンだけを離しても待機は終わりません。停止するか、新たな目的地をクリックするか、新たに長押し移動を始めてください。シーンの`run_requested → end_follow_wait`接続と`keep_aim_on_camera_turn = true`を維持してください。そうしないと追従の待機が続いたり、カメラの動きによって長押し中のカーソル操作が曲がったりします。

**確認：**画面を横切る方向に走り、90°曲がってからカメラへ向かって逆走します。最初の曲がり角ではカメラが進路の後ろへ移り、逆走では視点が反転しないはずです。走行中に手動でオービットして右ボタンを離すと、停止または次の走行まで選んだ視点が保たれるはずです。壁の近くでも同じ順序で試し、カメラアームを確認します。

単独のヒーローでは、次のコードがこの構成を有効にする方法に相当します。ヒーローの子ノードが準備できた後、ゲームシーンの`_ready()`から実行します。

```gdscript
extends Node3D

@onready var hero: PlayableHero = $Hero


func _ready() -> void:
    hero.place_at($Spawn, false)
    var rig := hero.camera_rig
    rig.follow_movement = true
    rig.follow_time = 1.1
    rig.follow_toward_camera_angle = deg_to_rad(30.0)
    rig.sharp_turn_speed = deg_to_rad(360.0)
    rig.follow_wait_after_rotate = true
    rig.follow_pitch = true
    rig.follow_pitch_angle = deg_to_rad(-22.0)
    rig.follow_pitch_time = 1.1
    rig.follow_zoom = true
    rig.follow_zoom_level = 0.55
    rig.follow_zoom_time = 1.5
```

この例は、ヒーローの移動と入力の設定を変更していないことを前提とします。デモ全体で使う場合は、保存済み設定と画面上の操作項目が一致するように、代わりに設定メニューまたは`Settings.set_value()`を使ってください。

## オプション：浮遊するヒーロー

いずれの構成でも、既存の浮遊機能を使えます。`Character/Visual/Hover.enabled = true`にするか、デモで**キャラクター → 地面の上に浮く**を有効にします。`height = 0.35 m`、`glide_time = 0.3 s`、割り当て済みの`player_floating_fall.tres`（落下時の重力倍率0.5、最大落下速度2 m/s）を維持してください。

浮くのはモデルです。衝突ボディは引き続き階段を上り、落下します。隙間を越えたり飛行したりはできません。ジャンプは同じ高さまで上昇し、その後ゆっくり下降します。浮遊中は足音イベントが止まり、2 m/sでの緩やかな着地はデフォルトの着地イベント閾値2.5 m/sを下回ります。モデルを持ち上げてもボディのコライダーは大きくなりません。低い天井を試してください。モデルと落下の詳細は[キャラクター](systems/characters.md)と[ロコモーション](systems/locomotion.md)を参照してください。

## 構成を崩さずに調整する

- **キャラクターごとに値を変えるなら、リソースを個別にします。** 1体だけを編集する前に、インスペクターでムーバーの設定リソースをユニークにし、別名で保存します。ムーバーがシーンツリーに入る前に別のリソースを割り当ててください。実行中は既存リソースのフィールドを編集します。`_ready()`の後で`mover.settings`を置き換えても、`GroundMotion`がすでに保持しているリソースは変わりません。
- **速度と減速を一緒に調整します。** `acceleration_time`と`stop_time`は通常速度での時間です。ダッシュでも加速と減速は同じなので、1.5倍速での停止時間も1.5倍の約0.33秒になり、0.22秒ではありません。直線上の理想的な停止距離は、5.5 m/sで約0.61 m、8.25 m/sで約1.36 mです。崖の近くでは余裕を取ってください。
- **カメラの急旋回判定を移動に合わせます。** `sharp_turn_speed`は`LocomotionSettings.turn_speed`の半分以下に保ちます。キャラクターの旋回速度を下げるときは、カメラ側の閾値も確認してください。
- **ボディ、ガード、ナビゲーションを合わせます。** カプセルの大きさ、最大段差高、斜面の上限を変えたら、ナビゲーションの半径、高さ、登坂高、斜面も見直して再ベイクします。ガードの落下制限は、意図した階段を通れる値に保ちます。物理レイヤーとナビゲーションレイヤーは別の設定です。
- **動作を1つ変えたら、その確認を繰り返します。** デモの**キャラクターの経路線**と**キャラクターの状態とイベント**のパネルで、問題が経路、衝突、入力、カメラのどれにあるか調べられます。記憶から再現するよりも、基準となるシーンを保存しておきます。

全プロパティの参照：[入力](systems/input.md)、[ロコモーション](systems/locomotion.md)、[カメラ](systems/camera.md)。
