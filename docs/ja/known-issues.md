# 既知の問題

> これは[英語の原文](../en/known-issues.md)の翻訳です。内容が異なる場合は、英語版が正しいものとします。

プロジェクトの制限事項と、プロジェクトが回避しているエンジンの癖です。各項目には、何が起きるかと、どうすればよいかを記しています。

## 制限事項

- **マウスとキーボードのみ**。ゲームパッドには対応していません。
- **アニメーションなし**。モデルは静的なプリミティブで、手に持ったアイテムだけが歩みに合わせて揺れます（`HandSway`）。`AnimationTree`を駆動するために`NavigationMover.get_speed()`と`GroundCharacter.get_step_phase()`が用意されています。
- **キャラクター同士の回避なし**。`NavigationMover`は経路をたどるだけでナビゲーションの回避（avoidance）を使わないので、移動中のキャラクター同士は互いを避けません。プレイヤーのボディはレイヤー2にあり、レイヤー1とだけ衝突するので、`player.tscn`から作った2体のキャラクターは互いにすり抜けます。互いにぶつかるようにするには、それらの`collision_mask`にレイヤー2を加えてください。デモのNPCは静止しており、障害物としてナビゲーションメッシュにベイクされています。
- **ナビゲーションメッシュは事前にベイクされています**。実行時に障害物を動かしても経路は変わりません。レベルを編集した後は、メッシュを再ベイクしてください（[ワールドとナビゲーション](systems/world-and-navigation.md#ナビゲーションメッシュの再ベイク)）。
- **Godot 4.7専用**。プロジェクトは4.7.2でテストされています。シルエットにはステンシルバッファ（4.5以降）が必要で、シーンの警告チェックは4.7.2の条件を再現しています。

## 入力

- **クリックはボタンを離したときに作用します**。押下がクリックか長押しかが決まるのは0.2秒後（`hold_delay`）か離したときなので、クリックは押した瞬間に作用する場合より約0.1秒遅れます。これは意図的なものです。そうしないと、長押しでもまず主人公が押した地点への経路を進んでしまいます。[入力](systems/input.md#クリックと長押し)を参照してください。
- **システムによってはカーソルが狙いを保てません**。カメラ回転中に狙いを保つ機能は、システムカーソルを動かします（`Viewport.warp_mouse()`）。システムがそれを許可しない環境（たとえばWayland）では、走る方向は保たれますが、カーソルは画面上の元の位置にとどまります。
- **「経路に沿って地点へ」ではルートが切り替わることがあります**。この長押しモードではカーソル下の地点が動くたびに経路が再構築されるので、高低差の近く（スロープ、プラットフォーム）では、あるルートから別のルートへ切り替わることがあります。デフォルトのモード（カーソルへ直進）にはこの問題はありません。
- **ゲームをエディター内で実行すると、Shiftが押しっぱなしになることがあります**。ゲームがエディターのゲームタブ（Game）に埋め込まれていて、フォーカスがエディターに移ると、エンジンは押されたキーをリセットしません。ダッシュのアクションが修飾キーに割り当てられている限り、`CharacterActionInput`は次のマウスまたはキーボードのイベントで、押しっぱなしになったダッシュを解除します。Windowsの固定キー機能（Sticky Keys）がオンになると（Shiftを5回続けて押す）、Shiftはシステム自体で押しっぱなしになります。Windowsの設定で固定キー機能をオフにしてください。[入力](systems/input.md#shiftは押しっぱなしにならない)を参照してください。

## カメラ

- **障害物のすぐ後ろにあるボディ**。Joltは、シェイプキャストが開始時点で触れているボディを報告しません。カメラが入り込んでいる障害物のすぐ後ろに別のボディがある場合（後ろに崖がある柵）、アームは代わりにターゲットに近い側で空いている空間を探します。[カメラ](systems/camera.md#アームが障害物の後ろの空間とボディの内部をどう区別するか)を参照してください。
- **物理補間なしでは動きがカクつく**。物理補間はデフォルトでオンです。オフにすると（設定 → 表示）、キャラクターとカメラがティックごとに毎秒60回動くので、高速なモニターではぎこちなく見え、カメラが走りに追従していると旋回時にキャラクターが揺れます。

## テスト

- **まれに出るJoltの警告で実行が失敗します**。CPU負荷が高いとき（たとえば、新規インポート直後の最初の実行）、Jolt Physicsが「Jolt Physics job system exceeded the maximum number of jobs. This should not happen.」と出力することがあります。テストランナーはエンジンの警告とエラーをすべて失敗として数えるので、すべてのチェックが成功していても、実行は終了コード1と「engine and script errors: 1」で終わります。この警告はプロジェクトではなく、エンジンの物理ジョブシステムから出るものです。負荷のかかっていないマシンで、テストをもう一度実行してください。

## レンダリング

- **シルエットはエンジンの実験的機能を使っています**。ステンシルバッファはGodot 4.5以降で実験的機能であり、透明パスでしか読めません。将来のエンジンバージョンでこれが変わった場合は、シルエットを確認してください。
- **Godot 4.7では投影がY方向に反転しています**（D3D12とVulkan）。シェーダー内で`PROJECTION_MATRIX[1][1]`が負になります。シルエットの縁取りはその`abs()`を取っています。そうしないと縁取りのメッシュが縮み、縁取りが消えます。

## プロジェクトファイル

- **丸められた回転は「non-uniform scale」警告を引き起こします**。4桁で`.tscn`に書かれた回転は基底の軸の長さに1e-5を超える差を生み、エンジンはボディとシェイプについて不均一なスケールを報告します。`Transform3D`の数値は完全な精度（有効数字9桁）で書いてください。
- **`shared/`はまだ完全には言語に依存しない状態になっていません**。`world.tscn`と`mountain.tscn`は`addons/iso_orbit/points_of_interest/point_of_interest.gd`を使っており、2つの小さなプロップ用スクリプトが`shared/world/props/`にあります。C#版には、独自の場所用スクリプトか、シーンだけで場所を示す方法が必要になります。
- **終了時にリソースのリークが報告される**。足音の再生直後にスクリプトが終了すると、エンジンが`AudioStreamPlayback`オブジェクトのリークを報告することがあります。`--fixed-fps`ではゲーム時間が実時間より先に進み、その間もサウンドは再生中だからです。終了する前にシーンを解放して少し待ってください。`tests/run_checks.gd`は0.1秒待ちます。
